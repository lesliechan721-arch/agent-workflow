# Spawn Subagent

保留调用方已确定的目标、角色、范围、权限与输出；已有完整调度方法时沿用，不另建一套。

## 选择执行配置

委派前先确定执行配置。调用方已明确选定时直接复用；否则先读取 执行配置（`references/execution-profiles.md`） 参考并选择配置。**不能用省略参数、继承环境默认来跳过配置选择。**

执行配置未写 executor 时使用 native。配置无效或执行器不可用时报告缺口，不自行切换执行器或材料目的地。

**判断配置是否可用应该实际委派结果或明确声明的允许范围为准**，不能仅因工具没完整列出支持的配置就认定配置无效。

native 使用可用的原生子代理工具。模型和推理强度按优先级 `明确要求 > 配置偏好 > 环境默认` 依次采用；当偏好已确认不可用并且允许回退时才降级并说明实际值。未指定角色时默认使用 `subagent`；角色不可用或硬要求不受支持时停止该次委派并报告缺口。

非 native 使用 外部委派（`references/external-delegation.md`）。

## 任务上下文

按调用方的任务模板提供当前目标、职责、对象与依据版本、仍有效的补充要求、必要输入、允许动作、写入归属、预算、输出及停止条件。

**默认使用干净上下文的新子代理。**将新工作交给新的子代理，并提供汇总后的完整任务范围，包括最初的任务说明、之后的所有指令，以及前一个代理的报告和分支。这一原则适用于修复轮次、后续工作、重试和队列中的下一个任务。

只有任务确实需要某个现有子代理独有且迁移成本高的状态时才恢复该代理、向其发送消息或为其安排后续任务，例如：仍在运行的进程、特定现场或难以重建的工作上下文。向正在运行的代理发送消息，停止或暂停指令不算复用。代理完成并返回结果后，由新的代理接手该角色的下一轮工作。连续中断并恢复代理会悄然丢失指令，因此应启动新的子代理并提供汇总后的完整任务范围，而不是相信一份“已完成”摘要。

共享工作区不隔离写入。调用者应明确各自可写范围、共享文件和集成者，候选产物保持隔离。

## 等待响应

需等待子代理响应才能继续时，默认采用至少 **10 分钟** 的响应式长等待，避免短时间轮询。等待工具上限不足时，用其允许的最长窗口等待。

## 接收结果

你要对每个子代理的工作负责。读取真实产物，审查差异并亲自撰写总结，不要直接转述子代理的结论。
