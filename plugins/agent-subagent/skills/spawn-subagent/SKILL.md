# Spawn Subagent

保留调用方已确定的目标、角色、范围、权限与输出；已有完整调度方法时沿用，不另建一套。

## 确定执行方案

**配置可用性以实际委派结果或明确声明的允许范围为准**：部分宿主或调度工具不会在 schema 中完整枚举所有受支持的模型或推理强度，按已选配置实际发起委派，仅在工具明确报错或存在硬限制后再按对应回退规则处理。

## 任务上下文

- **任务范围与依据**：提供当前目标、职责、对象与依据版本、仍有效的补充要求、必要输入，以及预算、输出与验收/停止条件。
- **权限与写入归属**：写清允许动作；共享工作区不隔离写入，并行委派前明确各自可写范围、共享文件与集成者，竞争候选产物保持目录隔离。
- **材料可达性**：为提示中的文件引用提供子代理可达的路径或访问方式；收到材料不可达缺口后，在授权内补充正文或可读路径，再决定继续或重派。
- **默认干净上下文的新子代理**：修复轮次、后续工作、重试与队列中的下一项，均启动新子代理并一次交给完整汇总范围（初始说明、后续有效指令、前序报告与分支），避免代理完成后被连续打断恢复导致早期指令静默丢失。**向仍在运行的子代理发送纠偏、补料或停止指令不算复用**；仅当任务依赖某现有子代理独有且迁移成本高的状态（如仍在运行的进程、特定现场或难以重建的会话上下文）时，才恢复已结束代理或沿原会话安排后续任务。

## 等待响应

需等待子代理响应才能继续时，优先使用宿主响应式唤醒或至少 **10 分钟** 的长等待，避免短轮询；等待工具上限不足时，使用其允许的最大窗口并续等同一任务。

## 接收结果

你对每个子代理的交付负责。亲自读取真实产物、核对差异并撰写结论，不直接转述子代理摘要。
