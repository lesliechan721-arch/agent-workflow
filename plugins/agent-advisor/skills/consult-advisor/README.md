# Consult Advisor

在任务推进遇到实质判断卡点或高代价拍板前，组织去锚定、独立的只读第二意见，打破主会话沉没成本与单一模型盲区，并由主会话逐条核验后决定是否采纳。

## 适合使用

- 同一前提下连续两次尝试仍未收拢，或存在互相冲突的假设/方案且单次廉价实验无法直接证伪。
- 即将拍板不可逆或高返工代价的技术架构、数据协议、分析结论、写作结构或业务策略，想先找反例与盲区。
- 用户或上游工作流明确要求独立第二意见或跨模型把关。

## 不适合使用

- 跑一次命令、测试或直查一手资料即可确认的事实问题（应先实测）。
- 明确的局部机械修改，或环境/凭据缺失报错。
- 应由用户本人拍板的需求或产品取舍（应直接向用户确认，而不是让顾问代做决定）。
- 需要对完整交付物做系统性全面审查，或需要并行产出多套完整竞争实现再融合的重型流程。

## 工作方式与结果

1. **去锚定提问**：整理一手材料、硬约束、已失败观察与该判断会改变的具体行动，剥离主会话倾向并显式要求顾问找反例与更简替代。
2. **独立（默认优先异构）咨询**：默认派 1 名独立顾问；在未配置专用顾问且任务允许外发时，若 `agent-subagent` 已注册与当前宿主不同厂商/家族的外部执行器，会优先通过 `spawn-subagent` 选用异构外部执行器以获得真正跨视角意见（无可用异构执行器时回退 `agent-subagent` 高难档；任务禁止外发时始终限定宿主原生 `native`，优先于所有默认与已配置外部路由）。极高分歧的不可逆决策在预算允许时可并行请 2 位独立顾问对照分歧前提。
3. **核验后裁决**：主会话对会改变行动的关键建议逐条查证一手依据，明确采用、不采用（附理由）或待补证。

## 边界

- 只读分析，不直接修改项目或替主任务拍板。
- **外发提示**：未配置插件覆盖且任务未禁止外发时，若本机 `agent-subagent` 已注册异构外部执行器，本 Skill 会优先将问题包发送至该外部后端；如任务涉密或禁止外发，请在请求中明确声明或通过配置固定为 `native`。
- 除在原生平台安装 1 条极简主会话触发规则外，不注册原生专属 Agent 角色，全平台统一通过 `spawn-subagent` 委派。
