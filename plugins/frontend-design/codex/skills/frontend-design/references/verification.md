# 结果验证

用于检查既有界面或核对本次实现。检查范围由任务和修改决定，不要求每个小改运行完整审计。

## 先建立可比较对象

确定页面或组件、实际数据、状态、主题、视口与验收依据。已有接受截图或原型时实际查看它，并在相应条件下对照实现；不存在的截图、缺失字体或未启动页面要作为缺口报告。旧截图可提供线索，但必须核对与当前版本的关系。

需要视觉判断时取得并实际查看渲染结果。需要交互判断时实际执行相应操作。HTML 存在、构建成功、DOM 快照和截图文件存在都不等于人已经看过外观；浏览器截图也不证明键盘、读屏或真实保存成功。

## 集中检查关键路径

先运行项目已有、与本次修改相关的构建和测试。再用当前可用浏览器能力集中检查主要视口和状态；完成用户明确要求的窄屏、主题或其他环境。命令和启动方式从项目取得，不自行安装工具或启动与任务无关的服务。

| 检查对象 | 观察什么 |
| --- | --- |
| 内容与层级 | 标题、主要信息、单位、条件和行动是否完整；视觉主次能否支持任务 |
| 布局与排版 | 实际长内容、图片加载、缩放和中间宽度下是否裁切、溢出或遮挡 |
| 操作与状态 | 主操作、等待、成功、失败、取消和恢复是否按真实合同工作 |
| 输入与焦点 | 键盘顺序、可见焦点、浮层关闭及返回；涉及拖动或复杂手势时，按适用条款分别验证非拖动、非路径的单指针替代（如点击/轻点）与键盘操作 |
| 色彩与动效 | 计算实际对比度；验证主题与减弱动效下的信息和操作不丢失 |
| 工程运行 | 无本次引入的资源失败、运行错误或明显迟缓；性能结论有测量条件 |

只检查实际存在且受影响的状态。完整表单需要成功与失败路径，纯排版修改可能只需真实内容、缩放和焦点不受影响的回归。不用截图张数、测试数或审美评分代替任务完成。

## 发现问题后修对应原因

先处理内容丢失、不可完成操作、错误状态和可访问性障碍，再处理间距与视觉一致性。把同一轮看到的问题合并修复，复验受影响路径及关键邻近状态。不能因为固定轮次已用完就将真实 blocker 标为通过，也不为主观偏好无限重排页面。

只读检查报告位置、复现条件、实际观察及用户影响；建议与已证实问题分开，允许等价实现。缺少浏览器时可完成源码、引用、编译和测试检查，但外观、设备交互与辅助技术结论保持未验证。不根据模拟或静态推断声称真实设备通过。

## 预览与证据边界

预览仍需要用户操作时交代查看方式；只关闭本任务创建且已不再需要的服务或会话。

作者自检、自动化工具结果、用户接受和独立审查是不同证据。当前检查不替任一缺失证据签字，也不自动授权提交、部署或发布。
