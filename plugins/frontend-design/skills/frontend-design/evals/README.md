# Frontend Design Eval

这些用例按当前仓库的 Manifest v1、trigger 与 conversation corpus 形式提供。`trigger` 检查是否加载，不要求成为第一个入口；`behavior` 检查实际产物、范围和证据。各 case 自带输入、允许写入路径、断言及判定理由。

行为族覆盖新页面、无设计文档的既有系统、只读检查、高频动效、中文数据窄屏适配、已确认原型的局部委派，以及明确授权的视觉重做。委派 fixture 是人工构造的本地消费测试，不证明真实工作流端到端交接或独立性。

手势回归包含自定义音量控件的修复与正确对照：前者已有拖动和键盘操作，但缺少单指针非拖动路径；后者只增加可点击、可轻点的等效控件，不应因仍支持拖动而被判错。判定依据是 [SC 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) 与键盘要求须分别满足，允许按钮、数值输入等有效替代。这两个用例仅覆盖拖动，不代表多点、路径手势、必需例外或真实触屏设备已验证；模型执行与准入状态见下文。

语义与视觉质量由实际模型结果及合格评审判断，不用 prose 正则、固定字体、截图张数或文件长度代替。没有动画可以是高频操作的正确答案；表格局部横向滚动也可以是有效适配。新增确定性测试仅应保护公开结构或真实产物边界，现有 AW validator 能覆盖的合同不再复制实现。

带 `holdout` 标签的项应在候选方法固定后才用于比较；标签只用于人工选择，不是运行器提供的隔离保证。若已用其结果调整正文，应重新保留未用于调整的任务。当前用例由作者编写和自检，尚无独立 Eval Audit，也没有模型运行结果；所有 suite 的 `requiredForRelease` 为 false，不代表质量已通过。

正式准备、准入和执行使用当前公开 AW Eval 工作流。执行前由未参与起草的合格上下文审核本次确切输入，并按运行器要求取得有效 Audit 和模型成本、网络及进程副作用授权。不能把包检查、EvalSpec 生成或作者自检说成模型评测成功。
