# 色彩与材质

调色、主题、状态、对比度、阴影与透明材质任务读取。

## 先定义颜色的职责

区分页面背景、内容表面、主要与次要文字、边界、主操作、选择态和语义状态。沿用已有语义 token，不让同一状态在不同组件中随机换色。品牌强调色不等于成功、警告或危险色；数据分类可能需要多个颜色，不能用“全页只许一种强调色”抹掉必要区别。

通过明度与层级建立秩序，色相和饱和度辅助表达身份。装饰色不应比主操作更醒目。中性底色可有冷暖倾向，但是否使用纯黑、纯白、紫色或渐变由品牌与场景决定，不设脱离语境的禁色清单。

浅色与深色主题分别校准，不对整组数值简单反转。检查文字、图标、状态、插图和半透明层在每种背景上的结果。OKLCH 等颜色空间可帮助组织色阶，但数值整齐不证明对比度合格。

## 对比度是计算结果

按实际呈现的前景和背景检查透明度、叠层、图片及渐变，不只检查 token 原值。必要时加稳定底面、遮罩或改变文字颜色；截图中“看起来清楚”不能替代计算。

[WCAG 2.2 SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 的 AA 基线是普通文字至少 4.5:1、大号文字至少 3:1。大号通常指至少 18pt，或至少 14pt 粗体，分别约为 24 CSS px 和 18.67 CSS px；CJK 要按等效字形大小判断，不能把任意 18px 正文当作大号。临界值不得向上四舍五入。标志、附带文字和非活动控件等例外按该条款核对，不把例外当作降低主要内容可读性的理由。

[SC 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 对识别控件、状态和必要图形的视觉信息要求与相邻颜色至少 3:1，适用例外见原条款。它不要求所有装饰边框都达到 3:1，也不是比较同一按钮未同时显示的两个状态色。焦点、选择、错误等信息要能识别，且不能仅靠红绿等色相变化传达。

## 材质表达关系

边框表达边界，阴影表达叠放，模糊和透明表达有意的前后关系。先确定关系，再决定效果；不要给每个区块同时加阴影、描边和玻璃层。复杂图片后面的透明面板尤其需要检查可读性。

圆角按组件职责和既有尺度设置，而不是全页强制同一值。嵌套圆角需结合内边距检查视觉间隙；小标签、输入框和大面板可以属于不同档位。图标保持相近笔画、视觉重量与对齐，已有图标库足够时不要再引入一套。

大量半透明叠层、大面积模糊或重复阴影可能带来渲染成本。效果确有价值时在目标设备检查；没有测量不声称性能良好，无法满足时降低表现复杂度而不是牺牲内容。
