# 动效与性能

新增或调整动画、手势、滚动效果，或诊断界面迟缓时读取。

## 先判断是否需要动

说明动效的作用：确认输入、解释状态变化、保持空间关系，或在低频场景中表现主题。若移除后更容易完成任务，就不必动画。高频导航、连续输入、快捷键和密集操作优先即时响应；低频展示可以更有表现力，但不能延迟操作或遮住内容。

按频率、移动距离和界面目的选择时长，不为全站强制一个值。按钮反馈和小浮层通常比整页过渡短；退出不应拖住下一步。缓动要让用户及时看见响应，空间移动要保持方向和来源一致。弹出层可从触发位置展开，居中的对话框不必伪装成锚定菜单。

不要给每张卡片复制相同入场，也不强制每个按钮缩放。颜色、边界、阴影或直接状态变化都可以提供反馈。单次展示的表达不能成为重复任务中的等待成本。

## 从中断和恢复设计交互

快速开关、反向拖动和连续输入应能从当前状态继续，不排队播放旧动画或在中途跳回起点。简单状态切换优先现有 CSS transition；多段时间序列、连续手势或复杂协调确有需要时，再使用项目已有的动画能力。选择 spring 时依据可中断性和运动反馈，而不是把弹跳作为高级感的默认答案。

拖拽需要明确的开始、移动、取消与结束，处理 pointer capture、滚动冲突及多指干扰。阈值应依据实际尺寸、距离、速度单位和任务风险选择，不复制没有单位的魔法数字。设计拖拽或其他手势前，按[触控与替代路径](interaction-accessibility.md#触控与替代路径)核对单指针替代与键盘操作。

## 减弱动效仍然可用

响应 `prefers-reduced-motion`，停止或减少非必要的位移、缩放、视差和循环效果，保留清楚的最终状态与操作反馈。功能完成不能依赖动画结束事件或固定延迟；移除动画后仍能关闭、提交、导航和读取内容。自动运动应能按适用要求暂停或停止，不接管用户正常滚动。

[WCAG SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) 对交互触发且非必要的运动动画提供关闭要求，属于 AAA 条款。本技能将减弱动效作为设计基线，但不把单独支持一个媒体查询说成完整 WCAG 合规。

## 依据测量控制成本

只过渡确实变化的属性，避免 `transition: all`。位移和透明度通常适合优先尝试，但是否进入合成层、是否产生昂贵绘制要实际观察，不能保证所有 transform 都免费。尺寸、阴影、滤镜、裁切和大面积模糊可用于有依据的效果，但要检查布局、绘制、合成及目标设备负载。

连续指针或滚动值不应无差别触发整个界面树重新渲染。把更新限制在实际变化的元素，使用已有机制按帧安排；组件移除时清理监听器和持续任务。不要在每帧读写交错地触发布局，也不要给全页永久添加 `will-change`。

先检查媒体尺寸与加载、字体请求、长任务、过度渲染和真实交互，再决定是否增加优化。测量记录页面、设备或模拟条件、操作和观察值。源码分析可以指出风险，只有同条件实际比较才能报告性能改善。
