# 交互、动效与可访问性条款

涉及交互组件、复杂表单/浮层、动效设计、拖拽手势、界面性能优化、界面文案，或需核对 WCAG 2.2 对比度/重排/命中区/手势精确条款与例外（见第 6 节）时读取。

## 1. 动效频率决策（先判断要不要动）

每个动效都必须能回答“它服务什么目的”（确认输入、解释状态变化、保持空间来源或低频叙事）；仅“看起来酷”的高频动效与无信息职责的持续悬浮/弹跳（idle bobbing）循环一律移除。

| 触发频率 | 默认决策 | 典型示例 |
| --- | --- | --- |
| **100+ 次/天或快捷键触发** | **0ms，不加动画**（动画会制造明显操作迟滞） | 命令面板开关、Tab 切换、键盘行导航、连续录入 |
| **数十次/天** | **无位移**；仅极短色彩/边界反馈（≤120ms）或直接切换 | 列表悬停、筛选切换、高频行选择 |
| **偶发状态变化** | **标准短过渡**，强调空间来源与即时响应 | 按钮按压、Tooltip、下拉菜单、浮层、抽屉、Toast |
| **低频 / 首访时刻** | 允许 **1 处编排式聚焦动效**，且不阻塞用户操作 | 页面首次亮相、首次引导、关键完成确认 |

## 2. 默认时长、缓动与空间细节

采用以下高响应起点；仅当品牌叙事、物理拖拽或用户明确规范要求不同节奏时调整并说明理由：

- **时长上限**：常规 UI 过渡控制在 **<300ms**（按钮按压 `100–160ms`、Tooltip 与小浮层 `125–200ms`、下拉/选择器 `150–250ms`、常规模态/Toast `200–300ms`）；仅大面积抽屉或全屏切换确需空间连续性时可至 `300–500ms`。**退出快于进入**（如入场 220ms、退场 150ms），避免退出拖慢下一步。
- **缓动曲线**：
  - 进入或退出：强 `ease-out`（如 `cubic-bezier(0.23, 1, 0.32, 1)`），起步迅速显跟手；
  - 屏内位移或变形：强 `ease-in-out`（如 `cubic-bezier(0.77, 0, 0.175, 1)`）；
  - 纯颜色或背景悬停：`ease`；匀速进度条/跑马灯：`linear`。
  - **常规 UI 默认避开 `ease-in`**（起步迟缓，同等时长下体感更卡顿）。
- **空间与微反馈**：
  - 弹层入场从 `scale(0.95); opacity: 0`（初始缩放不低于 `0.9`）起步，避免 `scale(0)` 凭空冒出。
  - 锚定浮层、下拉与菜单设置 `transform-origin` 指向触发元素；居中模态框保持 `transform-origin: center`。
  - 按钮按压可用轻微 `scale(0.97)`（0.95–0.98）或清晰的边界/色阶变化给出即时确认。
  - 多项成组入场用短错峰（stagger 30–80ms，单容器一次编排且不阻塞点击）；无 JS 入场优先考虑 `@starting-style`（按目标浏览器支持回退）；无缝高亮切换或擦除显隐可用 `clip-path: inset(...)`。

## 3. 可中断性、触屏隔离与减弱动效

- **可中断优于重启**：可能被快速连点、反复开关或中途反向打断的组件（下拉菜单、抽屉、Toast、折叠区），优先使用可中断重瞄的 CSS `transition` 或物理 spring，避免中断后从零重启的 `@keyframes`。连续触发时清除未执行的旧定时器，禁止旧延迟回调覆盖最新状态。
- **触屏悬停隔离**：悬停位移或缩放动效包在 `@media (hover: hover) and (pointer: fine)` 中，避免触屏轻点后悬停状态卡住；关键操作、字段解释与错误恢复绝不只藏在悬停中。
- **Tooltip 连续悬停**：首个 Tooltip 保留短延迟防误触，打开后指针移到相邻 Tooltip 跳过延迟与过渡（0ms），提升工具栏流畅感。
- **静息可见与原生滚动**：首屏标题与滚动揭示元素在静息、脚本未触发或减弱动效下均须保持可见可读，绝不卡死在 `opacity: 0`；自动运动支持暂停或停止，不劫持用户正常滚动，工具、新闻、目录、数据视图与侧栏导航保持原生即时滚动。
- **减弱动效（`prefers-reduced-motion`）**：作为设计基线（对应 [WCAG SC 2.3.3](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)，属 AAA），移除或大幅减弱位移、缩放、视差与循环动画，保留清晰的透明度或最终状态反馈。**功能流转绝不绑定 `transitionend` / `animationend` 或固定延迟**；移除动画后关闭、提交、导航和阅读必须完全成立。

## 4. 界面性能红灯

- **禁止 `transition: all`**：只声明实际变化的精确属性。
- **合成与重算控制**：优先过渡 `transform` 与 `opacity`（仍以目标设备实测为准，不假定所有合成免费）；控制大面积高半径 `blur` / `backdrop-filter` 与多层阴影叠加。
- **拖拽与滚动热路径**：连续指针或滚动驱动动画时，**直接更新目标元素的 `transform`**，不要在多子元素的父容器上高频修改可继承的 CSS 变量（会触发整棵子树样式重算）。避免每帧读写交错触发布局，不给全页永久添加 `will-change`，组件卸载时清理监听器与持续帧任务。
- **实测驱动优化**：先查媒体尺寸、字体请求、长任务与过度重渲染再做优化；同条件实测比较后再报告性能改善。

## 5. 浮层、表单状态与拖拽细节

- **浮层与复合控件**：检查遮挡、滚动穿透、视口边缘裁切与焦点归属。模态对话框严格遵循 [WAI-ARIA 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)（可访问名称、合理初始焦点、受控 Tab 循环、Esc 与关闭按钮、关闭后焦点返回触发器），不把模态焦点陷阱套给普通提示或下拉菜单；其他自定义复合控件按对应 APG 模式实现。
- **禁用与等待**：禁用操作说明原因或可恢复条件；使用 `aria-disabled` 时自行在事件处理中阻断动作。短操作用直接状态或轻进度，布局可预测的列表/卡片可用骨架屏，不用假进度或人为延迟。
- **错误与动态播报**：错误紧贴相关字段说明原因与修正路径，重要错误不只出现在短时 toast 中；动态结果按需用 `role="status"` 或 live region 播报，避免逐键刷屏。
- **破坏性操作**：依据风险与已有合同选择撤销或二次确认，不一律弹窗。
- **拖拽工程**：明确开始、移动、取消、结束状态；拖拽开始后调用 `setPointerCapture` 防止移出失焦，并处理与原生滚动的冲突（如按需设置 `touch-action`）；进行中忽略额外触点防止多指跳动；越界时使用阻尼摩擦而非生硬卡死；结合距离与带明确单位的速度阈值支持轻甩。

## 6. WCAG 2.2 精确速查表

在通用 Craft Floor 基础上，涉及对比度、重排、命中区或手势时按以下精确条款、单位与例外核对：

| 条款与级别 | 精确要求 | 关键例外与易错点 |
| --- | --- | --- |
| [SC 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)（AA 对比度） | 普通文字 ≥4.5:1；大号文字 ≥3:1（≥18pt[24 CSS px] 或 ≥14pt 粗体[18.67 CSS px]） | 按最终叠层/图片背景实算，临界值不向上取整；CJK 按等效字形判断，不把 18px 正文算大号；标志、附带文字与非活动控件例外见原条款 |
| [SC 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)（AA 非文本对比度） | 识别控件、状态与必要图形的视觉信息与相邻色 ≥3:1 | 不要求纯装饰边框 3:1，也不是对比未同时出现的两种状态色；焦点、选择与错误不能仅靠色相区分 |
| [SC 1.4.10](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)（AA 重排） | 普通纵向阅读内容在 320 CSS px 宽度下无双向滚动 | 确需二维布局的表格、图表或画布允许局部滚动，周围正文与操作仍须适配 |
| [SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)（AA 最小目标）与 [SC 2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)（AAA） | 实际命中区 ≥24×24 CSS px；主要触控控件优先 44×44 CSS px 作为更强起点 | 间距例外必须核对几何条件：以小目标中心画直径 24 CSS px 的圆，不与其他目标或相邻小目标的同类圆相交（不能只猜 padding）；另有等效控件、行内文字、未修改原生控件、必要呈现例外 |
| [SC 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)（AA 拖拽动作） | 作者实现的拖拽必须提供单指针、无需拖拽的等效操作（如点击/轻点按钮、直接输入数值） | **键盘操作（SC 2.1.1）不能替代单指针要求**；不用滑动替代拖拽；保留拖拽本身不是缺陷；未修改的浏览器原生控件与真正必需拖拽例外（“偏好拖拽”不算必需） |
| [SC 2.5.1](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html)（A 指针手势）与 [SC 2.1.1](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)（A 键盘） | 多点或依赖路径的手势须提供单指针、不依赖路径的等效操作；所有功能独立核对键盘可达 | 不用拖拽替代多点手势；长按不属多点或路径手势，但长按菜单仍应有易发现入口；保留必需例外，SC 2.5.1 仅针对内容解释的指针动作，浏览器原生滚动无需补造控件 |

## 7. 界面文案准则

- **用户语言与主动动词**：从用户视角命名（“通知设置”而非“Webhook 配置”）；按钮直述结果（“保存更改”而非“提交”），从按钮、等待到回执保持同一词义（“发布”→“发布中”→“已发布”）。
- **错误与空态给方向**：错误直接说明出了什么问题以及如何修正，不道歉、不模糊；空态区分“尚未创建”与“没有匹配项”，直接给出创建或放宽筛选入口。
- **保留业务事实**：不为了标签变短删掉单位、价格、日期或限制条件；先调布局，确需改写业务文案须核对授权。
