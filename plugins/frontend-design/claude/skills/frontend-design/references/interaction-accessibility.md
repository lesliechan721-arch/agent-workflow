# 交互与可访问性

控件、表单、状态、键盘、焦点、触控、手势和界面文案任务读取。

## 操作必须可识别、可完成

导航使用真实链接，页面动作使用按钮；保留原生控件行为或项目已有的可访问组件，不用可点击 `div` 代替完整交互。图标按钮有可访问名称，表单有持久标签，提示文字不代替标签。视觉顺序与键盘顺序一致，隐藏内容不能继续获得焦点。

先处理键盘可达和可见焦点，再增加 hover 或按压效果。触屏没有稳定 hover，不把关键操作、字段解释或错误恢复只藏在悬停中。禁用操作说明原因或可恢复条件；`aria-disabled` 本身不会阻止事件，是否可聚焦和如何阻断须与组件语义一致。

浮层检查遮挡、滚动、视口边缘和焦点归属。普通提示不要造成焦点陷阱；模态对话框要有名称、合理初始焦点、受控的 Tab 顺序、关闭方式及关闭后的焦点返回。遵循 [WAI-ARIA 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)，不要仅加 `role="dialog"` 就认为行为完成。需要实现其它自定义复合控件时查对应模式，不把模态行为套给所有菜单。

## 状态对应真实合同

对每个受影响操作确认它实际可能经历的状态。异步提交通常要处理等待、成功、失败和重试；数据视图区分首次空白、筛选无结果、加载失败和权限不足。状态不是为了凑齐固定清单，不适用的状态不必制造。

等待时给出及时反馈，避免重复提交，保留用户输入。骨架适合布局可预测的内容，简单进度或文字可能更适合短操作；不能用假进度或人为延迟制造“精致感”。只有真实回执支持时才显示成功，演示操作明确说明不保存或不发送。

错误靠近相关字段或区域，说明具体问题和下一步，允许修正后继续。重要错误不能只出现在很快消失的 toast 中。按需通过状态区域或 live region 传达动态结果，避免把每次按键和装饰变化都播报。破坏性操作的确认或撤销依据风险与已有合同选择，不一律弹窗。

## 文案减少理解成本

按钮说明将发生的动作，例如“保存更改”而不是无上下文的“提交”。同一操作从按钮、等待到结果保持同一词义。提示给出可执行信息；空状态区分“尚未创建”和“没有匹配项”，分别提供创建或调整筛选的路径。

保留业务术语、单位、价格、日期和限制。为了标签更短而删掉重要条件会改变含义；先调整布局，确需改业务文案再核对授权。未知客户、统计、资质和结果不能当作真实界面内容。

## 触控与替代路径

点击区域按实际命中区测量，不等同于图标尺寸。[WCAG 2.2 SC 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) 的 AA 最小目标通常是 24×24 CSS px，并有间距、等效控件、行内文字、未修改的原生控件和必要呈现等例外。利用间距例外时，要检查以小目标中心绘制的直径 24 CSS px 圆不与其它目标或相邻小目标的同类圆相交，不能只猜一个 padding 值。

主要触屏控件尽量提供更大的目标；44×44 CSS px 是更强的设计起点，并与 [SC 2.5.5](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html) 的 AAA 条款有关，不是所有 AA 控件的硬性尺寸。

作者实现的拖动功能按 [SC 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)（AA）提供单指针、不需拖动的等效操作；多点或依赖路径的手势按 [SC 2.5.1](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html)（A）提供单指针、不依赖路径的等效操作。点击或轻点可作为共同替代，不用滑动替代拖动，也不用拖动替代多点手势。长按本身不等同于多点或路径手势；长按菜单仍应有易发现的入口。

键盘支持按 [SC 2.1.1](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html) 单独核对，不能替代单指针要求。例如排序可提供可点击的“上移/下移”，或先点选项目再点选目标；这些入口也应能用键盘完成。只有快捷键、没有可点击或轻点的等效入口，仍未解决指针用户的困难。

两项手势条款按各自定义保留必需例外；“偏好拖动”不构成必需。SC 2.5.7 还排除由用户代理提供且作者未修改的功能；SC 2.5.1 只针对内容解释的指针动作。浏览器原生滚动无需补造控件，作者自行实现或接管的手势则要按相应条款核对。

语义、对比度和尺寸检查只覆盖其中一部分要求。完整可访问性结论还需要适用页面、完整流程和相应辅助技术验证，不从单个自动化分数推导合规。
