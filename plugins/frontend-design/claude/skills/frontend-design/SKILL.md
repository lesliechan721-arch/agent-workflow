# Frontend Design

为前端工作提供设计判断和可实施细节。按请求交付方案、页面、组件或局部改进，不把设计方法变成额外的产品流程。

## 取得设计依据

读取任务范围、真实内容、受众、主要操作、技术约束和已确认设计。查看现有页面、组件、tokens、字体和素材；引用了截图或原型时实际查看，并核对页面、状态及版本。没有设计文档不等于没有设计系统，现有实现也可能已形成有效视觉语言。

先区分当前工作：新建无既有约束的界面、扩展现有系统、局部打磨，还是明确授权的视觉重做。扩展和打磨保留未受影响的品牌、内容、行为与组件约定；视觉重做也不自动授权改变产品事实和业务流程。用户明确要求优先于通用审美偏好。

从材料能确定的事实直接采用。只有缺口会改变页面用途、关键操作或不可逆选择时，说明其影响并提出聚焦问题；普通布局和实现选择自行处理。缺少素材、数据或接口时说明具体限制，演示数据与真实承诺分开，不编造客户、评价、指标或服务能力。

## 从页面用途选择设计重点

按本次页面而不是整个产品选择重点；同一网站的首页、控制台和帮助页可能不同。

| 用户要完成什么 | 优先设计什么 |
| --- | --- |
| 理解价值并采取行动，如营销页、活动页 | 真实内容的特色、可信证据、视觉主次和清楚的行动路径 |
| 完成重复任务，如后台、表单、编辑器 | 扫描效率、状态区分、信息密度、可预测操作和系统一致性 |
| 阅读并理解，如文档、文章、帮助 | 内容结构、阅读节奏、导航和上下文定位 |
| 观看或探索作品，如作品集、画廊 | 作品呈现、探索顺序和不妨碍内容的交互 |

新页面、整体重做或方向尚不明确时，读取[视觉方向](references/visual-direction.md)。已有方向下的局部任务直接进入受影响主题，不重新开展风格选择。

## 按问题展开方法

只读取当前会影响决定的主题。完整页面通常需要多个主题；小改只读取相关部分。

| 当前问题 | 读取 |
| --- | --- |
| 字体、内容层级、密度、布局、窄屏重排或多语言 | [排版与布局](references/typography-layout.md) |
| 调色、主题、语义色、对比度或层次材质 | [色彩与材质](references/color-material.md) |
| 控件、表单、状态、键盘、焦点、触控或界面文案 | [交互与可访问性](references/interaction-accessibility.md) |
| 动效、手势、滚动效果或界面性能 | [动效与性能](references/motion-performance.md) |

## 落到当前产物

先确定内容和操作的层级，再决定排版、颜色、空间与表现性细节。新设计用少量相互支持的选择形成识别度；已有系统复用其语义 token 和组件。不要用重复卡片、无信息的装饰标签或同款首屏掩盖内容组织问题，也不要为避免模板感破坏用户指定的风格。

采用项目现有技术栈、包版本、样式体系和可访问组件。需要新增依赖时先证明现有能力不足，并遵守项目授权；不因为某种审美就更换框架、字体服务或动画库。将视觉变体和通用值放到已有复用位置，不为一次局部修改新建一套设计系统。

交互元素必须保留语义、键盘可达性和可见焦点。状态不能只靠颜色或动效传递；窄屏、长文案和实际内容应能使用。新增异步交互按真实合同覆盖等待、成功、失败和恢复，不给纯静态元素虚构状态。没有后端时实现明确的演示边界，不能以成功提示冒充真实保存。

按任务指定的位置交付必要设计说明，保留已确认的页面、状态、关系及允许变化范围；现有对话或文件足够时不另建记录。

## 核对与交付

检查已有界面或完成实现后，按[结果验证](references/verification.md)核对真实产物。实现任务修复影响验收的问题并复验；只读检查报告问题，不修改产物。

交付当前入口或修改位置、重要设计取舍、实际检查及结果，以及仍未验证的页面、状态或环境。仅设计请求交付可实施的设计，不声称代码已完成；仅静态阅读不声称视觉、浏览器交互或完整可访问性合规已通过。
