# Frontend Design

把网页与产品界面的视觉方向、结构层级、交互动效和真实渲染验收一起做好。从零建页或整体改版时摆脱千篇一律的模板感；在既有项目里扩展或打磨时守住品牌、设计系统与业务合同。

## 安装与使用

在包含本插件的 Catalog 来源中选择目标：

```bash
aw target set codex claude
aw plugin install frontend-design --scope user
```

安装目标包括 Codex、Claude Code、Antigravity、Cursor、OpenCode、Pi、GitHub Copilot CLI 和 Grok Build；`generic` 只输出通用 Skills。AW 按目标核对组件能力，并提示客户端无法保证的调用控制。

支持 user 和 project 安装范围，无插件配置项。唯一技能是 `frontend-design`，既可按任务自动采用，也可显式选择。

```text
使用 frontend-design，为我们的独立烘焙工坊设计并实现官网首页。先给我几个风格与首屏构图方向选定后再写代码，避免套用常见 SaaS 卡片模板。
```

```text
使用 frontend-design，改善这个订单后台列表的扫描密度、异常状态和手机端操作。保留现有品牌色、字段和交互，不要做成营销页。
```

```text
使用 frontend-design，只读诊断结算页的排版、交互和可访问性问题，按缺陷和建议分开报告，不要修改文件。
```

## 适用范围与工作方式

- **按页面用途采用不同工艺**：营销页和作品集突出视觉主张、色彩承诺与首屏记忆点；后台、表单和编辑器优先熟悉感、紧凑字阶、清晰状态与高频零迟滞；文档与阅读页把品牌识别留在外框，让正文阅读栏保持克制。
- **展示页与整体重做先对齐方向**：面向营销、活动或作品展示的绿地页与整体视觉重做，在方向开放时会先给出 2–3 个实质不同的方向卡与首屏线框，一轮确认后再编码；若你已指定风格、要求自行决定直接交付，或只是扩展/打磨既有界面，则会直接实施。
- **默认真实渲染核查**：实现完成后，只要当前环境具备浏览器能力，会先停稳动画并检查桌面、窄屏和关键交互态，合并修复并复验（细节打磨至多一轮，阻塞项修闭或如实披露）；无浏览器能力时如实区分静态检查与未验证的外观项。
- **只读界面诊断**：诊断类请求只读输出“已证实缺陷 / 可选设计建议 / 未验证范围”，不擅自改动文件。

## 边界

本插件不负责完整产品需求访谈、正式规格审批、独立双轴代码审查或多任务开发协调；方向确认仅限视觉世界、色板字体与首屏构图。纯后端、纯前端业务逻辑修复和已确定数值的机械样式替换通常直接处理即可。

实现请求会修改授权范围内的文件，并可能运行项目已有的构建、测试或预览命令；只读检查不会写入文件。插件不自带外部运行器、浏览器、字体或素材服务，不自动安装依赖、创建长期设计文档、提交 Git 或部署；外部访问和有副作用的操作遵守当前工具及授权。
