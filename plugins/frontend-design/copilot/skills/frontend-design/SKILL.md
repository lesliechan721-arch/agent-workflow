# Frontend Design

为网页与产品界面提供清晰的设计判断、高工艺实现与有依据的诊断。

## 基本底线

- **既有实现即视觉权威**：开工前读取任务范围、真实内容、技术约束、现有页面、组件、tokens、字体与素材；引用了截图或原型时实际查看并核对版本。缺少 `DESIGN.md` 不等于绿地项目，从多个实际页面抽样区分系统规律与偶然样式。
- **用户指定与既有系统优先**：用户或 brief 明确指定的风格、品牌、配色、字体与布局高于下方默认反模式；在未指定的自由轴上，必须遵守反模板红灯与模式默认，不落回通用模板。
- **事实与技术栈边界**：业务规则、价格、时间、文案事实与既有可用行为不可擅改。缺素材或无后端时诚实标注演示边界，不编造客户、评价、指标或“假保存成功”；严禁猜测未核验的外链图片 URL 或硬编码本机绝对路径，项目内素材统一使用相对路径。默认复用项目现有技术栈、样式体系与可访问原语；新增依赖须先证明现有能力不足并获授权。

## 1. 选择工作路径

先判定任务类型，再沿对应分支推进：

| 任务类型 | 处理方式 |
| --- | --- |
| **新建页面 / 明确授权的整体重做** | 读取 方向与系统（`references/direction-and-systems.md`）。展示/作品类且方向开放时先给 2–3 个方向卡与首屏线框确认再写码；操作/阅读类及已定调、要求直出或无交互场景按参考内的跳过条件完成内部契约与反默认自检后直接实现 |
| **既有系统扩展 / 局部打磨** | 保留既有品牌、tokens、字体、控件语言与未受影响区域，新变体放入已有复用位置，跳过方向重选；按下方页面模式默认与 Craft Floor 直接处理指定范围 |
| **受委派实现已确认原型或规格** | 严守已确认的页面布局、状态关系与接受范围，不重开方向探索或访谈；在允许变化范围内落实视觉、布局与交互工艺 |
| **只读界面设计检查** | 严守只读，不修改文件；按 核查与诊断（`references/review-and-verify.md`）三分栏输出，并按检查主题读取第 4 节对应参考 |

方向确认严格限定在**视觉世界、色板字体与首屏构图**，不扩展成产品需求访谈或业务流程定义。仅当关键信息缺口会改变页面用途、核心操作或不可逆选择时才补充聚焦问题；普通布局与实现细节自行决策。

## 2. 按页面模式采用工程默认

按**当前页面**（而非整个产品）选择模式；同一网站的官网、控制台和帮助文档应采用不同默认：

| 页面模式 | 典型页面 | 排版与字阶 | 色彩与材质 | 首屏与布局 | 动效默认 |
| --- | --- | --- | --- | --- | --- |
| **说服** | 营销页、落地页、活动页 | 有态度的展示字体与明显字阶对比 | 允许高承诺主色场或大面积色块建立识别 | 首屏直出核心主张、真实产品/实景证据与主行动 | 最多 1 处编排式聚焦动效，不做全页散点入场 |
| **操作** | 后台、表格、表单、设置、编辑器 | 单家族无衬线 + 固定紧字阶（1.125–1.2），不用流体 `clamp()` 大标题 | 克制双中性层级区分主区与侧栏/工具栏 + 完整语义状态色 | 熟悉感、扫描效率与清晰密度优先，统一控件词汇 | 零首屏加载编排；高频与快捷键操作 0ms 即时响应 |
| **阅读** | 文档、文章、指南、帮助 | 清晰标题层级；西文正文约 60–75ch，中文按实际字号与行高实测断行 | 品牌识别留在外框（顶栏、目录栏、代码块/提示块），阅读主栏保持克制 | 内容结构、阅读节奏与当前位置导航优先，不做成海报 | 仅服务导航或展开反馈，绝不干扰正文阅读 |
| **作品** | 作品集、画廊、展陈 | 服务作品气质，不喧宾夺主 | 衬托作品主体，控制界面噪声 | 首屏直接让作品本体出场，界面退后 | 可具表现力，以不妨碍观看与探索为界 |

新闻首页、博客、检索/目录索引、实用工具、后台、文档与简历应直接进入实时内容、工作区或文稿，绝不前置全屏营销横幅把正文或操作压到首屏以下。

## 3. 通用 Craft Floor（默认红灯）

所有实现与检查默认核对以下具体红灯，不必等读取子参考：

- **反模板默认（自由轴默认避开）**：
  - 用留白、背景色阶、细分割线或非对称主次组织叙述，不把普通内容硬切成等大三列图标卡片，避免卡片套卡片；编号（`01 / 02 / 03`）只用于真实顺序。
  - 用纯排版层级表达普通元信息，不使用非交互的装饰性标签、徽章或分类块（无论胶囊圆角还是方框描边），描边与胶囊形态留给交互控件及真实业务/系统语义状态（如订单、任务、表格或接口状态）。
  - 模式、尺寸、筛选等选择优先用分段切换、Tab、单选、开关或 `<select>`，不堆砌独立描边按钮墙。
  - 靠字阶、间距与主动动词建立层级，避开标题上方装饰眉标（全大写 eyebrow、`A · B · C` 隔点眉标、`WORD — 副词`）、标题内单字异色/斜体强调、链接/按钮乱加 `→` 与渐变字。
  - 避开幽灵卡片（1px 边框叠宽柔阴影）、圆角框单侧竖条装饰，以及假 `LIVE` 圆点、`SCROLL` 提示、侧边旋转装饰字与空转悬浮动画等伪遥测装饰。
  - 图标使用项目图标库或精简内联 SVG，不用 Emoji 或 Unicode 符号充当图标系统；展示/作品类绿地页在自由轴避开典型 AI 默认皮与高频默认展示字体（详见 `references/direction-and-systems.md`）。
- **排版与布局**：
  - 标题上方间距大于下方，靠亲密性分组；正文和标签使用相对单位并允许缩放，不靠缩字挽救布局。
  - 桌面导航保持单行紧凑，品牌名/字标的视觉权重明显高于导航链接；固定或吸顶顶栏在滚动后须提供清晰底面分离，避免下方正文文字与其重叠碰撞。
  - Flex/Grid 子项含长中文、长 URL 或长文件名时设 `min-width: 0` 与合理断行；媒体预留宽高比或尺寸防加载跳动。
  - 全屏高度按浏览器工具栏与内容选策略，不无条件套用 `100vh` 或 `100dvh`；嵌套圆角按内边距校准视觉间隙。
  - 下拉菜单与浮层必须逃离 `overflow: hidden` 祖先（用 `<dialog>`、Popover API、`position: fixed` 或 portal）。
  - 窄屏按任务重组而非等比缩小：需跨行比较的表格保留在自身可发现的局部横向滚动容器内，逐项处理可转为带字段标签列表；禁止静默丢列或用全局 `overflow-x: hidden` 掩盖溢出。
  - 普通纵向阅读内容在 320 CSS px 下正常重排；多语言任务检查文案膨胀、逻辑方向属性与数字格式。
- **色彩与对比度**：
  - 按实际叠层、透明度、渐变或图片后的前景/背景计算对比度（WCAG 2.2 AA：普通文字 ≥4.5:1，大号文字 ≥3:1，控件边界/状态与必要图形 ≥3:1；CJK 不把 18px 正文算作大号；字号换算与精确例外见 `references/interaction-and-motion.md` 第 6 节）。
  - 浅/深色主题分别校准而非简单反转；品牌主色不替代成功、警告或危险语义色；OKLCH 等色阶整齐不代表对比度合格。
  - 彩色底面上的次要文字用该底色色相调制，避免生硬纯灰；需纵向比较的数字启用 `font-variant-numeric: tabular-nums`。
- **语义、状态与输入**：
  - 导航用 `<a>`，动作优先原生 `<button>` 或既有可访问组件，不用可点击 `<div>`；表单配持久 `<label>`（不用 `placeholder` 替代），图标按钮有可访问名称。
  - 视觉顺序与键盘顺序一致，保留融入当前配色的清晰 `:focus-visible`；隐藏或关闭的面板/浮层不可继续获得焦点（使用 `hidden`、`inert`、`visibility: hidden` 或原生 Popover/`<dialog>`）。
  - 异步交互按真实合同覆盖等待、成功、失败与恢复，保留用户输入且防重复提交；数据视图区分首次空白、筛选无结果、加载失败与权限不足；不为纯静态元素虚构无关状态，状态不能只靠颜色或动效传达。
  - 命中区 ≥24×24 CSS px（主触控控件优先 44×44 CSS px）；作者实现的自定义拖拽必须提供单指针非拖拽等效操作（如点击/轻点按钮或数值输入），键盘快捷键不能替代单指针路径（间距例外与多点/路径手势见 `references/interaction-and-motion.md` 第 6 节）。

## 4. 按需读取条件参考

只读取本次任务命中的参考，均为单跳直达：

| 命中条件 | 读取参考 |
| --- | --- |
| 新建页面、明确授权重做，或视觉方向尚不明确 | 方向与系统（`references/direction-and-systems.md`） |
| 涉及交互组件、复杂表单/浮层、动效、拖拽手势、性能、界面文案，或需核对 WCAG 2.2 对比度/重排/命中区/手势精确条款与例外 | 交互、动效与可访问性条款（`references/interaction-and-motion.md`） |
| 实现后的验收核查，或任务本身是只读界面诊断 | 核查与诊断（`references/review-and-verify.md`） |

## 5. 核查与交付

实现完成后，按 核查与诊断（`references/review-and-verify.md`） 执行构建/测试与渲染核查（环境具备浏览器能力时默认实际看图并批量修复复验；细节打磨至多一轮，阻塞项须修闭或如实披露）。

实现或设计任务交付直奔结果：当前入口或修改位置、核心设计取舍（若有方向自检，简述反默认调整）、实际检查与结果，以及未验证的视口、状态或环境（只读检查按 `references/review-and-verify.md` 三分栏交付）。仅设计请求交付可实施的设计契约或方案；现有对话或文件足够时不另建设计文档。
