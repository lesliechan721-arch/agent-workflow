# 核查与诊断

完成实现后的验收核查，或任务本身是只读界面设计检查时读取。

## 1. 实现后验收闭环（Verify → Batch Fix → Re-verify）

检查范围随修改面缩放，不给极小改动强加无关审计，但不得省略受影响路径的真实核查：

1. **运行项目校验**：先跑与本次改动相关的项目构建、类型检查或测试；命令与启动方式从项目取得，不擅自安装工具或启动无关服务。
2. **默认批量渲染核查**（当前环境具备可用浏览器能力时执行）：
   - **先停稳入场动画再截屏**：防止仍在渐显或位移中的元素被误判为缺失，修出新回归。
   - **抓图并实际查看渲染结果**：涉及 Web 字体、相对路径素材或模块脚本时优先经项目本地开发/HTTP 服务加载；桌面端（如 1440px）同时截取并查看**首屏与按真实视口高度滚动后的首屏以下分区**，并覆盖窄屏（375/390px；普通纵向阅读内容另查 320px）及内容易折行的中间断点（如 768/1024px）。若有已接受的截图、原型或旧基线，在同条件下对照差异。
   - **驱动可达交互状态**：核对主操作、悬停与按压、键盘 Tab 顺序与 `:focus-visible`、浮层打开/关闭及焦点归还、等待/成功/失败/空态、自定义拖拽的单指针替代，以及 `prefers-reduced-motion` 下的完整可用性。
3. **集中核对以下具体项目**：
   - **内容与层级**：关键事实、单位、条件与主行动完整可见；新建或整体重做时，对照方向契约确认首屏主张成立、首屏以下至页脚保持同等视觉工艺与字阶纪律，并检查是否可删去一处无信息职责的装饰。
   - **布局与溢出**：核对横向溢出（`document.documentElement.scrollWidth <= document.documentElement.clientWidth`，二维表格允许容器内局部滚动）；检查桌面导航单行不折行、品牌权重高于导航链接、吸顶顶栏滚动后底面分离不与正文碰撞，以及真实长文案、中文/大号展示标题、图片加载、缩放与中间宽度下无裁切、重叠或被固定栏遮挡。
   - **色彩与对比度**：对实际叠加在色块、半透明层、渐变或图片上的文字与控件计算对比度，确认浅/深色主题均可读。
   - **运行与性能**：控制台无本次引入的报错、404 资源或明显迟缓；性能改善结论须给出同条件实测记录（页面、设备/模拟条件、操作与观测值）。
4. **合并修复并复验**：按“阻塞项（内容丢失、业务事实错漏、不可完成操作、A11y 障碍、错位裁切）→ 一致性与细节打磨”合并一轮修复，随后在相同视口与受影响状态上复验。视觉与细节打磨至多一轮，不为主观偏好无限重排；若复验仍暴露真实阻塞项或引入新回归，仅针对阻塞项继续修闭并复验（同一根因连续两次修补失败则停手排查前提并如实披露）。未关闭真实阻塞项不得宣称通过。
5. **收尾与预览**：需用户自行查看预览时写清打开方式；只关闭本任务新建且不再需要的服务或会话。

## 2. 只读界面设计检查

任务要求仅诊断、给建议或只看源码时，**严守只读，不修改任何文件**；明确禁止打开浏览器或联网时，仅基于源码与静态资源完成判断。

按三分栏交付结果：

1. **已证实缺陷**：按严重程度排序，每项给出精确位置、复现条件或源码/截图依据、用户影响及具体修复方向。涉及明确的代码或样式改法时，推荐用紧凑 `Before | After | Why` 对照，但不强求所有条目硬套同一表格。
2. **可选设计建议**：视觉层级、版式节奏、风格细节等存在多种合理等价解的建议单独列出，不冒充阻塞缺陷。
3. **未验证范围**：明确列出因缺少浏览器、真机、运行后端或辅助技术而未覆盖的项。

## 3. 证据边界

- **静态不代视觉**：源码检查、构建通过、DOM 快照与截图文件存在均不证明已看过外观；未实际查看渲染图不做视觉通过结论。
- **截图不代交互**：静态截图不证明键盘顺序、焦点管理、读屏播报或真实后端保存成功。
- **局部不代合规**：桌面模拟不等于真机触屏表现；单个自动化分数或支持某条媒体查询不等于完整 WCAG 合规。
- **自检不代签字**：作者自检、自动化工具、独立代码/设计审查与用户接受属于不同证据；当前检查不替代缺失证据，也不自动授权提交、部署或发布。
