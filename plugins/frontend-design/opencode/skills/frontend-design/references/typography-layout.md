# 排版与布局

字体、层级、空间、密度、响应式和多语言任务读取。

## 排版服务阅读任务

先选角色，再选字体：正文、标题、操作标签、数字和代码各需要什么辨识度。已有品牌字体和系统字体都是可用选择，不为了“独特”增加下载、缺字或与产品不一致的字体。只引入实际需要的字重，确认字体来源、授权和目标语言覆盖；回退字体也应保持可读和相近布局。

阅读页用稳定正文、清楚的标题层级和适当行长组织长文；工作型界面可用较紧凑的字号级差，让大量标签与数据仍能区分。展示型标题可使用更大尺度或流体字号，但不能挤压主要操作。不要把 `clamp()`、某个衬线字体或全大写当作所有场景的规则。

西文长段落可从约 45–80ch 的行长试起，再看字号、字宽和内容；`ch` 不是通用字符数，不能把这个区间直接当成中文每行字数。中文、日文和混排应实际检查字形、标点、断行与行高。负字距、过紧行高或固定高度可能裁切字形，尤其是斜体、重音和上下标。

使用真实最长标题、按钮标签、日期和数量检查。数字需要纵向比较时可用等宽数字特性，并保持单位、精度和对齐一致；不要让所有标签都变成等宽字体。正文和标签用相对单位并允许缩放，不靠缩小文字挽救布局。

## 先分组，再设置间距

按信息关系分组：同一控件的标签与提示靠近，不同任务组留出更明确的距离。复用小而一致的间距尺度，同时允许内容关系决定例外。先检查共同对齐线、容器宽度、行高和网格，再修单个元素的像素偏移。

选择布局机制时，二维对齐通常适合 Grid，一维排列适合 Flex；内容流优先，绝对定位留给确有叠放关系的元素。侧栏、内容区、工具栏和浮层的层级应有不同职责。紧凑不等于拥挤：减少重复容器和冗余标签，不能靠删除必要字段或缩小点击区域获得密度。

## 响应式是重组，不是等比缩小

从内容开始失效的位置选择断点，沿用项目断点体系。检查中间宽度，而不只看手机和桌面两个端点。窄屏下重新安排列、导航和操作优先级；浮层与固定底栏不能遮住内容或键盘焦点。

表格的窄屏方案取决于任务：需跨行比较时保留表格，并在自身容器内提供可发现、可操作的横向滚动；逐项处理时可改为带字段标签的列表。不能默默丢列、裁掉操作或用全局 `overflow-x: hidden` 掩盖溢出。

对长链接、文件名和不换行内容检查最小内容宽度；按需设置可收缩子项和合理断行。媒体保留宽高比或尺寸，避免加载后推动布局。全屏区块按浏览器工具栏与内容需求选择高度策略，不把 `100vh` 或 `100dvh` 作为无条件答案。

多语言任务检查文案膨胀、逻辑方向与数字格式。使用逻辑属性表达起止方向，确保视觉排列与 DOM 阅读、键盘顺序一致。对普通纵向阅读内容核对窄至 320 CSS px 的重排；确需二维布局的表格、图或画布可保留局部滚动，但周围正文与操作仍应适配。适用条件见 [WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。
