# Ask Me

在动手前建立足够准确的共享理解。

Ask Me 不会把所有细节都问一遍。它先读取对话、代码、配置和文档，只把会明显改变用户可见结果、权限、范围、验收或返工成本的问题交给用户。

## 安装

```bash
aw install ask-me -p both
```

## 包含的 Skill

| Skill | 什么时候使用 |
| --- | --- |
| [`requirements-clarifier`](skills/requirements-clarifier/) | 具体实现请求只有少量关键歧义，需要用最少问题补齐边界 |
| [`decision-grill`](skills/decision-grill/) | 需要通过多轮访谈把计划、方案或重要决定想透并形成共享理解 |

## 典型用法

```text
实现订单导出。先检查有没有会影响成品或验收的关键歧义。
```

```text
围绕新的权限模型逐轮提问我，直到目标、取舍、失败路径和验证方式都清楚。
```

## 它会做什么

- 先调查可以自行确认的事实。
- 区分“需要用户决定”“可以采用默认”“需要实验验证”。
- 优先询问会影响后续分支的上游问题。
- 有依据时给出推荐和主要取舍。
- 结束时返回简短的已确认内容、默认值和待验证事项。

## 它不会做什么

- 不因为任务较大就自动开始长访谈。
- 不询问纯内部实现细节或已经有项目惯例的事项。
- 澄清期间不修改文件，也不自行开始实施。
- 不把测试、压测或原型才能回答的技术事实交给用户猜测。

## 两个 Skill 怎么选

- “这个具体功能还有一两个关键点没说清” → `requirements-clarifier`
- “我需要把整个方案或决定系统地想清楚” → `decision-grill`
