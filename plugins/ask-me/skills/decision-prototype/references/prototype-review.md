# 网页反馈

只在标准交互页面比当前对话更便于比较、操作、标注或多轮反馈时使用。Review Shell 展示证据并收集用户输入，不替用户选择方案。

## 启动与展示

从 Skill 根运行 `node scripts/prototype-review.mjs --help` 查看可用操作和参数。启动当前配置对应的会话；若运行时已返回匹配的提交结果，直接消费该结果，不重复打开页面。

优先使用当前环境**能向用户展示可操作页面**的原生浏览器、预览或端口能力。仅供 agent 截图、检查 DOM 或自动化操作的浏览器，不等于用户可以看到的界面。

已有用户可见能力时先使用它，并核对会话的页面连接信息。没有该能力或发生技术失败时，使用脚本的 `open` 操作兜底打开同一会话。脚本因技术问题打开失败时，使用当前系统浏览器打开能力，打开会话中的同一 URL；不要重新启动会话。若通过脚本重试，使用 `--retry`，普通重复调用会复用已有打开结果。自动打开均失败时，输出会话 URL，让用户自行打开，然后继续等待反馈。打开进程成功只表示已发出请求；页面连接只表示加载就绪，都不表示用户已经阅读或决定。

用户拒绝打开或平台拒绝权限时停止，不换工具绕过。远程或无桌面环境不能在用户侧展示时，优先采用已提供的安全转发或预览；仍不可用则说明环境限制，保留原型与问题。输出 URL 时说明尚未解决的可达性限制，不把远程 localhost 说成用户本机地址，不声称已经打开，不默认公开服务。

## 等待与继续

展示或提供手动打开 URL 后执行 `wait`，默认等待 5 分钟。在工具允许的范围内尽量使用默认或更长窗口；需要调整时通过 `--timeout` 显式设置。支持后台执行时让同一次长等待持续运行，并按工具允许的较长间隔取得结果；需要进度更新时保持响应。不要使用几秒一次的短轮询。等待超时不取消仍有效的会话，也不代表用户决定；按需继续长等待，仅在需要诊断会话状态时查看 `status`，不忙轮询、不重复启动。

会话到期、取消或失联时，先确认是否已有有效提交；没有提交则保留问题和原型。用户仍要反馈时复用有效会话，或在原会话已终止后启动新会话。运行时负责服务到期和提交后的资源回收；不要用进程名称批量终止程序，也不要关闭用户浏览器。

只有运行时验证的 `submitted` 和对应反馈才能形成决定。所有 `submitted` 回执都包含运行时已校验的完整 `feedbackData` 和 `feedback` 文件路径。直接消费 `feedbackData`，核对当前原型 ID 和 revision，无需例行再读文件；仅在旧回执缺少完整内容或需要排查时读取 `feedback.json`。随后自动继续当前任务，不要求用户回到聊天输入“已完成”。

## 解释反馈

- 接受：保存当前答案、条件和支持证据。
- 要求修改：只处理与本问题有关的反馈，修改原型并递增 revision，再取得新反馈。
- 拒绝当前方向：保留拒绝及必要原因，重新确认候选方向，不把它当作接受。
- 出现新的材料问题：说明新问题，暂停当前原型扩张。

机器字段及合法值由 schema、运行时校验和命令输出负责。页面中的候选、评论、标注和受控参数按当前需要启用，不额外生成另一套 Review 界面。
