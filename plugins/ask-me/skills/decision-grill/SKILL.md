# Decision Grill

和用户一起把计划或重要决定想清楚。这里讨论的计划或决定本身是当前任务的产物，不是 agent 为完成其它任务安排的内部步骤。

## 梳理关键分支

1. 先只读查看当前对话、已有方案、决策记录以及相关代码和文档。能查到的事实自行确认，不把事实问题交给用户。
2. 只展开可能改变方向的重要分支：
   - 要解决的问题、非目标和成功标准；
   - 硬约束与核心取舍；
   - 主要备选，包括维持现状或不做；
   - 关键假设及其依据；
   - 失败、降级、恢复、迁移和回滚；
   - 验证方式，以及何时需要重新评估。
3. 用户已经作出的决定，只有在依据明显不足、与其它要求冲突、主要后果尚未想清楚或反转条件不明确时才重新讨论。不要为了完整而穷举细节。
4. 需要测试、压测、原型或外部证据才能回答的问题，列为待验证事项，不让用户替技术事实拍板。

## 逐轮讨论

- 优先问能影响多个后续分支的上游决定；互相独立时每轮最多三题，一题只讨论一个取舍。
- 适合给选项时优先使用 `{{questionTool}}`；工具不可用或选项不合适时，直接简洁提问。
- 给出推荐时，说明推荐依据、主要收益和代价。
- 收到回答后更新判断；只有答案带出了新的重要分支时才继续追问。

## 收尾

当重要分支都已有决定、明确委托、转为待验证，或被明确延后并接受风险时结束；不要继续进入低影响细节。

输出简短的决策记录，按需包含：**决定 / 关键取舍与假设 / 待验证 / 未解决**；省略空项，然后把控制权交还原工作流。

讨论期间不修改文件、不做原型，也不自行开始实施。
