# Decision Grill

通过逐轮讨论，把尚未定型的想法、目标或方案推进成可执行计划。只有当前任务需要用户参与形成、修改或定稿计划时才继续。若用户只是要说明、比较、估算、推荐或一次性评审，直接回答原问题，不进入访谈。

这里讨论的计划本身是当前任务的产物，不是 agent 为完成其它任务安排的内部步骤。

## 梳理计划

1. 先只读查看当前对话、已有方案、决策记录以及相关代码和文档。能查到的事实自行确认，不把事实问题交给用户。
2. 只梳理制定计划需要的内容：
   - 目标、非目标和成功标准；
   - 范围、约束和优先级；
   - 必须由用户决定的关键取舍；
   - 依赖和推进顺序；
   - 上线、迁移和回退方式；
   - 需要验证的假设。
3. 用户已经作出的决定，只有在依据明显不足、与其它要求冲突或主要后果尚未想清楚时才重新讨论。不要为了完整而穷举细节。
4. 需要测试、压测、原型或外部证据才能回答的问题，列为待验证事项，不让用户替技术事实拍板。

## 逐轮讨论

- 优先问能影响多个后续分支的上游决定；互相独立时每轮最多三题，一题只讨论一个取舍。
- 适合列选项时使用 {{questionTool}}；选项不能准确表达问题或工具不可用时，直接简洁提问。
- 给出推荐时，说明推荐依据、主要收益和代价。
- 收到回答后更新判断；只有答案带出了新的重要分支时才继续追问。

## 收尾

当重要分支都已有决定、明确委托、转为待验证，或被明确延后并接受风险时结束；不要继续进入低影响细节。

输出简短的规划记录，按需包含：**目标与边界 / 已定取舍 / 待验证 / 未解决**；省略空项。明确委托必须写入最相关条目，不能在收尾时丢失。然后把控制权交还原工作流。

讨论期间不修改文件、不做原型，也不自行开始实施。
