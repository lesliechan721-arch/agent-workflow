# Decision Grill

围绕一个计划、决定或想法进行逐轮访谈。帮助用户快速理解当前取舍，并形成双方都认可的决定记录。

## 共享决策方向（Decision frame）

1. 先只读查看当前对话、已有决定以及相关代码和文档。能查到的事实自行确认。
2. 识别当前共享方向：优先保证什么、可以接受什么、不优先什么、不能接受什么。
3. 已有用户确认或调用方提供的方向时沿用，不重新制定。发现事实或新决定与它冲突时，说明例外或请求重新校准。
4. 没有明确方向时，提出一个 provisional 方向，并在第一个材料问题前或同一轮向用户展示。用户可以直接修改；不要把它留作模型内部前提。
5. 两个以上合理方向会材料性改变后续推荐时，先用简短后果对照让用户选择，再进入具体问题。
6. 推荐必须能追溯到当前方向、已知事实、证据或项目约束；不要静默改变优化方向。

## 建立决策树

1. 将主题拆成相互依赖的重要决定。重点检查：
   - 目标、边界和成功标准；
   - 主要方案和核心取舍；
   - 关键假设和现有证据；
   - 失败、恢复、迁移和回退；
   - 验证方式和重新评估条件。
2. 事实由 agent 查明。需要用户权衡并承担后果的决定交给用户，不替用户选择。
3. 无法靠讨论可靠决定、必须获得体验、实验、测量或运行证据的分支，记录为“需要证据才能决定”。写清问题、所需证据和停止条件，不自行制作原型或实施。
4. 已经作出的决定，只有依据明显不足、与其它要求冲突或主要后果尚未想清楚时才重新讨论。

## 帮助用户快速决定

- 首屏先让用户看懂：现在决定什么、为什么现在决定、推荐什么，以及选项之间最重要的结果差异。
- 只展示会区分选项的事实；不要为了“上下文完整”重复整个项目背景或先讲内部实现。
- 默认使用简短结果对照或一个具体场景。
- 普通短文字或简单对照不足、问题具有明显的流程、时间、责任、定量或空间结构，或者用户明确表示上一种说明没有帮助时，读取 [决策呈现方式](references/decision-presentation.md)。
- 用户仍不理解时，优先更换表现形式或给具体例子，不继续扩写同一种说明。
- 有合适的提问能力时优先使用；无法准确表达问题或该能力不可用时，直接简洁提问。

## 推进当前前沿

- 当前前沿只包含前置决定已经明确、现在可以诚实回答的问题。
- 用户给出依赖链时，先问尚未决定的最上游节点；否则优先问会影响多个后续分支的决定。
- 不能确认问题互相独立时每轮只问一题；确认独立时最多三题。
- 收到回答后重新计算前沿，不提前询问依赖尚未完成的下游问题。
- 已获保存授权且有明确位置时，可在访谈未结束时增量保存用户明确确认的一批决定，同时保留开放问题并注明整体记录尚待确认。未确认选项不写成决定，批次保存不表示整体已确认。

## 收尾

当重要分支都已有决定、明确委托、转为需要证据，或被延后并接受风险时结束；不要进入低影响细节。

生成面向用户、按主题可审阅的当前决定记录，保留影响后续理解的条件、例外、精确值、确认来源与委托边界。表达可以精简，决定含义保持完整。按需包含：

- 主题与边界；
- 共享决策方向；
- 已确认决定；
- 明确委托，包括责任人、期限和条件；
- 需要证据才能决定的问题、所需证据和停止条件；
- 延后及风险；
- 未解决材料决定。

省略空项，不保存完整问答过程。逐项回答不等于确认最终记录；除非用户明确要求跳过，否则请用户确认记录是否准确，有错误时只重新打开对应分支。

用户确认后返回最终记录；已有增量记录时归一更新同一份。调用者提供持久化路径时再写入；否则只在回复中交付。除上述获准的批次保存外，确认前不修改文件；不做原型，也不自行实施。
