# Decision Grill

目标：提高计划或决策的质量；先暴露重大分支，再收敛。

## 1. 建立事实底座

先只读检查当前对话、已有计划、决策记录及相关代码或文档。区分已知事实、用户决定、未经验证的假设和待验证命题；自行查明可发现事实。只使用读取和搜索，把测试、原型和实施留给外层工作流。

## 2. 建立决策地图

只扫描可能实质改变结果的分支：

- 目标、非目标和成功标准；
- 约束、所有者和核心取舍；
- 主要替代方案，包括维持现状或不做；
- 关键假设及其证据；
- 失败、降级、恢复、迁移与回滚；
- 验证方式和重新评估信号。

仅在证据薄弱、与其它要求冲突、主要后果未被理解或反转条件不清楚时，重新挑战已有决定。以重大分支为边界，不追求穷举。

## 3. 询问当前前沿

优先询问能剪掉多个下游分支的上游决策。互相独立时每轮最多三题，一题只处理一个取舍；适合单选时使用 {{questionTool}}，否则直接简洁提问。推荐时说明依据、服务的目标和主要代价。

用户回答后更新决策地图；答案打开新的重大分支时再加入问题。将需要测试、原型、压测或外部证据的技术命题记为待验证项。

## 4. 收敛

当重大分支已经决定、委托、明确延后并接受风险，或转化为清楚的待验证项时结束。

输出紧凑的决策简报，按需包含：**决定 / 关键取舍与假设 / 待验证 / 未解决**。省略空项，并把控制权交还外层工作流。
