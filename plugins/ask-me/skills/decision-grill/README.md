# Decision Grill

通过逐轮访谈，把计划、方案或重要决定想清楚，并形成双方确认的共享理解。

## 适合使用

- 多个决定相互依赖，不能靠一次回答解决。
- 需要比较主要方案、取舍、失败路径和验证方式。
- 希望压力测试一个计划或重要技术方向。

## 工作方式

Skill 会先调查事实，再建立重要决定之间的依赖关系。每轮优先处理会影响多个后续分支的上游问题，并在有依据时给出推荐和代价。

当重要分支已经决定、明确委托、转为待验证或被接受风险地延后时，Skill 会生成简短决策记录并请用户确认。

## 不适合使用

- 只需要一次性解释、比较或评审。
- 具体实现只有少量局部歧义；此时使用 `requirements-clarifier`。
- 问题必须通过原型、测试或外部证据回答。
