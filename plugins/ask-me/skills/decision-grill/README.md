# decision-grill

通过逐轮访谈把计划、方案、设计或重要决定想透，并形成双方确认的共享理解。

## 什么时候使用

- 你明确希望被追问、共同推演或逐轮修订一个决定。
- 需要收敛目标、取舍、假设、失败路径、迁移和验证方式。

不要用于一次性说明、比较、推荐或 Agent 自己的内部计划。实施任务只有局部需求歧义时，使用 `requirements-clarifier`。

## 怎样调用

模型可以按明确的访谈意图自动调用，也可以显式使用 `$decision-grill`。

示例请求：

- “逐轮追问我，把这次 API 兼容策略想透后再制定计划。”
- “压力测试这个迁移方案，直到我们对回退条件形成一致理解。”

## 会发生什么

1. Agent 先查明可发现事实，再建立相互依赖的决策树。
2. 每轮只推进当前可以诚实回答的上游决定，并重新计算后续问题。
3. 重要分支收敛后，Agent 输出决策记录并请你确认。

## 权限和边界

- 决策记录确认前不修改文件、不做原型，也不开始实施。
- Agent 不替用户决定需要用户承担后果的事项；需要实验的数据会列为待验证。
