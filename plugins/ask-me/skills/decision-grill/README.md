# Decision Grill

通过逐轮访谈，把计划、方案或重要决定想清楚，并形成双方确认的共享理解。

## 适合使用

- 多个决定相互依赖，不能靠一次回答解决。
- 需要比较主要方案、取舍、失败路径和验证方式。
- 希望压力测试一个计划或重要技术方向。

## 工作方式

Skill 会先调查事实，再把推断的共享决策方向（Decision frame）在第一个材料问题之前或同轮展示给你。若多个合理方向会改变推荐，它会先用简短后果对照请你选择方向。

每轮优先处理会影响多个后续分支的上游问题。首屏说明当前决定、现在决定的原因、推荐和主要结果差异。默认使用简短结果对照或具体场景；只有问题具有流程、时间、责任、定量或空间结构，或用户仍未理解时，才升级表现形式。必须体验时转为需要 Prototype 的证据问题。

当重要分支已经决定、明确委托、转为需要证据或被接受风险地延后时，Skill 会生成包含共享决策方向的简短决策记录并请你确认。确认后的记录是本 Skill 的最终产物。

## 不适合使用

- 只需要一次性解释、比较或评审。
- 必须看到、运行或操作候选方案才能决定。
- 只需要测试、压测或外部证据确认技术事实。

确认前不会修改文件、制作原型或自行开始实施。

主要指令见 [`SKILL.md`](SKILL.md)，评测材料见 [`evals/`](evals/)。
