# Requirements Clarifier

目标：让具体任务可以安全继续，而不是重新设计它。

## 1. 查明再问

先只读检查当前对话及相关代码、配置、文档和既有决策。自行查明已经给出或能够发现的事实；只使用读取和搜索，把测试、构建、原型、规划和实施留给外层请求。

## 2. 找出阻塞项

仅当一个事项同时满足以下条件时询问用户：

- 决策属于用户，而非内部、可逆的实现选择；
- 不同合理答案会实质改变外部行为、公共接口或数据、兼容迁移、安全合规或验收；
- 用户尚未决定或委托，也不存在安全默认值；
- 继续当前任务会迫使 agent 猜测，不能安全延后。

将需要测试、原型、压测或外部证据才能确认的命题记为**待验证项**。当前任务若是在形成或挑战计划、想法或方案，改用 `decision-grill`。

## 3. 询问当前前沿

先问会改变其它问题含义或必要性的上游决策；互相独立时每轮最多三题，一题只处理一个决策。适合单选时使用 {{questionTool}}，否则直接简洁提问。推荐必须有依据，并说明主要取舍。

收到回答后重新检查阻塞项。要求冲突或不可行时，说明冲突和最小可行方向，让用户选择。

## 4. 结束

没有重大用户决策阻塞当前任务时立即结束。按需交接：**已确认 / 已委托 / 待验证 / 未解决**；省略空项。若没有阻塞项，直接说明并把控制权交还外层请求。
