# Ask Me

目标：在开发实现或设计讨论继续之前，只澄清会显著改变结果的未知决策，避免 agent 用未经确认的假设替用户决定产品方向。

本 skill 只负责澄清。澄清状态只保留在当前对话中；不得创建、修改或删除文件，不得改变配置或其它环境状态，不得制作原型，也不规定确认、规划、编码或任何后续动作。

## 触发门禁

- **隐式调用**：仅当开发实现或设计讨论仍有未知项，且不同答案会显著影响目标、范围、行为、接口、数据、兼容性、约束、验收或可行性时继续。若需求已经明确、只剩低风险细节或用户只问事实，立即交还控制，不人为制造问题。
- **显式调用**：当用户通过 `$ask-me`、`/ask-me` 或等价方式明确调用时，始终对已陈述需求执行一次隐藏假设压力测试，再判断当前决策前沿。

无论哪种触发方式，都跟随用户当前使用的语言提问。

## 工作流

1. **先查明事实**
   - 从当前对话、代码、配置、文档和环境中只读查找能够发现的事实。可以使用只读搜索、读取和诊断工具，但不得执行写操作。
   - 不向用户询问能够自行查明的事实；只把真正需要用户选择的产品决策和取舍留作问题。
   - 若没有相关仓库或工具不可用，使用已有上下文继续，不把缺少工具当作自行脑补的理由。
2. **建立决策树**
   - 将仍未确定的高风险决策按依赖关系组织。当前“决策前沿”只包含前置决策已经确定、现在无需猜测即可回答的问题。
   - 排除不会显著改变结果的偏好、低风险实现细节，以及能通过只读探索回答的事实。
   - 每轮收到答案后重新计算前沿；答案依赖尚未解决问题的事项留到后续轮次。
3. **询问当前前沿**
   - 有依赖关系时，一次只问最关键的一题。彼此独立时，一轮最多问三题。没有固定的总问题数。
   - 优先使用 {{questionTool}}。使用两个或三个互斥且有效的单选选项，并保留自由输入能力；不要把多个独立决策塞进一个选项。
   - 只有能够指出仓库证据、明确成本或通行约束时，才把某个选项标为推荐；否则平等呈现选项。没有合理选项时才直接提出一个简洁的开放问题。
   - 提问后等待用户回答，再进入下一轮。工具不可用时，退化为同等简洁的文本提问。
4. **处理冲突与不可行性**
   - 若用户的要求互相矛盾或在现有约束下不可行，指出具体冲突、证据或成本，并给出最小可行的替代方向供用户选择。
   - 不静默改写用户意图，不把 agent 的替代方案伪装成用户已经作出的决定。

## 结束条件

- 高风险决策前沿清空时结束并交还控制。不要求固定摘要、再次确认或建议下一步。
- 用户表示不知道、要求停止或不愿继续时，简要标记仍未解决的事项及其可能造成的返工风险，然后交还控制；不得声称需求已经稳定。
- 结束前确认澄清期间没有写文件、制作原型或执行其它有副作用的动作。

不要因为本 skill 结束而自行开始确认、规划或实施；后续行为由外层请求和适用指令决定。
