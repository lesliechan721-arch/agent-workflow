# Decision Prototype

制作一个用户可以直接反应的轻量原型，用最低成本回答一个明确决定。

## 工作流

1. 先读取当前对话、已有决定以及相关代码和文档。确认阻塞点是一个需要用户判断的问题，而不是可以调查的事实或普通局部实现选择。
2. 写出唯一的原型问题、用户需要观察什么，以及得到什么反馈后可以停止。不要用“探索整个产品”代替具体问题。
3. 选择最便于用户判断的形式：图片、候选文案、可点击网页、流程 walkthrough、API consumer 示例、状态模拟器或最小技术 spike。
4. 读取并使用 [原型说明模板](assets/prototype-brief.md)。优先使用用户或调用者给定的目录，其次遵循仓库约定；都没有时使用清楚命名的隔离目录 `prototypes/<decision-id>/`。清楚标记验证范围、有意忽略和查看方式。除非用户明确要求保留，避免覆盖生产文件。
5. 向用户展示或提供操作方式。适合有限选项时使用 `AskUserQuestion`；否则请用户说明观察、偏好和无法接受的部分，然后等待回答。
6. 记录已经确认的决定、证据、被否决方案、未解决项和新的材料问题，然后结束。不要在本 Skill 内开展新的决策访谈、编写 Spec 或进入生产实现。

## 输出

按需返回：

- **决策问题**
- **原型产物和体验方法**
- **用户观察**
- **已确认决定**
- **支持证据**
- **被否决方案**
- **新的材料问题**
- **未解决项**

原型默认可丢弃。只有用户明确选择复用，且后续实现者重新评估结构、测试和风险后，生产实现才可以从原型演进。
