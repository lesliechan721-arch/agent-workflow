# 决策呈现方式

只在普通短文字或简单结果对照不足以让用户快速理解当前取舍时读取。简单 owner-choice 不需要本文件。

## 选择表现形式

| 当前问题 | 优先形式 | 重点 |
| --- | --- | --- |
| 两个方案取舍 | 两列结果对照 | 每列只写最重要收益、代价和适用条件 |
| 用户可观察行为 | 一个具体场景 | 说明用户会看到什么、失败时会发生什么 |
| 状态或生命周期 | 3–5 步流程 | 只显示决定点和结果，不展开内部调用 |
| 保留、迁移、兼容 | 时间线 | 标明开始、过渡、停止和回滚点 |
| 责任和组件边界 | 小型关系图或责任表 | 谁拥有、谁调用、失败归谁处理 |
| 数量、成本、性能 | 少量数字或图表 | 只显示会改变选择的区间和阈值 |
| 空间、视觉、操作感受 | 可体验证据 | 用户需要看到、点击或调整后才能决定 |

## 决策卡

不要求固定字段，但首屏应覆盖：

- 需要决定什么；
- 为什么现在决定；
- 推荐和主要理由；
- 选项之间最重要的结果差异；
- 用户现在可以怎样回答。

## 压缩和切换

- 技术术语只有在它本身是用户决定对象时才放在首屏。
- 先说用户结果，再按需解释机制。
- 每个选项最多突出一个主要收益和一个主要代价；其它细节按需展开。
- 若用户仍不理解，换场景、流程、时间线或示意，不把原说明扩写成更长版本。
- 如果任何文字或静态表示都不足以决定，记录为需要体验、实验或测量的证据问题；不要在本 Skill 内制作该证据。
