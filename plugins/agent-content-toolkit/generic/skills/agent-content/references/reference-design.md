# 重组多文件资料

在迁移共享规则、调整大型资料或比较读取路径时使用。

## 沿任务盘点

选择一条真实常见路径，以及确有不同读取需要的条件路径。逐步查看入口、正文、指针与目标资料，记下读者此时要解决的问题、实际需要的段落和找不到的依据。没有独立分支时不人为制造一条。

先判断内容仍是否有用，再选择位置。把每个必要概念的定义、规则与例外放到一起；同一含义有多份时确定权威来源。原始业务资料、当前规则与历史讨论分别标明，不能把历史措辞直接当成当前要求。

## 选择迁移方案

共同方法放在入口正文。可独立命中的主题使用条件指针；全部同层且大部分同时需要的长参考，可以保留并增加主题导航。小段内容搬成新文件前，比较减少的无关读入是否值得新增读取和维护。

原材料缺少方法时，从真实依据补足决定性信息，不只改变位置。资料本身已足够时，先修指针的条件和名称，不把整份文档搬回正文。

需要跨上下文交接的内容，保留接受的决定、输入、重要设计和完成要求，并给接收者可访问的入口。仅改变文件位置不等于建立上下文隔离。

## 完成迁移并验证

采用目标结构后同步引用和所有实际消费者，移除不再维护的重复正文。不能留下只有旧作者知道的新位置，也不能把说明性示例路径当成真实资源。

从原材料核对定义、主体、条件、单位、权限、顺序、例外和要求强度，再用新结构走过选定路径。查看每次读入是否有用，必要信息能否直接找到，以及用户还需要记住哪些选择。

报告实际迁移与保留的含义、路径变化及验证范围。字符减少可以说明体积变化，不能单独证明理解、模型效果或执行成本改善。
