# Reference Design

在多文件、大型材料或读取路径存在争议时使用；创建和评价遵守同一原则，不要求固定审计产物。

## 先判断需要，再决定位置

每份材料服务什么真实任务条件？命中条件后要用其哪些部分？内容是否属于同一个主要概念或步骤？是否更适合正文、示例、数据、脚本或环境事实源？

定义、规则和例外应共置；区分重复与被拆散的概念。无价值内容先删除，不为它寻找新的参考位置。保留必要背景、理由与陷阱，不以“可查”否定所有摘要。

## 到达与导航

指针同时说明目标和读取条件。必要材料没有被可靠读取时，先改善指针，再决定是否前置少量核心内容。

选择一条相关常见路径和一条有区别的条件路径，检查实际读入量、各文件使用比例和跳转成本；没有不同路径时不编造第二条。清单可留在当前分析，不要求另存文件。

当两个主题可以独立使用且经常只需其中之一，按条件拆分通常有益。同一路径总一起使用的几行规则可以内联或合并。短文件数量和一层可达性都不能单独证明设计良好。

## 大文件的处理

尺寸只触发检查，不直接判错。平坦、权威、命中任务后大部分都需要的 reference 可以保留；必要时加清楚目录或章节锚点。约 300 行或 4000 个估算 token 是内部审阅提示，不是通用上限，估算应说明方法。

可以保留、加索引、按条件拆分、前置核心内容、转为脚本/数据、改读事实源，或先做删除对照。建议指出实际减少的读入或导航成本，以及保留信息的风险；不强制使用状态枚举。

磁盘中的平台副本会增加安装和维护成本，但只有被读取的副本才占本次上下文。也不要用删除人工选择的方式“解决”本来必要的判断或授权。
