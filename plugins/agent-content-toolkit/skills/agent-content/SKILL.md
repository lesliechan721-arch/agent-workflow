# Agent Content

用于编写和评价 Agent 读取的文档：项目指令、Skill 正文、角色说明，以及经指针读取的资料。目标是让不同输入下的执行遵循可靠方法，而不是每次产生相同答案。按当前请求编辑或只读评价；具体业务知识取自用户材料、项目事实和已确认决定。

## 上下文指针（Context pointers）

上下文指针是在已读内容中指向未读材料，并说明读取条件的文字。Skill 的 description、项目指令中的文档入口和正文的 reference 链接都承担这个作用。材料再完整，入口没有说清命中条件，也可能无法进入当前任务。

写指针时把有区分度的动作或概念放在前面，同时交代材料是什么、哪些分支需要它。一种条件的多个同义说法合并为一种；不要把目标正文已经说明的身份和背景再塞进入口。

“需要时参考资料”没有提供选择依据；“核对历史数据时读取兼容规则，按数据版本选择字段映射”给出了条件和用途。必要资料被漏读时，先修指针的措辞、位置和条件；修正仍不能可靠到达时，再前置必要内容。所有任务都需要的共同方法直接放正文。

## 两种负担（The two loads）

**Context load** 是常驻材料占用的上下文：项目指令、Skill description，以及每次都提供的入口。常驻指针即使命中率低，也持续占用注意力，应比正文更精炼。按需资料用一条指针换取发现能力，命中后才产生该次读入。

**Cognitive load** 是人需要记住哪些资料存在、何时选用的负担。没有入口的文档把发现工作全部交给人。人的判断权并非应最小化的成本：保留有价值的选择和确认，移除只有记忆和导航成本的选择。

评估一次实际任务时，另看该次读取的正文、参考资料和查找跳转；已读内容是否继续保留取决于环境。磁盘副本多不等于本次读入多；删除人的入口也不等于降低了全部成本。

## 信息层级（Information hierarchy）

先区分两种内容：**步骤**是执行者要做的有序动作，**参考**是判断时使用的定义、规则和事实。文档可以全是步骤、全是参考，或两者组合。完整、同层的规则集合可以平铺，不必套成流程。

按当前读者需要它的时点选择层级：

| 层级 | 放什么 | 何时使用 |
| --- | --- | --- |
| 文内步骤 | 当前任务的动作及必要先后关系 | 推进当前工作 |
| 文内参考 | 与本任务紧密相关的定义、规则和例外 | 同一任务中查阅 |
| 条件披露的参考 | 只有部分任务分支需要的细节 | 命中指针条件后读取 |

**渐进披露**首先保护主线与参考的层级关系。不要在相邻步骤中插入所有分支的完整说明，也不要把所有路径需要的规则藏到额外文件。看真实分支如何使用材料，而不是按篇幅平均拆分。

**共置（Co-location）**处理同一层中哪些内容应该相邻：把一个概念的定义、规则和例外放在同一主题，使读者一次读到完整含义。重复是同一含义出现多次；散落是一个含义被拆到多处。前者合并，后者聚合。

内容即使都有效且不重复，也可能多到掩盖当前动作。先按独立分支披露，必要时给同层长参考增加主题导航；只减少字符不能修复错误的信息层级。

## 步骤与完成条件（Completion criteria）

先确认这一步确有必要，再分别检查完成条件的**清晰度**和**要求程度**。

清晰度决定能否区分完成与未完成。“已经理解”缺少可检查界限；“每个输入字段均已映射到目标字段，无法映射的字段已逐项说明”能定位缺口。后续步骤可能诱使执行者提前结束当前工作，先修当前完成条件；确有仓促结束且局部措辞无法解决时，再考虑分离阶段。

要求程度决定覆盖哪些对象、做到什么程度。“给出修改清单”只要求一个产物；“每个实际修改文件都有对应原因，受影响调用点已核对”要求实际调查。平坦参考同样可以有覆盖要求，无需为每条规则另造一步。

完成条件应既可检查，又覆盖该任务真正需要的对象。保留必要单位、条件、例外和约束强度；不能用“保证质量”代替它们，也不要为无用步骤补上更重的门禁。

## 何时拆分（When to split）

某些分支需要、其它分支不需要的内容，适合通过条件指针拆出。每次都一起使用的短方法通常共置。按执行顺序拆分时，需要明确当前阶段交付什么、后续阶段从哪里取得它。

隐藏后续步骤需要真实的上下文边界。在同一上下文打开另一文件，不能清除已经看见的后续步骤。只有观察到阶段干扰且环境支持隔离时，才为这个目的拆分；不能仅凭文件分开就声称注意力已隔离。

需要重组多份文档、迁移共享规则或比较大型资料的读取路径时，使用 [Reference 组织](references/reference-design.md)。

## 引导词（Leading words）

引导词是读者已有的紧凑概念，可把相关判断集中到一个稳定名称，例如“回归”“基线”“幂等”。正文用它指向同一类动作，指针用它连接用户请求、项目词汇和目标材料。作用不只是统一术语，也在于调用已有知识。

查找反复用整句话解释同一概念的位置：能用已有准确术语表达时，保留一次必要定义，其后使用同一个词。自造词没有现成含义，需支付解释成本；短缩写但含义不明，通常没有节省。

优先直接表达期望动作。“只汇总已提供的记录”比围绕禁止行为展开长段更容易定位任务。必要的禁止项与可行替代放在一起；不要为了肯定措辞改变原来的权限和边界。

## 剪枝（Pruning）

**单一事实源。** 同一含义维护一处完整定义，调用位置留下当前判断需要的指针。重复一个术语有助于联系概念，重复整条规定则增加维护位置，并可能夸大其优先级。

**环境事实。** 当前命令、配置和目录优先从实际文件或 help 取得。缓存应有理由：查询昂贵、资料难到达，或执行前必须知道某个非显然陷阱。保留环境不会自行说明的约定、选择原因和错误假设，不重复容易查询的参数表。

**相关性。** 逐段判断它是否仍服务当前职责。失效规则、讨论过程、没有任务用途的背景应删除；只服务某个分支的细节移到该分支。必要的因果解释和领域知识不能因属于“说明”而一律删除。

**No-op。** 模型已经可靠完成、写上后不改变行为的句子可能没有增量价值。判断依赖目标模型和任务，不能凭个人偏好确定。明显的泛用提醒整句删除；价值有争议时比较有无该段的结果。弱而空泛的强调词同样需要检验。

## 来源与保真

摘要、重组和交接保留当前读者需要的目标、决定及精确条件。主体、单位、约束强度、例外和顺序不能因缩写而改变；图像、交互和接口中无法从摘要恢复的关系，保留可核对来源及已接受范围。

按实际用途保留输出格式。用户需要复制的 JSON、程序读取的字段或后续实施需要的材料，不因它们是结构化内容就删掉。过程讨论与当前要求分开；结论对应证据的覆盖范围，局部测试摘要不能单独证明完整设计或界面一致性。

## 核对修改

用当前读者的一个代表性任务沿新文本查找材料、作出选择并核对完成条件；有独立分支时加一条对照。重组前后核对定义、条件、例外和必要依据，确认新指针确实到达目标。

报告实际修改与检查。静态阅读只能说明材料和路径的判断，行为收益须有实际运行支持。需要人读评价版式时采用 [内容评审模板](assets/content-review-template.md) 的适用部分。
