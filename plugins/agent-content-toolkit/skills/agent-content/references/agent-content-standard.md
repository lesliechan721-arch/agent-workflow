# Agent-facing 内容共同标准

这些原则用于 prompt、项目指令、角色说明和参考材料。按当前任务采用，不要求每次输出完整检查表。它们不定义能力包装、运行时调度或项目发布政策。

## 读者、事实与目标

明确或从现有材料确定：谁会读、要完成什么、内容何时进入上下文、适用范围与必要约束。只写模型缺少且对目标有用的领域事实、稳定约定、选择理由和非显然陷阱。

项目事实以用户材料或实际环境为依据。未证实的目录、测试命令、组织流程和政策不能写成既有事实；建议和待确认假设单独说明。不为显得完整而补造背景。

新建或大幅重组、且必要行为尚不清楚时，先概括最小行为目标；小改不必产出单独合同或计划。

## 两种负担

**Context load** 是当前任务实际进入 Agent 上下文的内容：常驻说明、此次读入的材料、重复规则与模板。按实际读取路径评估，不把磁盘上所有副本相加当成一次上下文。

**Cognitive load** 是人需要记住哪些材料存在、何时提供或选择它们、哪些决定需亲自作出的负担。减少无价值的选择，但保留有价值的判断和授权；不能为了自动化而消除人的控制。

Agent 的查找、术语理解和文档跳转另按导航成本检查。少文件不自动更轻；把所有内容集中可能增大上下文，把每段拆开也可能让人和 Agent 更难定位。

## 指针与信息层级

外部指针说明材料是什么、在什么条件下需要。相同条件的同义词不算不同分支；必要内容不能只靠“详见资料”等弱指针到达。

漏读时先检查指针位置、措辞和条件；若仍不能可靠到达，再把少量关键内容前置或内联，不直接搬回整个参考文件。同一概念使用清楚、稳定的名称，不以生造缩写节约文字。

区分：当前必须执行的步骤、同文件按需规则、条件加载的参考材料、确定性脚本、模板或数据、环境事实源。平坦且同层的规则集合可以共置，不为拆分而制造文件。

## 最小充分控制与完成条件

先判断步骤是否必要，再规定怎样结束：唯一合法、高风险或脆弱操作需要清楚顺序和停止条件；有可靠默认时提供默认及适用例外；多种方法合理时给目标、选择依据和验收要求，保留模型判断。

优先说明期望行为。必要的安全禁止应保留，并在适用时给出安全替代动作；否定句本身不是缺陷。经验例子标为例子，不伪装成所有任务的必经流程。

真正必要的步骤，其完成条件应能区分完成与未完成、可观察核验、覆盖必要对象，不允许形式完成。后续步骤引起仓促结束时，先修正局部完成边界；不能用更复杂的 gate 挽救多余步骤。

## 输出要求

先看结果给谁使用以及怎样使用。用户明确要求的 JSON、表格或文件格式可以有价值，不必先找到已存在的 parser；面向人以可读性为主，机器消费按实际合同保留必要字段。

不要为了“统一”强制无用途的中间产物或输出字段。格式验证器只能证明形状符合要求，不能单独证明产物的用途。材料中未发现消费者时说明查证范围，不能断定不存在。

此处只判断表达和交付要求是否必要；具体接口、版本、运行状态和授权身份由实际使用结果的一方定义。

## 事实源、共置与剪枝

优先读取环境、配置、源码和帮助中已有的可变事实。需要立即理解的背景、选择理由、项目约定、关键陷阱或昂贵查询的稳定摘要可以保留；注明来源和适用范围，不把所有可查询知识一律删除。

同一概念的定义、规则与例外放在一个权威位置。区分重复含义与一个概念被拆散；相关内容的共置优先于按历史不断追加。

对多余内容优先删除、放宽或按条件迁移，再考虑重写或增加约束。新规则应对应真实失败、硬要求、领域知识或操作脆弱性。删除影响未知时标为待验证，不因为担心就永久保留，也不因追求短小删除必要保护。

## 相称验证与结论

改变读取路径或行为的调整，用一个代表性输入检查目标行为；边界有争议时增加一个最小对照。删除价值不确定的规则时比较保留与删除的版本。普通局部修词只需相应静态检查，不自动建设或运行整套 Eval。

报告区分：直接证实的问题、设计建议、未知项及实际验证。只做静态检查不能声称行为效果已验证；有限样例通过也不保证所有任务无回归。无需为了汇报这些信息再创建审计协议。
