# Agent 内容重构手法

改造已有指令、重组多文件、去空话或压减跳转链时读取。先定位具体病灶，再选对应手法，避免泛泛“润色一遍”。

## 1. 先沿真实路径诊断

选 1 条常见路径和 1 条确有不同读取需要的条件路径，逐跳核对入口、正文、指针与目标文件，记下：
- 读者在哪一步必须猜测业务语义、单位或边界；
- 哪段内容换到别的项目依然成立（空话/常识）；
- 哪些规则在多处重复粘贴，或拆得过碎导致常态任务要跳 4–5 次以上；
- 哪条刚性指令后面拖着削弱执行力的免责尾巴。

没有独立分支时不要人为制造分支。

## 2. 选择对应的重构手法

| 病灶 | 重构手法 | 具体动作 |
| --- | --- | --- |
| 抽象上位词堆砌、低要求完成标准、反复展开的短语 | **锐化去抽象（Sharpen）** | 拆成短句；把抽象属性改写为“红灯信号 → 具体动作/硬检验”，补强完成标准的清晰度与要求强度（demand）及 1 组高反差 Bad vs Good 对照；把多处重复展开的概念折叠为单个强引导词。目标不是变短，而是让行为发生偏移。 |
| 常识清单、反复粘贴的免责尾句、过时沉淀与起草残渣 | **剪枝去免责（Prune）** | 对 No-op 整句删除而非缩句；把权限/预算/只读等系统底线收束到唯一权威处；把模糊退路改成具体可判别的例外条件。 |
| 必读内容藏在外部、条件分支混在主线、同分支短文件串行多跳或与入口同义的空壳小文件 | **层级与跳数重组（Restructure）** | 必读规则前置回入口；独立分支外移并配清晰触发指针（解 Sprawl，防止参考埋掉步骤）；仅合并同分支/高共现短文件，空壳删去并入入口，正交低共现分支保持单文件防污染；长索引表补“0 跳可执行判据”；同层长参考加主题导航。 |
| 多份分支/Playbook 各自复读通用纪律，或同一概念散落多文件 | **上提与共置（Hoist & Co-locate）** | 共享纪律上提到唯一入口，子分支只保留独有步骤与反模式；同一概念的定义、规则与例外聚到一处并同步全部指针。 |

应对后续步骤诱发的**提前结束**时，先收紧当前步的完成判据；不要把“拆成两个文件”当成上下文隔离——在同一会话里打开另一个文件或内联调用不能清除已读的后续步骤。只有判据本质模糊且实测观察到抢跑，并且运行环境支持独立上下文（交接或子代理）时，才按序列拆分。

## 3. 保真核对与收尾

修改完成后，对照原始权威材料逐项核对：
1. **语义保真**：主体、条件、单位、顺序/并行、权限、约束强度、例外与真实消费者（含跨上下文交接材料与明确用户格式要求）完整保留。
2. **引用闭合**：所有实际消费者的指针已同步，已删除旧副本不再残留，没有示例性假路径或“……”占位省略。
3. **路径复走**：用第 1 步选定的两条路径走完新结构，核对实际读入、跳数和人的选择负担是否确有改善。

报告实际改动、保留的核心语义、减少的具体负担与未验证项。字符变少只说明体积变化，不能替代真实运行的效果证据。
