# Explain Clearly

将复杂需求、技术规格、系统架构、协议、代码机制或研究材料转化为人易理解、可查证的保真呈现。

## 适合使用

- 面对冗长或晦涩的需求文档、架构设计、状态机或协议，希望快速抓清全貌、正反示例、风险和待拍板点。
- 需要把官僚化、嵌套复杂的说明改写成清晰短句、条件表或结构图示。
- 需要制作一次性离线交互式 HTML 探索页（单步状态演练、What-If 条件对比、摘要联动原文）来彻底看懂复杂逻辑。
- 需要先预检工具链与成本，再制作带同步旁白字幕的定制讲解视频（如 3b1b 风格动画）。

## 工作方式与结果

- **先建心智模型，再看细节**：按“定框与状态 → 具象正反实例 → 全景主题与风险 → 精确定义与原文锚点”组织内容，并用 80% ASD-STE100 规则削减句法噪音。
- **按认知瓶颈升级媒介**：常规对话输出清晰文本与结构图/表；遇到多主题耦合或状态分支推演，在有路径/授权时生成单文件离线交互 HTML，无路径时先交付图文再提议升级；视频先预检环境与费用、确认后再渲染。
- **保真不洗白**：严格区分已确认事实、提案/待决项、未验证假设与资料缺口，不合并不同状态语义，不隐藏次要风险。

## 不适合使用

- 一句话术语解释或简单常识问答（直接回答即可）。
- 为尚未决定的产品界面或交互行为制作可体验的新产品候选原型。
- 只读追查源码机制或历史提交动机。
- 生产级网页或应用界面开发。
- 编写或重构给 Agent 读取的 `AGENTS.md`、Prompt 或参考文档。
- 对代码或规格做独立只读质量审查并出具问题清单。

## 边界

- 源文默认只读；仅在你明确要求直接改写原文可读性时才原位修改。
- 交互式 HTML 默认单文件离线、零外部网络、不启动本地反馈服务、不提供“批准/写回源文”动作；仅在你明确要求离线单页带批注导出时附极简本地导出面板。
- 定制视频制作前会先确认本机工具链、TTS 方案及潜在费用，不擅自调用付费 API 或安装重型全局依赖。
- 本地落盘产物不自动执行 `git add`、提交或推送。
