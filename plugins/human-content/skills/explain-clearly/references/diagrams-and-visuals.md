# 图示与视觉建模（L2）

需要将角色职责、状态流转、时序窗口、分支因果或数量权衡转化为可读图形或矩阵时读取。

## 1. 按关系选视觉形式

只画源文真实存在的结构，按读者需要辨认的关系选型：

| 读者要看懂的关系 | 首选形式 | 必须标出的保真要素 |
| --- | --- | --- |
| 状态与生命周期 | 状态图 / 流程图 | 触发条件、判定点、正常终态与失败/中止出口 |
| 多方交互与异步消息 | 时序图 | 同步返回 vs 异步排队、重试/超时与阶段边界 |
| 迁移、兼容与保留窗口 | 时间线 | 开始、并行过渡期、失效/停止点与明确回退条件 |
| 角色、权限与模块边界 | 分层架构图或责任表 | 谁拥有状态、谁可写入、谁负责失败处置 |
| 多维条件组合（>3 条件） | 条件决策表（优于复杂流程图） | 全部条件组合、对应行为与显式例外 |
| 方案权衡与数量阈值 | 对照矩阵或带标注标尺 | 收益、代价、成立前提、单位、阈值及证据范围 |

## 2. Mermaid vs 自定义内联 SVG

- **用 Mermaid**：纯对话或 Markdown 文档交付，且单图 ≤12 个节点、以标准流向/时序/状态为主。
- **用自定义内联 SVG**（尤其在 L3 HTML 中）：需要表达空间分层、多泳道嵌套、精细信息密度，或需要绑定点击高亮、悬停提示与单步演练控制。

## 3. 反垃圾图红灯（命中即修正）

| 可观察红灯 | 立刻执行的修正动作 |
| --- | --- |
| 单图超过 ~12–15 个节点，或连线交叉成乱麻 | 拆为 1 张 5–7 块的总览地图 + 若干聚焦局部子图，绝不硬塞一图 |
| 图示只是把正文要点逐条套进方框，无结构信息增量 | 删掉装饰图，改画隐藏在文字里的因果箭头、状态跃迁或责任边界 |
| Mermaid 中文标签含括号、冒号、斜杠等特殊字符 | 节点与边标签统一加双引号（如 `A["节点 (说明)"]`），避免节点内嵌 HTML 标签，输出前复查箭头与 `subgraph` 闭合 |
| 箭头暗含源文未承诺的并发、自动重试或隐式权限 | 在关键边上写明触发事件与前提；串行阶段绝不画成并行分叉 |
| 仅靠颜色区分状态或风险 | 用有限语义色区分 `已确认 / 待决定 / 风险或失败 / 缺口`，并始终附带文字标签，不依赖纯色传达含义 |

每张图配一句简短图注，写清覆盖范围与概括边界（例如“仅覆盖正常路径与超时失败出口，不含跨重启恢复”）。
