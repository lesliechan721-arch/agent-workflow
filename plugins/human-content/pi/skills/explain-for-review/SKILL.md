# Explain for Review

将已有材料转成读者能理解和查证的呈现。内容定义与决定来源保持原有归属；不发现并裁定整套需求，也不制作新的产品行为候选。

## 建立阅读路径

1. 确定读者现在要理解或判断什么，读取相应完整来源及其状态。区分来源声称、实际确认、提案、假设与验证证据；缺少材料时说明缺口，不补造结论。
2. 默认用清楚的文字、一个场景或小表格。关系／先后适合图示；长材料需要跳转、展开或局部反馈时使用 HTML，并读取 交互阅读（`references/interactive-reading.md`）。复杂组织或表达不清时使用 保真呈现（`references/faithful-presentation.md`）。用户明确的格式优先，工具、隐私和成本依当前授权。
3. 先呈现本次问题、材料后果和关键场景，再展开精确定义。多个主题分别提供入口，不让最醒目的一个问题遮住其余待决定项；重要取舍、风险、条件和未验证前提可见，完整材料有明确入口。每个图示的范围与概括性质清楚，举例不伪装成实际测量或运行证据。
4. 对照来源核对术语、值与单位、条件／例外、约束强度及确认状态。解释可以换形式，来源未决定的内容仍未决定；发现真实冲突时返回该问题，不以排版消解。

## 交付

提供实际可用的呈现与来源标识，说明范围和未验证项。文件写入采用当前给定位置；仅需当前对话解释时不建工件。源文默认只读；如另有内容修订请求，明确区分修订与展示。

反馈保留对应版本和具体位置，交给当前用户或调用者使用。反馈提出新行为、缺少的决定或体验验证需要时，返回具体问题，不在解释视图中替来源定案。阅读、标注和下载不构成批准或实施授权。来源改变时重新生成或明确旧视图已过时；文件不能访问新来源时只说明快照范围，不声称自动检测最新状态。
