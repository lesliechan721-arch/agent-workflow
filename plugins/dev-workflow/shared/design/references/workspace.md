# 工作位置与轮次归属

仅在首次决定保存位置、建立实施记录或替换旧交付依据时读取；已有明确路径直接沿用，短任务可在对话闭合。

## 位置选择顺序

1. 用户或调用者显式指定的位置；
2. 当前任务目录或仓库既有约定（已有 tracker/work 目录直接沿用，不搬迁）；
3. 默认 `.dev-workflows/<task>/`，仅按实际消费者创建所需项：
   - `<task>/design.md`、`<task>/spec.md`（及可选 `<task>/spec-history/`）：设计依据、保存规格与旧版依据；
   - `<task>/prototypes/`、`<task>/reviews/`、`<task>/evidence/`：原型及接受记录、审查记录、运行证据；
   - `<task>/decisions.tsv`：长任务或 Hillclimb 追加式决策日志（默认 gitignore，仅在审计需要时提交）；
   - `<task>/builds/<round>/work.md`：多轮实施的范围、代码基线与恢复入口；
   - `<task>/tmp/`：可重建临时产物。

## 轮次与写入归属

- 中断恢复、本轮修复补验与获准调整沿用**原轮次**；前轮已交付结束后获新授权才按需开下一轮；独立目标另建任务。
- 替换当前设计或规格前，确认旧交付对应的请求、设计依据与接受原型版本仍可按原版取回。
- 协调者指定具体路径与写入归属并传给下游，子代理不自行另开轮次或争写共享索引；本地过程资料不默认 `git add`、提交或推送。
