# 中断与不确定状态恢复

仅在会话中断、交接接手、外部操作回执缺失、工作区出现未核对变动或写入归属不明时读取。任务耗时长本身不需要进入恢复。

## 1. 先停新分派，再只读核实现场

1. 暂停受影响的新子代理分派。
2. 先读已有记录或轨迹（目标、有效依据版本、已用预算、未决副作用、写入归属），再**只读核对真实工作区**（`git status`/`git diff`、产物文件、活跃进程与外部状态）。记录只是线索，现场可能已有用户手动修改或仍在运行的写入者。
3. 单个外部子代理 run 沿 `spawn-subagent` 的原句柄核对与恢复，不另造生命周期协议。

## 2. 严守副作用与写入安全

- 回执或外部副作用状态不明时，**先只读确认已发生、部分发生、仍在跑还是未发生**，绝不盲目重发有副作用的操作。
- 严禁盲目 `git reset`、清空目录或按进程名强杀；只清理确认归属本次且不再需要的资源，保留原始证据。
- 同一写入范围必须在原执行者安全结束或确认采纳新依据后才可重派；无法确认时先隔离受影响范围，无冲突工作可继续。

## 3. 继承已有成果，不重头返工

已核对仍有效的前序成果直接复用，**抵抗“干脆从头再验证/重做一遍”的冲动**；仅重开受变化或失败影响的部分，沿用原比较基线与原累计预算（换会话或执行者不重置额度）。
