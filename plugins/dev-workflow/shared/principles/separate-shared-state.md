# Separate Shared State（先消除共享再谈锁）

当多个并发执行者可能写同一文件、分支、键或状态对象时，先问它们是否真需要共享同一可变对象，还是各自发布独立事实：
- **默认拆目标**：给每个执行者独立文件、独立键空间、独立目录或独立 git worktree，只在读取汇总处合并。**两个 worker 各自改同一个 `state.json` 的不同字段仍是共享可变状态**，同样会产生覆盖竞态。
- **仅在共享目标是真实不变量时才结构串行**：采用锁文件、单写者、顺序阶段或 CAS。**文字约定（“你改 A 字段我改 B 字段”）不是并发控制**；一想到“我们需要加把锁”，先检查是不是共享本身设计错了。
