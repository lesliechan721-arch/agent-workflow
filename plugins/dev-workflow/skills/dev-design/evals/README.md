# Dev Design Eval

本目录评价独立手动设计入口的调用边界、真实用户对齐、可实施设计、按需保存和停止纪律。设计结果不等于授权产品实施。

| Suite | 评价目标 |
| --- | --- |
| `trigger` | 用户显式选择才调用；完整任务意图或上游委派不自动启动手动入口 |
| `conversation` | 未定产品行为以实际用户回答为依据；已有充分设计直接复用，不强制新增文件 |
| `task-spec-lifecycle` | 跨会话完整本地规格、明确授权的公共合同更新、只适用于本任务的范围 |
| `simplified-design` | 轻量设计不造记录、草稿中保留未决事项、明确正式规格请求、已授权的累计预算耗尽与剩余修订 |
| `visible-alignment` | 主动发现和消费决策、明确请求不重复提问、事实变化重开受影响选择、同一草稿有无真实用户来源的对照 |
| `alignment-handoff` | 原始有效要求优先于摘要，保持约束强度、例外及实施自由 |

## 运行与判据

`project-default` 使用 Codex project profile 及被测插件的实际依赖闭包；常规子代理基线为宿主原生。各 suite 的 `strict` 参与列表只说明当前可用能力，不要求固定加载或角色组合。

Conversation 使用内置 provider。只读或因未决事项停止时，使用可写环境与空允许列表；实际工具轨迹与最终文件共同提供证据。写入用例声明用户已授权的位置、允许路径和 artifact；实际正文必须覆盖来源，不以存在性、文件数或模板标题代替完成。明确来源中未决的选择不能被完整候选或助手的批准标记替代。

已有设计复用用例保留未实施的产品代码与面向新规范的测试。其租户范围与空选择测试在初始 fixture 上预期失败；这是设计与实施边界的前提，不能为取得绿灯擅自修代码。

预算场景中的上限来自 fixture 中明确的用户授权，不是工作流默认的修订轮数。旧审查记录仅构造当前任务前提，不能证明本轮实际发生独立审查；真实审查只以本次运行证据为准。

以上为作者定义的待评测用例，不是已通过的运行或独立 EvalAudit。正式执行前重新 prepare 并取得独立审核；修改用例后不能将旧评测结果视作现行证据。
