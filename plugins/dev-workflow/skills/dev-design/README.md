# 设计阶段

协调需求对齐、规格编写与独立审查，形成有依据的当前设计；独立调用在设计边界结束。`decision-shape` 负责整体需求覆盖、问答、原型和知识维护，Design 负责把其完整结果交给规格与审阅环节。

材料取舍先获得实际答复，再细化依赖它的完整规范。已有充分且仍有效的要求直接复用；小任务可在当前上下文完成，不强制文件。正式规格通过 `dev-spec` 保留原始要求、确认条件、接受原型和知识依据，再由 `dev-review-spec` 独立检查并取得适用确认。资料沿现有本地目录，明确指定的公共合同原位维护。

复杂取舍或长稿可使用 `explain-for-review` 提供保真的阅读与反馈入口。新增需求或接受设计变化只交回 Shape 处理受影响部分，不重开全部对齐。源资料、审查和批准分别有依据；设计认可不自动授权实施、提交或推送。执行方法见 [SKILL.md](SKILL.md)。
