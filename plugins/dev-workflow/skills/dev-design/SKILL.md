# Dev Design

形成有依据的当前设计，不启动产品实施。读取用户请求、相关项目事实与有效确认；目标、范围、验收或风险仍有材料选择时使用 `decision-shape`，已有充分共识直接复用。

## 选择足够的交付

| 当前需要 | 设计结果 |
| --- | --- |
| 必要对齐、边界与验收能留在有效上下文，没有持久批准或交接需要 | 在对话中明确当前结果与实施自由；无需单独创建 Spec 或流程文件 |
| 多决定、长原型、正式规格或跨上下文实施 | 使用 `dev-spec` 形成完整规格与可达附件，再以 `dev-review-spec` 独立核对并取得适用确认 |

规模不免除实际风险、权限或恢复要求。需要落盘或转交原型前读取 [工作目录](references/local-workspace.md)，沿用当前位置。普通任务规格留在本地；明确指定的公共合同在其位置维护。

## 设计与恢复

- 新领域术语、非显然的重要决定需要长期维护时，使用 `project-context`；普通任务行为由当前规格及适用合同承载。
- 长对齐或原型前，在已授权的 Spec 草稿或相应原型 brief/verdict 中保存已确认内容、来源及开放问题。草稿可恢复但不表示批准；最终综合和确认前核对全部条件、例外、设计与精确约束。
- 已有实质规格问题且修订在授权内时，读取 [规格修订](references/review-repair.md)。预算归当前设计协调者，独立审查者只提供判断。
- 向用户呈现需其判断的完整结果、风险和实质变化；采用实际答复或明确委托。已经确认的同一含义直接复用，新增材料解释再核对。正式规格的必要独立审查与批准分别成立。

交付当前设计及可访问位置、确认范围、开放问题和下一步。仅设计请求到此结束；外层已有实施授权可接续 Build。设计尚需后续实施时，完整本地规格和必要接受证据持续保留。

新证据只重开受影响主题；更新相关资料后交回调用者，已有预算与停止点保持。取消或改向按实际授权处理本次不再有效的项目文件变更，保护无关工作；提交、推送和资料清理分别需要授权。
