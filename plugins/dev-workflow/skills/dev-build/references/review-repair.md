# 有界自适应 Review 修复

仅在已有 blocked 正式 Code Review 且自动修复获准时读取，适用于当前明确的阶段或最终审查范围。

## 授权与预算

遵循用户授权及适用项目/运行时上限。新授权未指定次数时，默认最多三轮；这是上限，不是必须完成的轮数。已有一次授权、提前停止决定或更低上限继续有效，不能用新默认值扩大。需要更高预算时取得新授权。开始时简短说明本次适用范围和预算。

一轮是一批有界修复、相关与集成验证、以及当前完整范围的 fresh 复审。该批首次产品修改即占用一轮；多个 worker 共享该轮，验证失败或复审 incomplete 不退还次数。初审、只读诊断和补充审查不计为修复轮，但仍受当前任务时间、成本和权限限制；条件未改善时不重复重试。

## 修复与续行

1. 核对 blocker 的证据、材料影响和可验证关闭条件。只修当前 blocker、必要影响面和直接回归；关闭条件约束结果，不强迫采用 reviewer 指定的更大方案。争议先提交依据给 reviewer 澄清，不静默删除有效问题。
2. 组织必要工作项，检查实际 diff、相关测试和集成结果，再让独立 reviewer 检查当前完整审查范围，而不是只确认旧 finding 已改动。
3. 预算尚有余量时，说明上一轮实际解决了什么、还剩什么真实问题，以及下一步的新依据。剩余问题明确、修复可行且仍在范围内时继续；仅因还没有 clean 或 blocker 数量下降，不足以续修。
4. 同一问题反复且无新诊断依据、修复显著恶化结果、出现方案往返，或需要改变 Spec、材料决定、权限与风险边界时，提前暂停受影响修改。可在现有授权内做有目标的诊断；不能自行解除需用户决定的暂停。
5. incomplete 时补足真实审查条件，不盲目修改代码。高风险但覆盖不足时，针对明确缺口补验证或独立审查；不无目的增加 reviewer，不以另一份 clean 覆盖尚未合理关闭的有效 blocker。
6. 所需验证充分且当前完整范围 Review clean 时结束，不为用满预算继续完善。耗尽预算仍有 blocker 或证据缺口时暂停；不弱化测试、验收或 Review 标准以取得 clean。

## 恢复与范围

当前协调者在上下文或已有 work/issue 中保留授权范围、已用预算、实际结果和继续/暂停的依据；只有恢复需要时持久化，不创建专用 ledger。worker、报告、commit、Skill 重入、会话恢复或临时重命名 milestone 不刷新预算；无法确认剩余额度时先恢复事实或询问用户。

预算对应实际获授权的审查范围。真正不同的 milestone 或最终范围可按已有授权分别处理；不得拆分同一失败以续修。阶段 blocker 暂停相关依赖，独立工作只能在原授权与安全范围内继续。

这里是 agent 的操作约束，不是运行时强制计数保证。需要不可突破的次数或成本限制时使用已有运行时，不靠增加 Skill 文本替代。
