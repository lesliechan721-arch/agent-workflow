# Checkpoint 与历史

当前集成结果有恢复、比较或审计价值，或用户要求整理历史时读取。协调者主动判断价值并提出下一步。

## 保存点与授权

本地提交需要用户或适用项目政策授权。尚未获得时，说明拟保存范围、验证状态和用途，并请求本任务范围的授权；获得后在连贯的已验证集成边界使用现有 Git 能力。

精确提交本任务修改，遵循 hooks 与已有 Git 状态。checkpoint 证明版本被保存，独立审查和数据备份分别证明其它条件。用户明确保存 WIP 时记录未验证/失败状态。

记录实际返回的 commit 和验证/Review 位置即可。未授权的已有改动保持原样；push、squash、rebase、force push、分支删除和用户文件回滚需要各自适用授权。

## 最终历史

默认追加提交。用户/项目要求整理时，优先在最终验证和 Review 前完成，也可采用平台已有 squash merge 流程。

历史变更后核对文件内容、当前 Spec、设计依据和目标基线。仅提交身份变化且审查上下文可证明一致时更新引用并执行政策要求的检查；实际内容或集成影响变化时重新验证并审查相关范围。无法证明一致时保守复核。

有长期审计要求时，按组织政策保存明确引用或外部记录。Git 版本历史、生产回滚、数据备份和外部审批分别承担各自职责。
