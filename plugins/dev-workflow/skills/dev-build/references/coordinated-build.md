# 协调实施

仅在工作需要多个实现上下文、持续进度或已获准委派时读取。

- 使用已有 issue/work；没有且确实需要分解时使用 dev-breakdown。只维护一份当前工作记录。
- 默认顺序执行已就绪工作项。fresh worker 的价值首先是隔离上下文；独立、写入与验证环境不冲突且集成成本合理时才并行。
- 委派前确认权限与当前工具能力。提供目标、范围、验收和可访问的上下文指针；不让 worker 根据父会话不存在的记忆猜测。worker 使用 dev-implement 完成当前任务，不接管全局流程。
- 不强制 worktree、分支或 merger agent。遵守已有隔离和 Git 策略；无法安全隔离并发写入或验证服务时串行。只有客户端实际支持且已授权才委派。
- 用平台 agent 工具取得真实结果与终态；暂停等待不等于失败。恢复时先确认旧 worker 的实际状态，不重复派发可能仍在执行的修改。
- 当前协调者接纳实际 diff、运行集成验证并更新共享进度。worker 只交付自己的修改和证据。存在两个协调者时先明确接管者；Markdown 不是并发锁。
- 依赖以已集成、已验证且通过所需阶段审查的结果为准，不以 worker 的“完成”自述为准。
- 调整切片顺序和局部安排不重批 Spec；新增材料行为、成本、风险或范围则停止并说明。

大型共同接口改动可以先稳定一个基础，再顺序迁移；不为了增加并发而虚构独立性。结束时报告实际集成结果和未解决问题，不承诺尚在运行的 worker 已经交付。
