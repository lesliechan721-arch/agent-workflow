# 实施协调

用户手动选择 `$dev-build`，将明确请求、问题清单、工作项或规格组织成实现交付。没有 Spec 文件也可工作，但预期结果、范围和验收需要有有效依据。Build 负责本轮范围、真实依赖、集成与交付；采用共享核验方法取得当前证据，不需要再启动另一个手动宏。

多上下文实施前核对任务、真实依赖、共享接口与验收；不足时由 dev-breakdown 补足，单个连贯任务不强拆。需要持久协调时按轮次保存本地 Work，普通短修改不强制创建文件。

同一任务支持多次 Build。中断恢复和本轮修复继续原轮次；前轮交付后再次实施时开始下一轮，只安排当前差异。任务规格保留当前完整要求，已结束轮次的依据与结果仍可找回，不因更新规格而改写历史。旧目录直接沿用，不自动搬迁。

实现不符合有效要求时按授权修复；需要改变产品取舍时暂停受影响工作，返回完成现状、缺口和影响，不自行启动设计。新轮次不自动增加修复额度。

不设置 checkpoint 提交阶段。提交、推送和清理分别依适用授权；独立核验不依赖是否创建 commit。完整方法见 [SKILL.md](SKILL.md)。
