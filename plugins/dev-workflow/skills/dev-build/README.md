# 实施协调

依据明确请求或当前规格准备任务、实施与集成。Build 负责整体范围、真实依赖及交付；将 milestone 或最终范围的核验交给 dev-review-loop，并依据其实际证据推进，不重复运行同一审查修复循环。

多上下文实施前必须有可独立接手的任务、真实依赖、共享接口与验收；已有任务不充分时先由 dev-breakdown 补足，单个连贯任务不强拆。需要持续协调时按需使用本地 work.md，普通短修改不强制记录文件。

实现不符合有效要求时按授权修复；需要改变产品取舍时暂停受影响工作，返回完成现状、缺口和影响，不自行启动新设计。已完成／中止任务的规格与结果保留为历史，后续变更引用它们而不覆盖。

不设置 checkpoint 提交阶段。提交、推送和清理分别依适用授权；独立核验不依赖是否创建 commit。完整方法见 [SKILL.md](SKILL.md)。
