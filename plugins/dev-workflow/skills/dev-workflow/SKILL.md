# Dev Workflow

```text
当前请求与有效成果 → dev-design →〔实施已授权〕→ dev-build → 交付
                         ↑              │
                         └── 获准修订 ──┘
```

1. 明确本次目标、范围和已有确认。使用 `dev-design` 完成设计，已有充分有效的设计结果直接复用；只请求设计时在其交付后结束。
2. 目标明确且实施已获授权时，使用 `dev-build`。沿用当前依据、资料位置、原始范围及限制；设计认可本身不新增实施权限。
3. Build 返回材料缺口时，采用其完成现状、依据与影响；核对已有设计授权，获准后交给 `dev-design`，否则交付缺口等待决定。取得有效结果并同步任务与执行者后继续；独立部分可按原授权推进。
4. 采用 Build 已取得的当前核验结果。恢复时保留原始基线、未关闭问题、累计修复预算和用户停止点；外部交付依实际授权处理。
