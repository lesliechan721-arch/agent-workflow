# Dev Workflow

负责当前请求的阶段选择、跨阶段变化和用户检查点。设计、实施及核验的完整方法由本包共享资料维护，不调用其他手动宏。

1. 核对目标、已有成果、实际确认与授权。设计尚不充分时采用 设计协调（`references/methods/design.md`），完整有效的设计直接复用；仅设计请求在其交付后结束。
2. 目标充分且实施已授权时采用 实施协调与交付（`references/methods/build.md`）。沿用当前任务、依据和位置；设计认可本身不新增实施权限。
3. 实施返回缺口时，采用完成现状、原依据与影响；只在已有授权涵盖设计时重开受影响主题，否则交付缺口等待决定。取得有效结果并同步相关任务与执行者后继续，独立部分可按原授权推进。
4. 采用 Build 已取得的当前核验结果，不重放核验循环。恢复保留原始范围、未关闭问题、累计预算和用户停止点；外部交付依实际授权处理。
