# Dev TDD

在具备廉价稳定本地测试路径或用户明确要求 TDD/回归锁定时，执行先红后绿的测试驱动节奏，并用两条假想修改检验过滤“改坏行为仍绿”或“改实现就挂”的低价值测试。

## 适合使用

- 新增、修改或评估自动化单测、组件测与轻量集成测。
- 用户明确要求先写失败回归测试再修复缺陷，或审计既有测试是否锁死内部实现。

## 示例请求

```text
使用 $dev-tdd 为这个重试重复扣款问题补一条最小失败回归测试并验证真红灯，再修复验证。
```

## 工作方式与边界

- **工作方式**：先判断是否值得新增测试（重型 harness 或脆弱内部 mock 场景宁跳不造烂测试，换用最近可执行复现）；确需新增时先跑出目标缺陷导致的真红灯，最小修复变绿，并过行为敏感性双检。
- **不适合使用**：普通未知故障定位改用 `dev-debug`；纯文档或文案微调无需强行补单测。
- **权限与副作用**：会编辑测试与相关修复代码并运行项目测试命令；严禁放宽既有有效断言换取绿灯。
