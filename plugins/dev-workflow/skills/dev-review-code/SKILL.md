# Dev Review Code

审查当前变更及其实际依据。正式双轴结论来自两个独立审查上下文，审查本身不授予修改或后续操作权限。

## 当前职责

- **组织完整审查**：先核对本轮已安排的 reviewer 与范围，只补足尚缺的独立判断。当前参与过目标设计、实施、修复或继承作者工作历史时，委派两个独立上下文子代理 reviewer 分轴。当前自身独立时，可以先承担一轴、再汇总另一独立上下文，也可仅协调两名 reviewer；采用前者时先形成自己的判断再读取对方结论。
- **执行已分配的审查轴**：直接按该轴方法读取资料、查证并报告；其它轴及整体结论由组织者汇总。发现职责外的重要风险可以提示，但不据此重建完整审查。

独立性由参与历史和上下文决定。必要产品资料与旧 finding 继续可读，作者的自证和预设结论仅作待核验线索。已分配 reviewer 的隔离不足时向组织者说明；缺少另一独立轴时如实限定整体覆盖。

## 固定范围与来源

1. 明确基线、当前版本、请求覆盖的工作及验收。按实际范围包含相关已提交、暂存、未暂存和未跟踪内容；不能从材料确定且会影响结论时先询问。
2. 读取原始需求、Spec/issue、有效决定和评论、项目规范、已接受设计及真实代码。追踪到原型、图像、接口或样例本体；冲突、缺失和来源权威不明处应说明。
3. 区分当前应交付内容、上下游相关影响和当前范围外内容。组织者向本轮各轴 reviewer 提供固定目标、明确分工、必要可访问依据及验证条件；已受委派者在当前上下文读取并执行，两个轴可并行或顺序完成。

## 双轴实证审查

当前 reviewer 执行所分配的轴；完整审查由组织者确认两轴都有独立证据。

- **需求与设计符合度**：按当前材料要求核对预期与实际，寻找遗漏、未批准偏离、scope creep 和验收缺口。涉及 UI、交互、图像或原型依据时读取 [设计与界面对照](references/design-fidelity.md)，直接检查实现与被接受的设计。
- **工程质量与项目标准**：读取变更及必要调用链，检查正确性、安全、故障与并发、数据和兼容边界、维护性、测试价值及当前项目规则。代码结构迹象用于定位风险，finding 应说明实际影响。

一次报告当前证据支持的实质问题，每项说明证据/位置、材料影响和可验证关闭条件。等价且更小的修复方式可满足关闭条件；改进偏好与缺乏当前依据的扩展建议单独呈现。

## 汇总与交付

已有报告或明确复审时，读取 [复审](references/rereview.md)。单轴 reviewer 返回该轴证据、问题和限制；组织者汇总两轴，各自判断保持可辨，同一问题可交叉引用；有争议的有效问题依据事实解决。

使用 [报告模板](assets/code-review-template.md) 中对应本次范围的部分组织人读结果。区分直接观察、实际运行、已有记录与未验证内容；确定的问题和证据不足可以同时存在。缺少规范依据时仍可做工程审查，需求符合度相应保留判断。

核对审查结束时目标是否仍一致。缺少必需独立上下文或实际验证能力时说明未完成的覆盖，已发现问题继续报告。默认只在对话中交付；明确要求保存时采用给定位置或确认的项目约定。被审源码、测试、需求和工作状态保持原样，后续行动由用户或调用者决定。
