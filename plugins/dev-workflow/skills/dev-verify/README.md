# Dev Verify

在真实运行表面（CLI、API、UI、存储、异步任务或 `--dry-run`）核验项目改动是否兑现承诺，拦截“能编译”“端口在听”等代理指标伪通过，并清晰归因产品缺陷、入口错误或环境阻塞。

## 适合使用

- 实现完成后需要按真实用户触达的表面拿原始运行证据验收。
- 需要对照已接受的界面/交互原型或已有形式化模型做运行核验。

## 示例请求

```text
使用 $dev-verify 运行真实导出命令验证 60k 行场景与取消清理，贴出原始输出。
```

## 工作方式与边界

- **工作方式**：核对启动的是本次修改后的真实实例，按变更类型操作真实表面并记录命令与原始输出；失败时保留现场并区分产品缺陷、验证驱动问题或环境前提缺失，逐条承诺标明 `通过 / 失败 / 阻塞 / 证据不足 / 未运行`。
- **不适合使用**：审查代码质量、设计或找隐蔽 bug 改用 `dev-review`；核验性能数字改用 `dev-benchmark`；创建或重建整套项目验证资产改用手动 `$dev-verify-author`。
- **权限与副作用**：会执行项目构建、启动命令与真实接口/UI/存储检查，仅清理本次自建进程与临时数据并保留证据；不会越权建设整套项目验证基础设施。

详细执行说明见 [SKILL.md](SKILL.md)。
