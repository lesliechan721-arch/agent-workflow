# Dev Review Spec

正式审查需要一个独立判断。审查结论描述文档质量，用户批准和后续执行由调用者负责。

## 当前角色与独立性

当前未参与目标的实质设计、起草或修订，且未继承作者工作历史与预设结论时，直接执行审查。原始需求、已确认决定、原型、代码、测试和旧 finding 是判断依据，正常保留。

当前带有作者工作历史时，由组织者委派不继承作者工作历史的独立审查子代理。已受委派的审查子代理按本次范围直接审查；若发现自身不满足隔离要求，说明限制并交回组织者处理。角色不确定时先核对实际任务和上下文。

本 Skill 的方法供实际审查者使用，组织者负责尚缺的隔离与最终交接；已满足本轮独立性时直接使用该执行者。

## 审查

1. 固定本次被修改规范的范围与版本，读取原始请求、有效决定、相关原型接受说明和适用项目契约，包括相关未修改约束。核对重要行为与选择确有用户要求、确认或明确委托支持，模型提案在确认前仍是提案。既检查文档引用，也检查本次任务已提供但可能遗漏的来源。
2. 当前独立审查者读取完整规范入口、被纳入的附件与必要来源；委派时提供相同资料和明确职责。检查来源覆盖、条件与例外、精确值和约束强度、内部一致性、重要技术决定、可实施性、验收与自主空间。附件中的规范与正文同样有效。
3. 已接受原型具有明确约束时，核对版本、页面/状态、保留要求、允许偏差和演示边界。只有笼统引用且会使不同实施者形成材料性分叉时，说明具体缺失。
4. 同时检查用户审阅路径是否暴露全部材料变化、取舍和风险，以及规范是否引入无来源约束或重复定义。每个实质问题给出来源/位置、具体错误结果或审阅遗漏、影响和关闭条件；必要细节不因篇幅而删除，可接受的局部自由不强制提前确定。
5. 当前任务规格可以完整保存在本地，也可以引用适用的现有公共合同。先区分活动任务依据与最终长期资料：活动期间重点核对完整性和真实可达性；长期资料不能在本地任务删除后失去唯一必要定义或设计。目标可先于实现成立，声称已经支持或验证的事实则需有证据。审查者无法完成、必要来源缺失或审查时目标变化时，说明受限范围，仍保留已经确定的问题。结束前核对目标，保持审查者的实质判断。

已有上一份审查或明确复审时读取 [规格复审](references/rereview.md)。首次审查直接使用本页方法。

## 报告

使用 [规格审查模板](assets/spec-review-template.md)。分别说明语义保真、人审完整性、可实施性与证据缺口；修订比较突出实际含义的变化，组织偏好和长度本身不构成 blocker。已有测试或实现声明不替代规格依据。

默认在对话中报告，明确要求保存时采用给定位置或确认的项目约定。保持被审文档和实现不变；报告不会自行批准规格或启动修订。
