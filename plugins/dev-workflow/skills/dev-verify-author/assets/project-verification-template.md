# 项目验证入口

初始状态为待核验。按实际项目填写本模板，删除不适用章节；只有真实运行后才记录相应通过结果。

## 目标与约束

| 内容 | 记录 |
| --- | --- |
| 目标行为或属性与依据 | 用户场景、预期结果、形式化属性、需求或合同来源 |
| 对象 | 提交/构建/未提交差异标识、实例或模型版本与环境 |
| 代表负载 | 输入、数据来源、规模、必要种子 |
| 操作边界 | 已有读写授权、外部操作及允许数据 |
| 未覆盖 | 当前不证明的场景、平台和条件 |
| 有限执行 | 多轮执行的累计事项、计数口径、已用/剩余及停止条件 |

## 环境与执行前提

写出可执行准备和启动命令，包括工作目录、运行时与依赖、必要参数、配置获取方式、超时和完成信号。记录进程、端口、账号、临时目录的归属确认与隔离方式；秘密值不写入本文。

运行验证启动后确认目标实例与就绪信号；纯模型检查记录检查器及其输入，不要求启动无关产品。若资源已存在，先识别所有者，不直接终止未知进程或覆盖已有数据。说明准备或启动失败如何保留证据并清理。

## 条件分支：运行验证

| 场景 | 前提与实际操作 | 观察点 | 通过依据 | 失败证据 |
| --- | --- | --- | --- | --- |
| 填入具体目标场景 | 命令、请求或可定位界面操作；含完成信号 | 输出、状态或产物位置 | 可直接比较的预期与来源 | 原始日志、响应、截图或文件 |

就绪仅证明可以开始操作；异步工作要观察真正完成。需要时用安全可撤销的已知失败条件确认观察点有效，并说明其未覆盖范围。

## 条件分支：形式化验证

有明确属性且模型与工具适用时，按 [形式化验证方法](../references/formal-verification.md) 填写本节；其他任务省略。

| 内容 | 记录 |
| --- | --- |
| 属性 | 精确表述、来源、例外与适用对象 |
| 模型与实现 | 模型版本、初始条件、状态/转换及实现对应；抽象和省略 |
| 假设与边界 | 环境假设、输入范围、搜索深度或状态范围；目标路径可达性 |
| 工具与执行 | 工具版本、配置、实际命令、超时/资源限制和终止状态 |
| 反例 | 原始轨迹、复现方式、模型/假设/实现的归因状态 |
| 结论 | 模型和检查范围内的判定、未完成部分及实现覆盖依据 |

分别记录入口是否可靠运行与目标属性是否成立。有界范围未发现反例不等于无界正确；超时或搜索未完成不算通过。模型结论不替代尚未执行的产品运行验证。

## 条件分支：测量

涉及性能或数值时，记录正确性与误差约束、计时边界、冷/热条件、预热、样本和停止口径、对照顺序、反失真检查、单位及统计汇总。原始值与机制解释分别保留；不可比或噪声过大时不给确定收益结论。

## 单次证据

| 字段 | 必须能恢复的事实 |
| --- | --- |
| 时间与运行标识 | 原始执行时间及可定位标识 |
| 对象和负载 | 确切版本、实例、输入与规模 |
| 操作和环境 | 实际命令/操作、目录、依赖和相关条件 |
| 预期与观察 | 执行前标准、实际事实、原始证据位置 |
| 判定和覆盖 | 通过/失败/阻塞/证据不足/未运行；分别记录入口可用性、目标判定与实现覆盖 |
| 复用 | 原证据时间和前提一致性的理由 |
| 成本和清理 | 本次及累计成本，自有资源回收和遗留原因 |

## 失败与维护

区分产品违约、模型或假设错误、驱动故障、环境阻塞、文档漂移和原因未定。反例先核对模型与实现关系，保留第一次失败。验证资产维护走 `dev-verify-author`；产品修复另按范围处理。不得删检查或降低预期消除失败。

## 清理与恢复

列出只作用于本次自有资源的清理步骤、归属检查、完成观察与证据保留方式。中断后先确认资源现状、已发生副作用、当前版本和已用预算，不直接重跑全部操作。记录未清理对象、原因及影响。

## 有效范围

记录最近一次适用方法的真实代表闭环：运行验证的准备—启动—操作—观察—清理，或模型检查的输入准备—检查器执行—结果/反例解释—资源清理。列明已覆盖条件、可能使证据失效的变化和最小重跑影响面。分别说明结构检查、模型属性、实际项目运行与目标宿主调用；缺少相应证据时保持未验证状态。

## 功能地图与属性维护

多功能运行入口使用 [功能地图模板](feature-map-template.md) 保留场景与覆盖。需要属性模型时使用 [形式化模板](formal-verification-template.md)，记录实现映射、原子边界、可达性、受控负例、基线恢复与同步版本。只改模型的负例不能证明实现检测覆盖；阻塞或未完成的检查不推进同步基准。
