# Dev Correct

显式启动的仓库防呆硬化入口：梳理项目里反复出现的错误或人工纠正，按最高有效层级把教训固化进仓库结构，让后续只看局部文件的 Agent 无法重犯。

## 适合使用

- 近期代码评审、回滚记录或人工纠偏中，同类错误已经重复出现 ≥2 次。
- 希望把口头约定升级为架构约束、类型/Lint/CI 拦截或行为回归测试。

## 怎样调用

本 Skill 仅支持用户显式调用（如 `$dev-correct`），不会在普通对话中自动触发。

```text
使用 $dev-correct 梳理本仓库近期反复出现的错误类型，并按架构/类型/Lint/测试最高有效层级固化防线。
```

## 工作方式与边界

- **工作方式**：从提交历史、评审意见与注释归纳重复错误类，按“架构消除 → 类型/Lint/CI → 行为测试 → 文档规则”依次选取最高有效防线，并用真实历史坏样本亲验拦截效果。
- **不适合使用**：只发生过一次的偶发故障，或尚在定位原因的单次 bug（改用 `dev-debug`）。
- **权限与副作用**：会修改仓库类型、检查配置、测试或 Agent 规则文档并运行本地校验命令；删除已由机械手段拦截的冗余文字规则。

详细执行说明见 [SKILL.md](SKILL.md)。
