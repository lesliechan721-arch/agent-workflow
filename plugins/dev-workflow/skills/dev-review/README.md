# Dev Review

统一的代码改动、PR、架构设计、实施计划与变更影响面（Blast Radius）只读审查入口：按 5 档证据阶梯报告有实据的问题、过滤风格噪声；命中高危可运行边界或显式压测请求时自动升级多代理隔离实测破防。

## 适合使用

- 审查分支 diff、PR、关键重构或架构/实施设计是否存在需求遗漏、隐蔽影响面或安全前提漏洞。
- 需要针对并发、锁、鉴权、持久格式等可运行高危变更做零噪声对抗实测压测。

## 示例请求

```text
使用 $dev-review 审查当前分支相对 main 的改动与隐蔽影响面。
使用 $dev-review 审查这份迁移设计是否有需求遗漏和状态机死角。
使用 $dev-review 只做对抗压测，尝试用运行反例打穿这段并发队列实现。
```

## 工作方式与边界

- **工作方式**：先核对真实范围与意图，排除 1 档口头猜测；代码审查必查 grep 之外的线格式/配置/时序/依赖源码影响面与 1–2 个核心安全前提；命中可运行高危或显式压测条件时在隔离工作区派发对抗者构造运行反例并由主审逐条复跑；零发现合法。
- **不适合使用**：仅在真实表面验证改动功能是否跑通时改用 `dev-verify`；纯抽象设计或计划不会进入实测对抗模式。
- **权限与副作用**：**只读审查，绝不修改产品源码**；对抗实测会在独立临时工作区/worktree 运行复现脚本，且允许外发时可能使用已配置的异构外部执行器（禁外发时限定宿主原生）。

详细执行说明见 [SKILL.md](SKILL.md)。
