# 对抗实测破防（Adversarial Interrogate）

仅在被审对象为**可运行代码或可执行原型**，且命中 `SKILL.md` 第 1 节纯压测分支或第 4 节升级条件时执行。

## 核心铁律

**只有运行证明的反例才能存活。** 未运行的推导、风格、命名、结构偏好以及依赖未来假设的风险一律丢弃。不修改产品代码。

## 1. 隔离环境与多对抗者派发

1. 固定精确被审版本；若包含工作区未提交改动，必须将其完整复制到每个对抗者的独立工作目录或 git worktree（仅检出 commit 会漏掉未提交改动）。
2. 按下方生效路由通过 `spawn-subagent`（默认中性执行角色）并行启动隔离对抗者（严禁修改产品源码，仅允许在各自隔离工作区创建并运行复现脚本）；对抗者均未参与被审版本编写，彼此隔离、不互看结论：

<!-- review-adversaries -->

3. 发送以下固定 brief（附上范围、原始意图、允许隔离写入路径与预算）：

> 尝试打穿这份变更。每条发现必须用真实运行证明：失败测试、最小复现脚本或展示错误行为的实际命令输出（原型则对原型或真实依赖树做探针）。复现文件仅放在你自己的隔离工作区，严禁修改产品源码或自行修复。
>
> 每条候选必须给出：标题、精确复现命令、实际输出、以及原始意图要求的正确行为。**凡未实际运行证明的内容全部不要提交**（包括风格、命名、结构和需要未来改动才成立的风险）。直接完成本单元，不再委派子代理。零发现是合法结果。

## 2. 主审逐条复跑与归并

主审在**同一被审版本**上亲自复跑每一条候选命令：

- **保留**：复跑确实复现失败，且该失败真实违背原始意图。
- **丢弃**：环境/探针自身故障、预期与原始意图不符、输入在真实入口不可达、或遗漏了真实保护层。

保留所有已验证发现的**并集**（同根因合并，但保留不同触发路径与影响），**不投票、不选“获胜审查者”**。无法复跑的候选记入覆盖限制，不混入已验证发现。

## 3. 输出增量

- **已验证反例**：逐条给出精确命令、关键输出、如何违背意图及发现者标识；全部未存活时明确写 `无已验证实测发现`。
- **Dropped 清单**：按对抗者列出丢弃条数与丢弃原因（供用户按需复核）。
- **多样性与限制**：说明实际参与的座次配置是否具备跨模型多样性，以及未覆盖的运行前提。
