# Dev Architect

跨函数或跨模块边界改动动手编码前，用真实调用示例和两套结构不同的具体类型签名定清接口、数据模型、状态所有权与迁移边界。

## 适合使用

- 新增或调整公共接口、共享数据模型、状态生命周期、跨模块依赖或迁移结构。
- 需要识别薄转发层、联动布尔值扩散、边界泄漏等结构红旗后再施工。

## 示例请求

```text
使用 $dev-architect 先别写代码，设计这套插件下载取消与断点清理的接口和状态所有权。
```

## 工作方式与边界

- **工作方式**：先追踪全部真实消费者，写出正常与失败/取消调用示例，再给出两套实质不同的具体类型/边界方案并按单一状态所有者、调用方懂最少等硬标准选型；遇到高代价或实质分歧时转交 `dev-arena`。
- **不适合使用**：局部单文件小改无需触发；产品方向或界面取舍未定时使用 `decision-grill` / `decision-prototype`。
- **权限与副作用**：只输出设计结论、类型草图与迁移顺序，不直接实施产品代码；涉及产品语义变化时交回用户确认。
