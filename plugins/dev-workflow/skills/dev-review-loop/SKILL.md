# Dev Review Loop

在当前范围内协调核验与必要修复，依据已有信息选择起点。

## 范围与起点

读取请求、原始范围／基线、相关代码、需求与接受设计、现有问题和报告、权限及已用预算。没有 Spec 文件也可依据真实要求和公共合同工作；影响结果的缺口先核对。显式选择本能力不扩大只读或更窄授权。

| 当前输入 | 起点 |
| --- | --- |
| 已明确、获准的有界工作或 finding，要求完成后核验 | 核对当前适用性和必要复现，读取修复方法，先完成本批修改与验证，再独立核验结果 |
| 当前需要发现问题并处理 | 使用 dev-review-code 取得所需独立判断，再按实际问题决定是否修复 |
| 已有报告或核验在途中 | 具体问题可作为修复线索；已有通过结论须经当前适用性检查后采用，补齐缺失覆盖 |

用户指定的有效先后顺序优先。已知 finding 不要求先重做完整初审；已失效或不成立的 finding 先查明，不重复修改。需要重新设计或多任务协调的范围交给当前调用者处理。

## 有界处理

实际修改前读取 [有界自适应修复](references/review-loop.md)，沿当前授权与累计预算执行。使用 `dev-review-code` 更新当前所需独立覆盖，向其提供实际变化、完整约定范围及可访问的旧证据；复审方法由该能力负责。

问题已关闭且当前所需独立覆盖充分时返回。证据不足先补条件，材料决定缺失时交回用户或当前协调者。未经处理的有效问题不会被后来的乐观结论覆盖。

## 结果与恢复

说明实际范围／版本、修改与验证、当前核验依据、未关闭问题和覆盖限制；发生修改时报告累计已用预算及继续／暂停理由。区分本轮检查与沿用证据，不将复用表述为两份新全面审查。

恢复沿用原始范围、已有预算和用户停止点。结果交给调用者采用，后续任务、整体交付及外部动作依各自授权。
