# 代码审查与有界修复

用户手动选择 `$dev-review-loop`，对明确代码范围组织独立审查、必要修复、验证与复审。Build 和 Workflow 通过共享方法完成内部核验，不需要再调用本手动入口。单点诊断、普通修改与只读审查有各自的直接方法。

已有明确工作或 finding 时，核对当前适用性后先完成有界修改和验证，再独立核验；需要发现问题时先审查。旧报告的具体问题与可作为通过证据的结论分别判断。

修改批次沿有效预算，默认新授权最多三轮，旧较低上限与停止点保持。已知问题首批修改也计入。复审按实际影响更新完整目标所需的两轴证据，保留本轮查证与复用的区别。

每轮新查证使用干净上下文，不续接上轮 reviewer 会话。旧报告仍可作为待核验的证据，不要求每次重新全面审查。没有实质问题时零修改结束；需要新产品决定时交付完成现状、缺口与影响，不自行改写规格或启动新设计。

```text
使用 $dev-review-loop 先修复这条已确认 finding，验证后核验当前结果。
使用 $dev-review-loop 检查当前模块，在授权范围内修复并复审。
```

不要求Spec、Work或新的协调子代理；具体范围、权限和工具条件来自实际任务。方法见 [SKILL.md](SKILL.md)。
