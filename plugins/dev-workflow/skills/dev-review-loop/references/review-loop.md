# 有界自适应 Review 修复

已有明确、获准的待处理工作或当前审查问题时读取。当前范围由一个协调者管理修改与核验。

## 授权与预算

遵循用户授权及项目/运行时上限。完整实施交付授权通常涵盖本范围必要缺陷修复；只审查、明确暂停或更窄授权保持其原边界。开始续修时说明适用范围和预算。

新自动修复授权未指定次数时最多三轮。已有一次授权、更低上限和提前停止决定继续有效；增加上限需要新授权。

一轮是一批有界修改、相关及集成验证、再更新当前完整约定范围所需的独立核验。该批首次产品修改即占用一轮，多个实现子代理共用；验证失败或审查未完成仍计入已用额度。用户已提供 finding 或工作项而先实施的首批同样计入，采用已有证据不会退还轮次。初审、只读诊断与专项补审受任务的时间、成本和权限约束。

## 修复与续行

1. 对照原始用户来源、当前有效决定和实际证据核对工作项或问题与完成条件。现有共识内的缺陷、必要影响面及直接回归进入修复；需要改变用户结果、接受设计或风险的建议，先由协调者组织对齐。实现采用满足已确认关闭条件的最小合理改动，审查分歧依据事实澄清。
2. 使用 dev-implement 完成当前批次，检查实际变更与相关、集成验证。协调相同范围写入，明确修复后的当前版本，再使用 dev-review-code 更新完整约定范围的必要覆盖，包括接受设计与修复影响；提供各旧结论的原版本、范围及其后累计变化，按实际影响取得补充或全面审查。结束时核对目标仍一致。
3. 预算内说明上一轮解决了什么、剩余实际风险和下一步依据。剩余问题明确、修复可行且范围稳定时继续。
4. 同一问题反复且无新依据、结果显著恶化、需要改变材料决定或越过权限时提前暂停。证据/审查能力不足先补对应条件，条件未改善时交还用户。
5. 必要验证和完整覆盖充分、有效问题已解决时结束。预算耗尽仍有问题时保留事实与用户检查点；交付标准始终不变。

## 恢复

在当前上下文、已有 Work／tracker 或必要修复报告中保留授权范围、已用额度、实际结果和继续/暂停原因。Skill 重入、实现子代理更换、commit、报告改名或新会话沿用同一授权；额度无法确认时先恢复事实。旧记录中的能力名称变化不改变同一任务的预算；Build此前正常实施不追溯计入本循环，进入本循环后的实际批次按上文计算。
