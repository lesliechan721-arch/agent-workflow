# 复杂规格的阅读与保真

多个决定主题、较多附件或重组已有规格时读取。

## 先明确阅读任务

让用户先看见当前状态、尚需选择的内容、关键场景和主要后果，再进入完整技术定义。已确认与待确认、建议与硬约束、目标与验证事实保持可辨。重大风险不能只出现在默认折叠的细节中；完整条件仍可逐项进入。

按主题聚合同一能力的行为、例外、精确规则及验收。场景说明体验，条件组合用表格，事件先后用时序，公共数据用 schema，空间或交互保留实际原型。user story 是表达方式之一，不以条目数量证明完整。

## 共置、附件与过程资料

短而相关的定义共置。独立技术主题较长或需要单独消费时，拆为规范性附件，链接说明用途、范围和适用版本。正文与附件的效力相同，原始事实与示例则按其实际性质呈现。

同一规则维护一处完整定义；导航、关键提醒和验收按用途引用。让实施者能直接找到适用章节，而非在全部历史中猜测。

当前规范保留足够的确认状态、实质变化和非显然理由。Review轮次、finding关闭经过、旧命令输出和运行日志按恢复用途链接现有记录，避免打断当前行为说明；移动时保留原依据及范围。没有请求清理时不删除来源。

## 清楚表达不改变精度

先写主体与结果，再按需解释机制。条件与动作分开，一句聚焦一个主要含义；同一概念用同一名称，技术标识照原样保留。中文借鉴受控语言的清晰原则，不宣称符合受控英语的词汇或规则。

| 容易被合并的概念 | 应保留的区别 |
| --- | --- |
| 接受／交付／确认 | 排队责任、尝试返回与确认事实不相同 |
| 保存／生效 | 用户意图保存不证明运行状态改变 |
| 必须有上限／建议某值 | 要求强度与具体值的决定程度不同 |
| 新输入到达／模型读取 | 宿主事件不证明模型已得到内容 |

## 核对重组

从原来源核对每项重要条件与例外，再从新结构反查新增要求。复杂迁移可临时保存位置映射，不为普通任务创建规则登记表。

让读者用新结构回答关键场景和待决定问题，并定位完整依据。格式更短、图更多或页面更美只说明呈现变化；保真与理解需要分别核验。派生阅读视图指向当前完整来源，不另行维护第二份规范。
