# Dev Repair

## 确定本次范围

读取用户要求、原始范围／基线、实际代码、适用合同与接受设计、现有报告、修改权限和已用预算。已有范围直接沿用；无法确定且影响结论时先明确。没有 Spec 文件也可依据真实需求、公开合同和项目事实审查，缺失的需求依据如实限制判断。

完整核验修复请求涵盖其授权范围内的必要本地修复，不能自动扩大产品行为、权限或风险。

## 审查与修复

```text
独立审查／采用仍有效的报告
├── 无实质问题且覆盖充分 → 返回当前结果
├── 证据或材料决定缺失   → 补条件或交回协调者／用户
└── 有依据且修复获准     → 有界修复 → 实际验证 → 独立复审
                                    预算内按新依据继续，否则停止
```

独立审查使用 `dev-review-code`；复用报告需确认目标、版本、覆盖和独立性仍适用。

已有实质问题且修复在授权内时，读取 [有界自适应修复](references/review-loop.md)。具体修复使用 `dev-implement`，只处理当前问题、必要影响面及直接回归。规范冲突或新的材料选择交回当前协调者；

## 结果与恢复

返回当前范围／版本、实际修改与验证、独立审查结果、未关闭问题和覆盖限制；有循环时说明累计已用预算与继续／暂停依据。完成判断来自实际证据，不来自次数或报告标题。依赖解锁、整体交付及后续任务由调用者决定。
