# Dev Implement

按当前请求或 Spec 交付可工作的结果。用纵向切片吸收实施中的新发现，不把实现过程反写成完备计划。

## 开始

1. 确认用户已明确要求实现，或已明确批准当前 Spec。读取相关决定、Prototype 结论和仓库约定。
2. 判断是否需要 `work.md`。一个上下文能完成的低风险任务直接实现；跨会话、多切片、并行、迁移或 handoff 时读取并使用 [Work 模板](assets/work-template.md)。

## 实施循环

3. 选择一个窄而完整、可以单独演示或验证的纵向切片。避免按数据库、API、UI 做水平批量。
4. 在稳定公共 seam 上优先使用 red-green。探索性或主观界面工作使用适合的行为验证。
5. 运行与变化相称的测试、类型检查、构建或真实行为检查。修复后重新运行相关验证。
6. 记录重要发现、局部工程选择、偏离和剩余风险。少量关键歧义使用 `requirements-clarifier`；整体目标、主要方案或相互依赖决定变化时停止并使用 `decision-grill` 或更新 Spec。
7. 完成后给出结果、实际验证、偏离和风险，并建议使用 `dev-review-code`。

遵循仓库现有 Git 和发布政策。涉及破坏性、远程、凭据、显著成本或不可逆动作时，先取得明确授权。
