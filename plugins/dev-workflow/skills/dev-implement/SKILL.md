# Dev Implement

按当前请求或 Spec 交付可工作的结果。用纵向切片吸收实施中的新发现，不把实现过程反写成完备计划。

## 产物位置

一个上下文能完成的低风险任务不创建工作文档。跨会话、多切片、并行、迁移或 handoff 需要 `work.md` 且未指定路径时，使用：

```text
docs/dev/<task-slug>/work.md
```

## 开始

1. 确认用户已明确要求实现，或当前 Spec 已获批准。读取相关决定、Prototype 结论和仓库约定。
2. 判断是否需要 `work.md`。需要时读取并使用 [Work 模板](assets/work-template.md)。

## 实施循环

3. 选择一个窄而完整、可以单独演示或验证的纵向切片。避免按数据库、API、UI 做水平批量。
4. 在稳定公共 seam 上优先使用 red-green。探索性或主观界面工作使用适合的行为验证。
5. 运行与变化相称的测试、类型检查、构建或真实行为检查。修复后重新运行相关验证。
6. 记录重要发现、局部工程选择、偏离和剩余风险。
7. 遇到以下情况停止写入并返回处理类型，不直接选择下一 Skill：
   - `material-decision`：整体目标、范围、公共行为或相互依赖决定仍需用户取舍；
   - `evidence-needed`：必须通过体验、实验、测量或运行结果才能决定；
   - `spec-change`：已确认 Spec 的材料决定需要改变；
   - `high-risk-authorization`：破坏性、远程、凭据、显著成本或不可逆动作尚未授权。

## 输出

返回：完成结果、实际验证及结果、重要工程选择、与请求或 Spec 的偏离、剩余风险、阻塞类型和未完成切片。没有阻塞时明确写“无”。

遵循仓库现有 Git 和发布政策。高风险动作必须在获得明确授权后执行。
