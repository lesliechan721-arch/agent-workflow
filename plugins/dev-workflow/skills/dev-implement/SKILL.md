# Dev Implement

按当前请求或 Spec 交付可工作的结果。用纵向切片吸收实施中的新发现。

## 产物位置

一个上下文能完成的低风险任务不创建工作文档。跨会话、多切片、并行、迁移或 handoff 需要 `work.md` 且未指定路径时，使用：

```text
docs/dev/<task-slug>/work.md
```

## 开始

1. 确认用户已明确要求实现，或当前 Spec 已获批准。
2. 如果本次是 Review 修复，读取最新 `code-review.md`，区分实现缺陷、Spec 偏离和 Spec 本身的问题。
3. 需要跨会话工作记忆时使用 [Work 模板](assets/work-template.md)。

## 实施循环

4. 选择一个窄而完整、可以单独演示或验证的纵向切片。
5. 在稳定公共 seam 上优先使用 red-green；探索性界面工作使用适合的行为验证。
6. 运行与变化相称的测试、类型检查、构建或真实行为检查。修复后重新运行相关验证。
7. Review 修复必须覆盖全部 blocker；无法修复的项明确说明原因和所需决定。
8. 记录重要工程选择、偏离、验证和剩余风险。

## 停止条件

- 材料目标、范围、公共行为或跨模块契约需要改变。
- 必须通过用户体验、实验或测量才能决定。
- 破坏性、远程、凭据、显著成本或不可逆动作尚未授权。

## 输出

```text
结果：complete / blocked
产物：<代码、work.md 或无>
验证：<实际运行及结果>
未解决：<材料决定、Spec 变化、高风险授权或无>
建议动作：<补充决定 / 收集证据 / 修订 Spec / 代码审查 / 无>
```

实现或 Review 修复完成后建议代码审查。若材料决定或 Spec 需要改变，先完成对应决定或规格修订。
