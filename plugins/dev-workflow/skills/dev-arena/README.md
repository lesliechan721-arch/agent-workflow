# Dev Arena

面对高返工代价、有实质分歧或无先例的设计、接口、算法或实现形态，并行派发多个隔离竞争候选，经独立裁判评判后端到端通读选定唯一基座，再按同一心智模型手工嫁接落选方案的亮点。

## 适合使用

- 存在多种实质不同的架构、算法或实现方向，单一首稿容易锁定错误形状。
- 决策返工代价高，值得用隔离并行探索加独立评审换取更稳的基座方案。

## 示例请求

```text
使用 $dev-arena 对比这套缓存失效与并发锁架构的多种方案，选出最优基座并手工融合亮点。
```

## 工作方式与边界

- **工作方式**：先拟定不发给候选的隐藏评分标准，在各自隔离目录/worktree 并行派发候选，结束后默认启动 1 名干净上下文独立只读裁判评分，主代理通读全部候选选定唯一基座并手工融合 1–2 个亮点，最后验证交付。
- **不适合使用**：方向单一清晰的设计改用 `dev-architect` 或直接实现；审查已有改动改用 `dev-review`。
- **权限与副作用**：会并行派发多个子代理并创建隔离输出目录或 git worktree；在任务允许外发时可能优先使用已注册的异构外部执行器（禁止外发时一律限定宿主原生）。

详细执行说明见 [SKILL.md](SKILL.md)。
