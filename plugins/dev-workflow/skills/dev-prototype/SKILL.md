# Dev Prototype

制作一个用户可以直接反应的原型，用最低成本回答一个明确问题。

## 工作流

1. 写出唯一的原型问题和成功观察。不要用“探索整个产品”代替具体问题。
2. 选择最便于用户判断的形式：图片、候选文案、可点击网页、流程 walkthrough、API consumer 示例、状态模拟器或最小技术 spike。
3. 读取并使用 [原型说明模板](assets/prototype-brief.md)。清楚说明验证什么、忽略什么、如何查看。
4. 收集用户观察。区分事实、偏好和新的材料问题。
5. 把确认后的结论交给 `dev-spec`。仍有相互依赖决定时使用 `decision-grill`；只有少量局部缺口时使用 `requirements-clarifier`。

原型默认可丢弃。只有用户明确选择复用，且实现者重新评估质量、测试和风险后，生产实现才可以从原型代码演进。
