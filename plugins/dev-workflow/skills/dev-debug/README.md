# Dev Debug

按科学方法定位未知故障根因：亲手复现故障、设计切割空间最大的二分实验、证伪即回滚，并识别“同前提连续失败”硬停信号，避免对着源码盲猜叠补丁。

## 适合使用

- 故障、崩溃、偶发超时、数据错乱或回归原因尚未查明，需要运行证据锁定根因。
- 已有修复尝试未见效或怀疑陷入错误假设，需要重新做区分实验。

## 示例请求

```text
使用 $dev-debug 复现并定位并发同步偶发丢配置的真正根因，只诊断不改正式代码。
```

## 工作方式与边界

- **工作方式**：先在真实入口驱动复现并保留原始失败输出；每轮优先跑最能缩小假设空间的观测，被证据推翻的假设立刻撤回改动；同一前提连续两次失败同一检查时硬停验证前提本身。
- **不适合使用**：仅了解代码机制或历史理由改用 `dev-investigate`；纯粹补充自动化回归测试改用 `dev-tdd`。
- **权限与副作用**：会执行本地复现命令、运行测试或添加临时观测探针；仅诊断任务在交付前清理全部临时改动。
