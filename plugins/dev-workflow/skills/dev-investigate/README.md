# Dev Investigate

只读调查代码或系统的当前运行机制（How）、历史设计原因（Why）及 CPU/内存/trace 运行捕获材料，交付带出处引用与证据强度的事实链。

## 适合使用

- 需要搞清某段逻辑如何流转、状态权威归谁、失败与取消怎么释放资源（How）。
- 需要沿重命名与一手提交/讨论史料查证某项设计或阈值当初为何这样写（Why）。
- 需要分析已有日志、CPU profile、堆快照或 trace 捕获文件。

## 示例请求

```text
使用 $dev-investigate 解释插件同步时的锁获取和失败回滚路径是怎么工作的。
使用 $dev-investigate 查一下为什么这里的重试超时硬编码成 10 秒，区分直接记录与记录空白。
```

## 工作方式与边界

- **工作方式**：小范围直接追踪源码；跨多模块或大代码库可委派只读子代理隔离探索。历史动机考证严禁从代码倒推，逐条标明 `直接记录 / 推断 / 记录未答` 并保留空白项。
- **不适合使用**：需要亲手复现未知故障并二分定位根因时改用 `dev-debug`；审查改动质量与影响面改用 `dev-review`。
- **权限与副作用**：**严格只读**，不修改产品代码。
