# 运行现场与固定捕获分析

分析日志、CPU/内存 profile、线程快照、trace 或固定捕获数据时读取。

## 先保真再分析

- 确认实例身份、构建版本、输入负载、采样时段与观测开销；保留原始文件与转换参数，结论可回查原件。
- 新增现场探针可能改变时序或内存分布，必须记录潜在扰动与事后恢复方式。
- 缺少符号映射时明确标注未解析的函数/对象身份，绝不猜测并伪造源码位置。

## 按材料类型的硬检查

| 材料 | 正确定位方式 | 常见误判陷阱 |
| --- | --- | --- |
| CPU profile | 按占比与调用树找热路径，区分自身耗时（self）与子调用耗时（inclusive）及等待时间 | 把采样偏差或等待 I/O 当成纯 CPU 热点 |
| 内存 / 堆快照 | 比较多次快照的持续增长对象及到 GC Root 的保留链 | 拿单次快照里体积大的对象直接判为内存泄漏 |
| Trace / 线程快照 | 对齐事件顺序、重复调度、锁持有者与异步完成信号，留意跨进程时钟漂移 | 忽略缺失事件，把先后出现当因果 |
| 对比材料 | 同负载、同配置前后对照才支持因果判断 | 无对照组时把“最像的假设”写成已证实根因 |
