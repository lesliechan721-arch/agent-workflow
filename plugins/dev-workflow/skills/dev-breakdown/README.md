# 工作分解

把明确需求、Spec、issue 或 Review 修复范围分解为可以执行和交接的工作项。可以独立使用，无需采用完整开发流程。

每个工作项提供新上下文实施者所需的交付结果、真实依赖、技术安排、设计依据、验收与自主决定范围。原型和接口引用指向实际可访问的页面、状态或契约。只展开近期需要开展的工作；已有可靠任务列表时直接复用，单个自然工作项不强拆。

跨上下文交接通常一项一个 Ticket 或 issue，小任务可同页或在对话中交付；已有 tracker 时直接复用。分解不创建共享进度记录、不修改产品代码、不启动 worker，也不授予提交权限。材料决定尚未明确时先说明缺口。

```text
使用 dev-breakdown 把批准 Spec 拆成可独立交接的 Ticket，写到 docs/dev/invitations/tickets/，先不要实施。
```

协作时采用调用者给定的本轮 Ticket 位置，不自行分配 Build 轮次。需要协调完整交付时由用户手动选择 `$dev-build`，直接实现明确工作项时使用 `dev-implement`。执行说明见 [SKILL.md](SKILL.md)。
