# 工作分解

把明确需求、Spec、issue 或 Review 修复范围分解为可以执行和交接的工作项。可以独立使用，无需采用完整开发流程。

每个工作项说明交付结果、真实依赖、必要上下文和验证方式。只展开近期需要开展的工作；已有可靠任务列表时直接复用，单个自然工作项不强拆。

需要持久交接时按用户路径或仓库约定保存工作记录；已有 issue 或 tracker 时不另建副本。分解不修改产品代码、不启动 worker，也不授予提交权限。材料决定尚未明确时先说明缺口。

```text
使用 dev-breakdown 把批准 Spec 拆成可交接工作项，写到 docs/work.md，先不要实施。
```

需要执行完整结果时使用 dev-build，直接实现明确工作项时使用 dev-implement。执行说明见 [SKILL.md](SKILL.md)。
