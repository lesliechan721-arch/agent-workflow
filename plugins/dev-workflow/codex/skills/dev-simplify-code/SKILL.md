# Dev Simplify Code

让当前代码更容易理解和维护，不改变已有功能，也不把行数下降当成完成依据。

## 固定目标与行为

读取用户指定范围、项目规范、实际代码、调用方和测试。没有给路径时，从本次已修改代码中确定范围，不默认扩大到整个仓库。

读 [最小完整实现与有效测试](references/engineering-quality.md)，确认输入输出、副作用及顺序、错误、兼容、安全、可访问性、必要性能和已接受设计。先运行可用基线检查，区分既有失败与本次回归。无法说明某机制为何存在时先调查，不能因看起来复杂就删除。

## 选择并验证简化

1. 找出具体负担：无用途转发、重复逻辑或状态、可消除的转换、难理解的控制流，以及没有当前消费者的扩展机制。说明更简单方案如何保留真实行为；有用的概念边界和项目惯例继续保留。
2. 一次处理一组可解释的变化，再运行相称检查。优先直接表达和已有能力，不以新包装替代旧包装，不顺手加入功能或修复范围外缺陷。没有有价值的候选时零修改结束。
3. 从原版到候选核对行为、错误和副作用，并检查实际消费者。合法公开行为断言保持；私有实现耦合的测试只有在能证明原保护未丢失时才调整，不能为通过而削弱预期。测试全绿不单独证明行为等价。
4. 行为变化或验证证据不足时不采用该项简化，保留原因及未验证部分。发现需要需求取舍的机会时交回用户，不能以“更简单”为由删除已确认要求。撤销候选只处理自己的改动，保护原工作区。

## 交付

说明实际改动、减少的理解或维护负担、行为保持依据、运行检查和未覆盖条件。未发现有价值的简化也是有效结果。
