# 需求与设计

把当前需求推进到可审核、可交接的设计；本次只设计时在这里结束，后续用户明确实施后再交给Build。

使用[当前方法](SKILL.md)对齐材料选择，按需要维护项目词汇和重要决定，形成完整当前任务规格并完成必要独立审查。已经确认的共识和现有文档位置直接复用；没有新知识时不生成词汇/ADR，没有持久需求时不建任务目录。

```text
使用 dev-design 把上游接入需求对齐并形成项目设计，今天先不实施。
使用 dev-design 继续 .dev-workflows/upstream/ 的设计，沿用已有规范和当前确认。
```

完整任务Spec、接受原型及过程资料默认本地.dev-workflows；已有公共合同按实际变化维护，长期知识与设计只保留确有消费者的部分。设计已确定、代码已实现和运行已验证分别陈述。只读请求不授权文档编辑；设计认可不自动授予实施、提交或推送权限。
