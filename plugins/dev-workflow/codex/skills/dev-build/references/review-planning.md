# 里程碑核验与推进

共享基础即将扩散、重要风险／迁移转换、代表性设计推广或高返工集成结果需要先核验时读取。milestone 是当前累计范围，不是每个开发步骤。

```text
明确本阶段结果、基线与依赖
    → 集成并验证 → 固定当前审查对象 → dev-repair
                                              ├── 满足阶段要求 → Build 解锁依赖
                                              └── 问题／缺证据 → 相关依赖保持暂停
```

Build 提供当前承诺的完整结果、Spec／接受设计、验收、累计范围和授权／已用预算；后续未承诺功能明确在本次范围外。工作区或已有 commit 均可作为对象，审查期间协调相同范围的并发写入，结果变化时重新核对适用性。

由 `dev-repair` 负责本范围的审查、必要修复、验证和完整复审；Build 采用这份结果，不重复同一循环。阶段验收、必要独立覆盖、问题关闭和用户额外条件满足后再解锁依赖；真正独立且不受风险影响的任务可继续。

保存有实际价值或用户要求时使用 [Checkpoint 与提交](checkpoints.md)，未创建 commit 本身不阻塞核验。新决定使旧阶段依据失效时重验相关结果。最终仍从任务原始基线核验全部当前交付，不能用局部通过替代整体覆盖。
