# 审查安排与结果采用

需要独立检查公共基础、高风险边界、设计敏感代表性实现或重要集成时读取。

明确本次已承诺完成的结果、适用需求与设计范围、当前基线及将被解锁的依赖，再请求 dev-review-code 审查。专业 reviewer 接收的是完整的当前范围，后续未承诺功能由调用者明确列为范围外。

两轴未发现实质问题且覆盖充分时，协调者可继续相关依赖。已有实质问题则暂停依赖该结果的工作；证据不足先补足相应验证。真正独立且风险不受影响的任务可在原授权内继续。

阶段报告采用单独位置，保留范围与版本。最终仍从任务原始范围检查完整集成结果，使用所有当前适用的验收与已接受设计。已有局部审查不能代替整体覆盖。

报告可以同时有确定缺陷与覆盖缺口。协调者按事实处理两者，独立审查不会自动授予修复、提交或发布权限。
