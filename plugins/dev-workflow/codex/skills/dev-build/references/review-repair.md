# 有界自适应 Review 修复

当前独立 Review 发现实质问题，且修复在现有授权范围内时读取。

## 授权与预算

遵循用户授权及项目/运行时上限。完整实施交付授权通常涵盖本范围必要缺陷修复；只审查、明确暂停或更窄授权保持其原边界。开始续修时说明适用范围和预算。

新自动修复授权未指定次数时最多三轮。已有一次授权、更低上限和提前停止决定继续有效；增加上限需要新授权。

一轮是一批有界修复、相关及集成验证、再对当前完整范围做独立复审。该批首次产品修改即占用一轮，多个实现子代理共用；验证失败或审查未完成仍计入已用额度。初审、只读诊断与专项补审受任务的时间、成本和权限约束。

## 修复与续行

1. 对照原始用户来源、当前有效决定和实际证据核对问题与关闭条件。现有共识内的缺陷、必要影响面及直接回归进入修复；需要改变用户结果、接受设计或风险的建议，先由协调者组织对齐。实现采用满足已确认关闭条件的最小合理改动，审查分歧依据事实澄清。
2. 检查实际变更和验证。当前范围属于 milestone 时，按 [里程碑审查](review-planning.md) 固定本轮实际审查对象，再对完整当前范围复审，包括已接受设计证据。这份复审结果同时供阶段推进采用。
3. 预算内说明上一轮解决了什么、剩余实际风险和下一步依据。剩余问题明确、修复可行且范围稳定时继续。
4. 同一问题反复且无新依据、结果显著恶化、需要改变材料决定或越过权限时提前暂停。证据/审查能力不足先补对应条件，条件未改善时交还用户。
5. 必要验证和完整覆盖充分、有效问题已解决时结束。预算耗尽仍有问题时保留事实与用户检查点；交付标准始终不变。

## 恢复

在当前上下文或本地任务记录中保留授权范围、已用额度、实际结果和继续/暂停原因。Skill 重入、实现子代理更换、commit、报告改名或新会话沿用同一授权；额度无法确认时先恢复事实。

预算属于实际获授权的审查范围。真正不同范围按其授权处理；阶段问题仍阻塞依赖。需要硬次数或成本保障时依靠已有运行时控制，本文件提供 agent 的操作准则。
