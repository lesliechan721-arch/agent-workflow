# 协调实施

任务需要多个实现上下文或持续交接时读取。

## 准备可派发任务

复用已有 ticket/issue，必要时使用 dev-breakdown 补足。下一批任务应包含结果、相关规范与设计入口、已确定技术安排、真实依赖、验收和范围。按实施者能力调整粒度，较弱 worker 获得足够领域背景；跨域关键选择先由协调者调查明确。

资料指针必须在目标 worker 的环境可访问。共同布局、接口或迁移规则在依赖扩散前稳定；任务初始说明保留在正文中，后续状态附着其后。

## 执行

默认顺序使用 fresh worker 以隔离上下文；写入范围、公共接口和验证环境独立且集成收益明确时并行。使用现有平台的 spawn/wait/结束能力，按当前权限和成本范围选择模型。

worker 使用 dev-implement 完成分配的工作项。委派说明目标、允许写入、必读资料和验证重点；共享工作索引由当前协调者维护。同步产品接口或共同 UI 的工作按依赖安排。

采用项目已有隔离和 Git 策略。并行可能相互影响时串行；确认旧 worker 的真实终态后再恢复其修改范围。

## 接纳与恢复

核对实际 diff、任务验收和运行证据，合并后执行组合验证。设计敏感任务在代表性实现处先做实际对照，获得稳定依据后再推广共享模式。

更新 ticket 的实际结果和索引状态，保留任务定义、原始审查范围及可访问证据。完成由已集成且已验证的结果证明。恢复时核对真实工作区与 worker 状态；无法确定安全接管条件时说明缺口。

任务拆分和局部顺序可以调整；材料行为、范围、权限、风险或成本改变时请求相应确认。
