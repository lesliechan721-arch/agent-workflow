# 实施协调

面向多工作项协调、跨上下文交接、集成修复或用户委托的完整交付，组织实施到独立审查的闭环。可以直接调用，所需方法由当前任务决定。

当前上下文足够的机械修改直接实施和验证；需要规范依据、独立委派或有界修复时使用 dev-implement。存在多个独立验收/交接工作项、较重局部实施或用户要求子代理时，先补足可派发 Ticket，再默认顺序委派子代理实施。只有已获委派授权、工具可用且工作之间确实独立时才并行。协调者核对实际变更、设计对照和集成验证，并维护共享进度。任务正文保持完整；现有 tracker 不足以支持恢复时才增加 Work 索引。

自动修复沿用实际授权；新授权未给轮数时默认最多三轮。每轮根据实际结果和下一步依据决定是否继续，可以提前停止。旧授权和已有停止点继续有效，预算耗尽不代表允许交付。

只有完整最终结果验证充分并通过双轴独立审查时才交付。阶段审查不能替代最终审查；缺少独立审查能力时会报告限制。选定 milestone 后默认采用“集成验证、授权 checkpoint、固定范围审查”的闭环；提交授权不足时主动确认，明确无提交选择按该路径记录。提交权限不包括推送或历史重写。

```text
使用 dev-build 按已批准 Spec 完成工作项、集成验证和最终 Review。不要提交。
```

函数修改是否需要 dev-implement，取决于规范、委派与修复约束，而非文件或函数数量。只需分解或审查时分别使用 dev-breakdown、dev-review-code。执行说明见 [SKILL.md](SKILL.md)。

## 当前共识

新需求先读取已确认要求与委托边界，选择会影响用户结果时取得实际答复；已有充分依据则继续。新证据影响旧决定时只重新对齐受影响部分，同步规范、任务与在途执行者后恢复。局部工程自由和材料决定分开，用户不必点名 decision-* 才能触发必要对齐。
