# 当前任务资料

开始持久化、跨上下文交接、原型迭代或恢复任务时读取。

## 一个任务位置

优先用户给定位置，其次沿用当前任务既有位置，再遵循仓库约定。需要新增持久任务且都无约定时，可采用 `docs/dev/<task-slug>/`，向用户说明。

将具体目标位置和已有工件作为调用上下文传递。Prototype 获得本任务的原型子目录，实施者获得 ticket 与引用，reviewer 获得实际审查范围及证据；leaf 的独立默认路径仅在没有当前位置时适用。

已有外部 issue、ADR、设计文件或文档按可访问指针复用。需要保留而临时位置将消失的关键证据，保存到本任务证据位置或组织认可的存储，并保留来源说明。

## 角色与落盘

| 产物 | 何时保存 | 保存内容 |
| --- | --- | --- |
| Shape / decisions.md | 复杂多轮决定、长原型或跨上下文需要恢复 | 当前共识、开放问题、必要理由与证据 |
| prototypes/<question>/ | 实际构建可打开产物或多轮反馈 | 原型、问题、接受范围与必要证据 |
| spec.md | 需要稳定交付规范与批准 | 当前行为、重要设计、验收及可达权威引用 |
| tickets/ 或已有 issue | 多实现者或需要独立派发 | 完整工作项、依赖、实施上下文与验收 |
| work.md | 没有 tracker 可承担协调恢复 | 任务索引、进度、原始基线、验证与下一步 |
| Review / evidence | 后续修复、交接或审计需要 | 指定范围的判断、实际证据和覆盖限制 |

Spec 成为当前规范后，Shape 保存决定来源；后续新决定须进入相应 Spec 修订。tickets 引用规范并细化执行安排。work 指向 tickets，实际结果更新不替代任务正文。

只创建当前有消费目的的文件。小任务在对话中完成必要共识、代码验证与 Review；原型与测试文件本身仍可按任务需要产生。

## 记录与确认

确认一批材料决定时保存当前答案，进入长构建前保存开放问题。Spec 审查后，给用户提供决定摘要、重要风险、设计入口和实施自由，明确请求对当前范围的批准。

用户批准及高风险授权沿用现有对话、issue/PR 或项目机制，记录指向实际版本/范围的依据。报告保存与审计历史由当前协调者按任务策略安排；审查技能默认只提供结果。
