# 有界自适应规格修订

已有实质 Spec 问题，且用户的当前规格任务包含修订授权时读取。当前Design协调者组织修订与独立复审；dev-spec 修订相同项目规范，dev-review-spec 只读审查。

## 范围与预算

沿用用户及项目/运行时的有效限制。新自动修订授权未指定次数时，默认最多三轮。旧的一轮授权、更低上限、只读请求和既有停止点继续有效。开始时说明实际范围与预算，增加预算需要新授权。

一轮是一批有界实际修订、对原始决定/接受设计/项目合同的自检，以及完整当前 Spec 的独立复审。首次修改规范性内容即占用本轮；初稿编写不计作修订，复审未完成不退还已用轮次。补事实、诊断和额外审查继续受当前任务成本、时间与权限限制。

## 修订与继续

1. 依据证据和关闭条件处理遗漏、冲突、验收缺口、不可达依据，以及妨碍当前审核的隐藏材料决定或无来源约束。修订可以补充、合并、移动或引用，但保留有效条件、精度与自主空间；篇幅本身和对更完整未来设计的偏好不是新增要求的依据。
2. 新证据引出产品选择，或使已接受设计、兼容和风险依据失效时，先暂停相应规范修改，由当前协调者说明差异并组织对齐。已有事实自行调查；需用户权衡时取得实际回答或明确委托，再更新受影响要求。修订预算与 Review 建议不构成新的产品授权。
3. 使用 dev-spec 修订，并核对来源覆盖、接口与设计、验收和实现自由；随后由满足本轮独立性要求的审查者使用 dev-review-spec 全面复审。已为本轮分配的子代理直接执行，不再重复委派。
4. 有剩余预算时，依据上一轮实际修复、当前真实问题及下一步新依据决定继续。重复偏好性重写、没有新诊断依据、缺乏当前依据的规范扩张或需要材料决策时提前暂停。审查能力或资料缺失时补足对应条件，条件不变则交还用户。
5. 实质问题关闭且必要覆盖充分时结束修订，向用户展示当前规范的完整审阅入口、被纳入的附件和设计、重要风险、自主空间与本次实质变化，明确请求批准。预算耗尽仍有问题或缺口时停止自动执行；批准和进入产品实施仍由当前有效共识与用户授权决定。

## 恢复

在当前对话或本地任务中保留授权范围、已用次数、实际结果及继续/暂停理由。新会话、报告改名、Skill 重入或 Spec/Code 阶段切换不重置同一未解决事项的授权限制。真正不同任务按各自有效授权处理；来源或额度无法确认时先恢复事实。

设计交付在当前范围结束，批准设计不自动启动实施。本文提供协作准则，硬次数或成本上限由现有运行时实现。独立调用规格编写或审查 Skill 不会自动取得整个修订循环的权限。
