# 有界自适应规格修订

已有实质规格问题且修订获准时使用。Design 协调，`dev-spec` 修改规格及适用公共合同，`dev-review-spec` 独立只读复审；单独编写或审查不自动授权整个循环。

## 范围与预算

开始时说明本次范围及剩余预算。沿用用户、项目和运行时的有效限制；新自动修订授权未指定次数时最多三轮，旧的更低上限、已用次数、只读限制与停止点保持。增加预算需要新授权。

一轮包含一批有界修订、来源自检和独立复审。首次修改规范性内容即占用本轮；初稿不计，复审未完成不退还轮次。复审按累计影响选择范围，最终完整目标须由本轮检查及经核对仍有效的旧证据覆盖，不要求每轮重读全部材料。

## 修订与继续

1. 根据问题证据、影响和关闭条件组织最小充分修订，保留有效条件、精度与自主空间。没有当前必要性的机制可简化；已确认选择有疑问时先提议变更。篇幅和未来架构偏好本身不是问题依据。
2. 未决选择会改变方案，或新证据使接受设计、兼容及风险依据失效时，暂停受影响修改，将差异与原始来源交给 `decision-shape`。取得实际答案或明确委托后同步要求；获准的比较稿保持待定。修订预算不产生产品决定权。
3. 使用 `dev-spec` 修订并自检，再交由 `dev-review-spec` 核对变化、影响和证据复用。Review 拥有复审方法与独立性判断，Design 不重放其委派步骤。
4. 仅在预算内、仍有实质问题且有新的修复或诊断依据时继续。重复偏好性改写、依据不明的规范扩张、必要资料或能力无法补足时提前停止；补充调查和额外审查仍受成本、时间及权限限制。
5. 实质问题关闭且当前完整范围覆盖充分时，展示主 Spec、纳入附件、重要变化、风险及自主空间，按适用要求请求批准。预算耗尽则报告未闭合问题与覆盖缺口，不继续自动修改。批准设计不自动授权实施。

## 恢复

在对话或既有修订记录中保留授权、已用次数、结果和停止理由；跨上下文恢复才保存到当前 reviews/，不把循环历史复制进主 Spec。会话、文件名、Skill 重入、阶段或存放位置改变不重置同一事项的预算。事实不明先恢复；真正不同任务使用各自授权。硬次数与成本上限由现有运行时实施。
