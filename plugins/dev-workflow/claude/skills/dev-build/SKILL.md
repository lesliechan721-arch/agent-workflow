# Dev Build

```text
有效目标 → 准备任务 → 实施／集成 → dev-review-loop → 当前范围结果
                                       │
                       Build 决定依赖推进与最终交付
```

## 准备与实施

1. 核对当前请求、实际确认与实施授权、适用规范和设计、相关代码；保留任务原始基线。明确小任务可凭当前请求和答复实施，文件自称批准不是确认来源。
2. 缺少材料决定或需要修订设计时，由当前用户协调者使用 `dev-design` 处理；独立调用时由本代理协调。已有充分依据直接复用。需要分解时使用 `dev-breakdown`；开始前确认任务目标、依据和验收足以独立接手。
3. 当前上下文足够的机械修改直接执行和验证；受规范、设计、接口约束的工作项使用 `dev-implement`。多项独立交接、局部实施挤占协调上下文或用户要求委派时，读取 [协调实施](references/coordinated-build.md)。
4. 接纳实际 diff、任务验收及设计对照，再作组合验证；进度更新保留任务正文。需要保存临时输出、证据或协调记录时，读取 [工作目录](references/local-workspace.md)。多任务、在途执行者或恢复需要时，由当前协调者维护 [工作索引](assets/work-index-template.md)；已有 tracker 足够时复用，单项短工作不强制记录。

## 核验与推进

公共基础即将供下游复用、重要风险或迁移转换、代表性设计推广、高返工代价集成时，读取 [里程碑核验](references/review-planning.md)。Build 固定当前承诺范围、累计基线和依赖，将该范围的审查修复交给 `dev-review-loop`，依据返回证据决定解锁；普通工作项执行相称验证。

整体实现与集成验证后，对原始任务范围的完整结果使用 `dev-review-loop`。传递实际依据、必要设计、授权和已用预算；提供各旧报告的原始版本／范围供审查者核对当前适用性；局部通过不替代整体覆盖。采用其当前结果推进。

交付前核对实际结果、未关闭问题和证据限制，受影响公共资料与实现一致。长期只保留后续确有用途的概念、理由、合同或接受设计；完整任务规格无需全部转为永久文档。仅设计完成、仍有未实现要求或唯一依据时继续保留本地资料；清理依明确请求。

## 变化、保存与恢复

材料变化暂停受影响派发和写入，交回当前用户协调者完成 Design；按 [协调实施](references/coordinated-build.md) 同步相关任务与在途执行者，重新核对受影响结果。独立部分可按原授权继续。

有回退价值或用户要求提交／整理历史时，读取 [Checkpoint 与提交](references/checkpoints.md)。本地实施授权不包含 commit、push、历史重写、部署或数据回滚；需求未完成默认不推送，完成后也须适用授权。

恢复核对真实工作区、在途任务、原始范围、累计预算和停止点。取消按实际授权处理本任务未完成变更，保护无关工作；不自动删除过程资料。
