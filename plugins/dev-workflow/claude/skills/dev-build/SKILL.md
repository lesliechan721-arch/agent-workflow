# Dev Build

协调当前授权范围的实施闭环。直接使用时也能从请求和现有资料建立工作，无需父流程私有状态。

## 准备实施

1. 读取目标、实际确认或批准、当前 Spec/issue、规范性附件、接受设计和任务。确认材料依据及实施授权，保留任务原始审查基线。独立调用时可以从明确请求开始，无需父流程状态；已有资料位置继续沿用。
2. 当前请求或有效确认已充分时直接复用；存在材料缺口或冲突时，由当前用户协调者使用 `decision-shape` 按下方要求对齐，再准备依赖该决定的任务；已确认结果缺少代码入口、依赖或任务安排时，调查或用 `dev-breakdown` 准备下一批任务。核对任务对适用规范的读取范围、关键条件、共享约束和验收，确保新上下文不依赖作者私有记忆。远期任务逐步展开。
3. 有持久规范和任务需要交接时，在首次产品实施前按 [Checkpoint 与历史](references/checkpoints.md) 处理当前规范、确认来源及首批任务的实施基线；已有等价保存可复用。准备完成以任务可执行和所选保存方式处理完毕为准，范围内拆分通常由协调者决定。

## 实施与集成

当前上下文足够的机械修改直接执行并验证；受规范、设计、接口或有界修复约束的工作项使用 `dev-implement`。多个工作项具有独立验收或交接价值、局部工作明显占用协调上下文，或用户要求委派时，读取 [协调实施](references/coordinated-build.md)，在权限与工具具备时默认顺序委派子代理，独立性和集成收益明确时才并行。

接纳结果时核对实际 diff、Ticket 验收、适用规范与设计证据，再执行组合验证。保留任务正文，实际结果附着其后；tracker 不足以支持恢复时使用 [工作索引](assets/work-index-template.md)。

共享基础即将供多个下游使用、风险或迁移转换、代表性设计推广，以及错误会造成显著返工的集成结果可选为 milestone。读取 [里程碑审查与推进](references/review-planning.md)，完成验证、授权保存和独立审查后再解锁依赖。普通工作项执行相称验证。

## 交付核验

整体实现与集成验证完成后，使用 `dev-review-code` 对原始任务范围的完整当前结果进行双轴独立审查，提供原始用户来源、有效规范及附件、接受设计、任务与可访问证据。修复由本 Build 协调，实质问题关闭且覆盖充分后交付；同一结果不因返回外层 Workflow 再重复审查。

## 主动判断与权限

完整交付请求中的本地实现、验证和有界缺陷修复按现有授权执行；只审不修的请求保持只读。已有实质问题需要修复时读取 [Review 修复](references/review-repair.md)，说明适用预算并按证据续修或提前暂停。

选定 milestone 时，主动确认本任务的本地提交授权；其集成结果验证后默认保存 checkpoint，再审查固定范围。提交安全、明确无提交路径与历史整理见 [Checkpoint 与历史](references/checkpoints.md)。委派、成本和外部动作继续受当前平台与项目权限约束。

## 新证据与对齐

新证据产生未确认的用户行为或使既有决定失效时，先核对其影响，暂停依赖该决定的修改和派发。当前协调者说明原决定、新事实、后果及可行选择。有外层用户协调者时交回该协调者，由它使用 `decision-shape` 对齐受影响主题；独立调用 Build 时，当前代理使用 `decision-shape` 完成对齐。只提供本次缺口和必要的已有依据，当前主题的有效结论继续复用。

获得实际答复或明确委托后，更新受影响 Spec、Ticket 与验收；材料变更完成相应独立审查与批准。向在途相关子代理传达当前依据，确认它已接收或安全结束后再接续同一范围，重新核对已完成的受影响结果。对齐不刷新预算或清除用户停止点。保持已确认结果等价的局部工程变化可自主处理。

## 交付与恢复

问题与审查结论均对照原始用户来源和当前有效决定。阶段结果不能替代完整交付审查，过去通过也只覆盖其仍然适用的范围。

记录实际结果、未关闭问题、验证限制和相关位置。需要持久报告时由本次协调者提供保存位置和历史要求。恢复时检查真实任务、代码与证据，沿用有效授权、已用预算及人类检查点。
