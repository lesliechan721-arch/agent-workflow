# 本地任务与项目资料

持久记录、原型、交接、恢复或结束任务时读取。内容在当前任务和交付后的用途，决定其维护位置。

## 当前任务的完整依据

默认使用仓库根 `.dev-workflows/<task>/`，已有明确本地位置优先。需要时，`spec.md` 及其附件保存本次完整目标，`task.md` 保存范围、确认来源、开放问题与进度，Ticket、Review、证据和探索原型放在相应子目录。小任务可在当前对话完成；按真实恢复和交接需要创建文件。

本地Spec保留已确认行为、条件、例外、精确技术决定、验收及实施自由。它说明本次对哪些既有合同作变更，未变部分引用原定义；已有明确公共规范按其适用范围维护，避免竞争的完整定义。任务Spec描述当前目标，代码与测试提供实现事实，用户确认不能由文件自述替代。

## 项目长期知识

默认按需维护领域词汇与少量重要决定，复用已有位置；`CONTEXT.md` 是领域词汇表，ADR保留非显然的选择、条件、必要理由和后果。普通行为可由代码、类型、测试和已有文档承载。

已有API、配置、操作、安全或架构资料确受变更影响时同步维护。用户明确要求或真实消费者需要长期设计资料时保留相应内容；不为每项需求创建一份永久的完整规格。已确定的技术约束仍须在活动任务中完整保存和落实。

探索原型在任务期间可留本地。不能由最终实现、测试或已有资料可靠恢复，而后续仍需要的接受设计，应在授权下保留必要产物、版本、范围和演示边界。不能仅保存“符合原型”的摘要后删除唯一依据。

## Git与权限

首次使用检查过程目录未被跟踪，并验证忽略规则。项目默认根 `.gitignore` 加入 `/.dev-workflows/`；个人配置或权限受限时，在获准范围采用本地exclude或先请求处理。已跟踪文件不会因ignore自动移出索引。发现已跟踪过程文件时先报告事实，取得具体清理授权后再处理，保留本地文件和其它暂存修改。

过程内容不暂存、不提交、不推送。最终暂存按具体路径核对，本地`.dev-workflows`与项目`.agent-workflows`配置是不同对象。权限或忽略条件未处理时可以先对话工作，不宣称已可靠保存。

当前文件支持同机恢复，不承诺跨主机或误删除恢复。提交、备份和独立审查提供不同保障；阶段转换与milestone不普遍要求commit，外部动作另依实际授权。

## 接手、变化与审查

交给实施者和审查者的是本次Spec及适用合同、明确引用的附件/原型、任务和项目事实。另一个checkout不会自动包含这些本地或未提交内容；核对真实可达版本，必要时在受控环境提供，或在同一工作区顺序执行。复制供读取不产生另一份可独立修改的规范。

目标变化时回到当前用户协调者，经实际回答或委托更新Spec、受影响合同、任务和验收，再使相关执行者采用新依据。原始基线、已用预算和用户停止点保持；不能靠改规范迁就实现。

活动任务Spec引用本地资料是正常交接方式，审查看完整性和真实可达性。长期项目资料若依赖将被删除的唯一必要信息，则属于交付缺口；两种生命周期分别判断。

## 完成、取消与清理

完成前核对当前完整要求已实现、验证与独立核验充分，受影响公共资料已同步。长期保留足够词义、重要理由和真实消费者需要的依据；不要求复制整份任务Spec或每条验收为永久文档。仅设计完成时，完整本地Spec与必要原型仍保留供后续实施。

取消或改向时核对本任务产生的项目文件变化，按用户决定处理已失效目标，保护无关工作。本地资料只在明确清理请求下处理；未完成工作、未关闭问题和唯一必要依据尚在其中时先说明并妥善保留。清理范围与权限以当前明确请求为准。
