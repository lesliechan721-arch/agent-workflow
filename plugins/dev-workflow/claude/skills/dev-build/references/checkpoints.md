# Checkpoint 与历史

只在已有明确 checkpoint 授权、项目明确要求，或用户要求讨论历史整理时读取。

## 保存点

在连贯集成结果通过相关验证、且对恢复或 Review 有价值时创建普通本地提交。使用项目现有 Git 能力，精确提交本任务范围，正常运行 hooks；范围混杂或存在进行中的 Git 操作时先报告。

checkpoint 只证明保存了某个版本，不证明独立 Review clean。需要阶段审查时另行请求；没有 commit 授权也可以对稳定 diff 审查。用户明确要求保存未完成 WIP 时说明失败/未验证状态，不能把它当已验证里程碑。

记录 Git 能力返回的 commit 与验证/Review 位置即可。代码 commit、后续 Review 报告和 work 更新无需伪装成同一个原子事务；不要让文件引用尚未存在的自身 commit。

授权本地 checkpoint 不包含 push、squash、rebase、force push、删除分支或回滚用户文件。

## 最终历史

默认追加提交，不重写已共享历史。用户/项目要求整理时，优先在最终验证和 Review 前完成；也可采用平台已有 squash merge 流程。

历史整理后，核对被审内容、Spec 和目标基线。只是 SHA 改变且内容/审查上下文可证明相同，可更新引用并执行政策要求的检查；内容、冲突解决或集成基线影响结果时重新验证和审查。不能证明一致时保守复核。

squash 会隐藏主分支上的逐阶段历史。需要长期审计时按组织政策保留明确引用或记录，否则不压缩。Git 保存点不替代数据备份、生产回滚和外部审批。
