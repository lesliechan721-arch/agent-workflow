# Dev Implement

完成当前已授权工作项。依据可以是当前请求、Spec、issue 或调用者提供的任务说明，不要求全局工作文档。

## 实施

1. 读取目标、边界、相关决定、必要代码和验收。委派时只接纳当前任务范围；关键行为未决定或所需上下文不可取得时说明缺口。
2. Review 修复先读取当前 blocker 和关闭条件，只修分配给本次任务的 blocker、必要影响面和直接 regression；未能关闭的项目必须披露。
3. 选择满足当前合同和仓库结构的最小完整改动。新增抽象、fallback、配置或相邻重构须有当前消费者、项目硬要求或真实缺陷依据。
4. 最终产物表达当前有效行为、接口和必要理由。保留必要安全/兼容约束与非显然 gotcha，不把被否决方案、Review 指令和修复历史写进产品内容。
5. 在稳定行为边界上优先使用 red-green。遵守项目测试价值门；没有规则时，测试保护可观察行为、公开合同、已知 regression、安全/数据边界或确定性工具合同。
6. 精确文案、私有布局、内部 prompt、全文 snapshot 或 hash，只有自身就是消费者依赖的公开合同时才锁定。
7. 实际运行与变化相称的测试、检查或行为验证，修复后再验证。报告已运行、未运行和结果，不以推测代替证据。

## 边界

当前工作项过大、材料行为或跨模块契约需要改变时，说明发现和受影响范围，不静默扩展任务。破坏性、远程、凭据、显著成本和不可逆动作需要明确授权。

独立工作时可保存必要任务笔记；协作时只更新分配给自己的产物，不争写其他任务的共享进度。是否执行后续工作项、Review、提交或部署由调用者和项目政策决定。

完成时说明变更、实际验证、未解决问题和重要发现。子代理还需提供调用者可以访问的变更位置或提交引用；无需固定 JSON 返回格式。
