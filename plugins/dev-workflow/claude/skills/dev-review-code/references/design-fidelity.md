# 设计与界面对照

当前变更涉及已接受的页面、图像、布局或交互要求时读取。

## 建立可比较条件

读取原型本体与接受记录，确认版本、适用页面/状态、必须保留内容、允许差异及演示边界。来源只明确接受方向时，先区分已确定关系和仍需确认的细节。

在实际实现和原型中使用等价数据、身份、视口和操作状态。选择当前变化覆盖的代表性页面、关键编辑/选择路径和必要边界；已要求响应式行为时检查对应尺寸。配置、mock 数据和已声明演示简化按 Spec 的生产要求处理。

## 直接检查

分别核对信息分组与顺序、内容优先级、操作入口和反馈、布局关系、滚动/响应式行为，以及与接口状态的联动。阅读源码用于解释现象，实际页面或可访问输出用于证明用户体验。

功能测试、无异常、无溢出和按钮可点击分别证明局部事实。视觉/交互要求需要对应观察；截图需要实际比较，不能只凭文件存在判断符合。

使用语义观察、代表性截图、DOM/可访问树或有针对性的行为测试支撑结论。验收面向已接受的可见关系，私有 DOM/CSS 可以等价变化；精确像素或字节一致性仅在用户确实要求时检查。

## 记录证据与限制

给出设计状态、实现状态、对应或差异、材料影响和关闭条件。未打开的页面、不可用环境或无法复现的条件如实说明；源码可以支持确定问题，但不能证明尚未观察的视觉一致性。

原型含演示简化时，验证生产实现同时满足真实数据、保存、错误和权限合同。当前 evidence 仅支持部分要求时，只对该范围作结论。
