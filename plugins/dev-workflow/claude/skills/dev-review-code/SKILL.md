# Dev Review Code

审查当前变更及其实际依据。完整双轴结论由两个独立判断来源的有效证据共同支持；复审可以组合本轮检查与经核对仍适用的旧证据。审查本身不授予修改或后续操作权限。

## 当前职责

- **组织完整审查**：先核对当前需要的覆盖、已有证据与本轮执行者。首次完整审查建立两轴独立判断；已有报告或复审请求先按 [复审](references/rereview.md) 确定缺失覆盖。当前满足本轮独立条件时可承担一轴，先形成自己的判断再读取另一轴结论；其余缺失判断使用本轮已分配的合格执行者，没有时再委派。当前参与过设计、实施或修复时只协调；两轴都缺时分别派发。
- **执行已分配的审查轴或补充范围**：直接完成或续接本轮未完范围，按对应方法读取资料、查证并报告；其它轴及整体结论由组织者汇总。发现职责外的重要风险可以提示，但不据此重建完整审查。

每轮新查证使用不继承作者及上轮审查会话历史的干净上下文，不恢复旧 reviewer 会话作为新判断来源。必要产品资料、原报告与旧 finding 继续可读；读取可核验资料不等于继承旧会话，作者自证和预设结论仅作线索。隔离不足或缺少独立轴时，如实限定整体覆盖。

## 固定范围与来源

1. 明确基线、当前版本、请求覆盖的工作及验收。按实际范围包含相关已提交、暂存、未暂存和未跟踪内容；不能从材料确定且会影响结论时先询问。
2. 读取原始需求、Spec/issue、有效决定和评论、项目规范、已接受设计及真实代码。追踪到原型、图像、接口或样例本体；冲突、缺失和来源权威不明处应说明。
3. 区分当前应交付内容、上下游相关影响和当前范围外内容。组织者向本轮各轴审查者提供固定目标、明确分工、必要可访问依据及验证条件；已受委派者在当前上下文读取并执行，两个轴可并行或顺序完成。

## 双轴实证审查

当前审查者执行所分配的轴；完整审查由组织者确认两轴都有对当前结果仍适用的独立证据。

- **需求与设计符合度**：按当前材料要求核对预期与实际，寻找遗漏、未批准偏离、scope creep 和验收缺口。涉及 UI、交互、图像或原型依据时读取 [设计与界面对照](references/design-fidelity.md)，直接检查实现与被接受的设计。
- **工程质量与项目标准**：读取 [最小完整实现与有效测试](references/engineering-quality.md)、变更及必要调用链，检查正确性、安全、故障与并发、数据和兼容边界。核对新机制、依赖及测试是否服务当前需求，报告无当前用途的复杂度与重复验证的具体代价；项目已声明不追求的低价值风险不升级为必修扩展。

一次报告当前证据支持的实质问题，每项说明证据/位置、材料影响和可验证关闭条件。等价且更小的修复方式可满足关闭条件；改进偏好与缺乏当前依据的扩展建议单独呈现。

## 汇总与交付

单轴或补充审查子代理返回实际检查、沿用依据、问题和限制；组织者汇总两轴，各自判断保持可辨，同一问题可交叉引用；有争议的有效问题依据事实解决。

使用 [报告模板](assets/code-review-template.md) 中对应本次范围的部分组织人读结果。区分直接观察、实际运行、已核对适用的旧证据与未验证内容；确定的问题和证据不足可以同时存在。缺少规范依据时仍可做工程审查，需求符合度相应保留判断。

核对审查结束时目标是否仍一致。缺少必需独立上下文或实际验证能力时说明未完成的覆盖，已发现问题继续报告。默认只在对话中交付；明确要求保存时采用给定位置或确认的项目约定。被审源码、测试、需求和工作状态保持原样，后续行动由用户或调用者决定。
