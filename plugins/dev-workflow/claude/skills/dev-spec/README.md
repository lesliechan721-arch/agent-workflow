# Dev Spec

将已确认需求与接受设计写成可直接人审、可交接实施的规格，也可按审查意见修订现有规格。

新写或实质重组时，在编写前直接采用 `explain-for-review` 的阅读与保真方法，不依赖 Design 先调用它。主 Spec 说明改变、场景、取舍、风险与验收；必要接口、精确规则与原型约束保留在正文或可达附件中。局部修词不重做完整呈现，额外阅读页只在确有导航或反馈需要时生成，不成为第二份规范。

新增机制会与更简单方案比较，保留必要安全、兼容和恢复约束，局部工程选择留给实施者。已确认设计不擅自删改；缺少重要决定或证据时说明缺口，获准草稿仍标明未决，不补造批准。

按请求交付正文或文件；普通持久任务默认 `.dev-workflows/<task>/spec.md`，规格及附件仅本地保存。获准维护的公共合同原位更新，未变定义引用已有来源。本能力不自动启动审查、实施、提交或推送。
