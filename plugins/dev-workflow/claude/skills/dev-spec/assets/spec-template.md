# <主题>规范

优先在项目现有规范中修订相关主题。内容按用途选择，主文与纳入的规范性资料表达完整当前目标；项目实际支持程度需要实现证据。

## 目标、范围与阅读入口

用户结果、适用对象和重要条件。所有需要用户判断的行为、兼容、安全、数据和成本后果清楚可见，相关精确定义可继续展开。

## 行为、条件与例外

按场景、表格或关系表达完整当前合同；保留已定值、单位、建议强度及允许变化。原型需要标明接受版本、页面/状态、保留关系和演示边界。

## 精确规范与设计

已确定接口、类型、数据/状态、模块责任或必要逻辑；规范性附件说明范围和读取目的。长期需要的设计和约束保存到项目可维护位置。

## 验收与实施自由

真实结果如何证明要求，环境和数据前提；哪些局部工程选择自由，哪些已经确定。实际测试结果、任务拆分与进度由本次任务记录。

## 相关主题与稳定依据

公共合同指向其当前定义，词汇/重要决定链接相应资料。保留足够的必要理由，长期规范不能只依赖本地任务会话。未决定部分清楚说明适用限制；本次审阅变化和批准范围在交付说明呈现。
