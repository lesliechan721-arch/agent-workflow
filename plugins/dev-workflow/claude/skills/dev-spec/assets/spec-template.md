# <功能名称> Spec

## 决策摘要

用几句话说明用户最终获得什么，以及当前有效的主要取舍。

## 结果与范围

- 预期结果：
- 本次包含：
- 不在范围：

## 用户可观察行为

使用少量代表性场景说明正确结果。不要穷举所有边缘情况。

## 材料决定与不变量

记录公共接口、数据、兼容、安全、失败语义、迁移或跨模块责任等必须保持的决定。正面陈述当前合同，不复制讨论顺序、reviewer 指令或已被替代方案。

## 验收与验证 seam

说明从哪里观察正确结果，以及哪些测试或证据足以判断完成。

## 风险与授权

记录需要用户理解或单独授权的风险、成本、外部副作用和回滚原则。

## Agent discretion

明确列出交给实现者决定的文件组织、局部算法、类型设计、测试组织和任务顺序。

## Evidence

链接仍支撑当前决定的 Prototype、研究或 ADR。被替代方案和实验过程只在安全、兼容、迁移、回滚或避免高概率重复决策需要时保留，并留在 Evidence 或 ADR 中，不复制为规范。

## Open decisions

批准前应为空，或只保留明确委托给实现阶段的非材料事项。使用 `material-decision`、`evidence-needed` 或 `fact-gap` 标注仍阻塞的内容。
