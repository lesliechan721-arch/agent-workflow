# 代码修复

## 授权与预算

完整实施交付通常涵盖本范围必要缺陷修复；只审查、明确暂停或更窄授权保持。开始续修时说明适用范围与剩余预算。新自动修复授权未指定次数时最多三轮；已有一次授权、较低上限、已用额度与提前停止决定继续有效，增加上限需要新授权。预算耗尽或原授权尚未恢复清楚时，停止产品写入。

一轮是一批有界修改、相关及集成验证，再更新当前完整约定范围所需的独立核验。该批首次产品修改即占用一轮，多个实施者共用；验证失败或审查未完成仍计入，复用旧证据不退还轮次。已知工作先实施的首批也计入；Build 进入本循环前的正常实施不追溯计入。

## 本批修复

1. 对照原始用户来源、当前有效决定和实际证据核对问题与关闭条件。现有共识内的缺陷、必要影响面和直接回归进入修复；需要改变用户结果、接受设计或风险时暂停受影响工作，返回原依据、已验证结果、缺口与影响，不自行修改规格或启动设计。
2. 使用 `dev-implement` 完成当前批次，检查实际 diff、相关及集成验证。协调相同范围写入，明确修复后的当前版本；改动满足已确认关闭条件，不为审查偏好扩张范围。
3. 回到 [有界核验修复](methods/review-loop.md) 更新当前完整范围的独立覆盖，核对问题关闭与证据限制。仍有实质问题、存在新的修复或诊断依据且预算足够时继续，说明上一轮结果、剩余风险和下一步依据。同一问题反复且无新依据、结果显著恶化、需要新决定或越过权限时提前暂停。
