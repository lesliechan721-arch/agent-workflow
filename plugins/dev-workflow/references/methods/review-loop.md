# 有界核验修复

供已启动的 Review Loop、Build 或 Workflow 在明确代码范围内采用。当前协调者管理本范围修改与核验；`dev-review-code` 拥有独立判断和复审方法，`dev-implement` 完成有界修改。本方法不承担需求设计、多任务实施协调或整体产品交付。

## 范围与起点

读取请求、原始范围与代码基线、需求及接受设计、现有问题和报告、实际代码、权限与已用预算。没有 Spec 文件也可依据真实要求和公共合同工作，影响结果的缺口先核对。沿用实际授权、项目及运行时上限、已用额度与停止点；显式选择或采用方法不扩大只读及更窄授权。初审、只读诊断与专项补审仍受时间、成本和权限约束。

| 当前输入 | 起点 |
| --- | --- |
| 已明确、获准的工作项或 finding，要求完成后核验 | 核对当前适用性和必要复现，先完成本批修改与验证，再独立核验 |
| 当前需要发现并处理问题 | 使用 `dev-review-code` 取得所需独立判断，再按实际问题决定修复 |
| 已有报告或核验在途 | 问题作为线索；通过结论须核对当前适用性，并补缺失覆盖 |

用户指定的有效先后顺序优先。已知问题不要求先重做完整初审，已失效或不成立的 finding 先查明，不重复修改。需要新的产品决定或多任务协调时返回缺口，由用户或当前调用者处理。

已知获准工作需要先实施、审查发现需修复的实质问题，或恢复已有修复范围时，在任何产品写入前读取 代码修复（`references/code-repair.md`），核对预算与本批方法。恢复时预算已耗尽也命中此条件；同一上下文已读且仍有效的内容直接复用。

## 独立核验

1. 使用 `dev-review-code` 取得或更新完整约定范围的必要覆盖，提供实际变化、接受设计，以及旧报告的原版本、范围和其后累计变化。由审查能力判断补充或全面检查及执行者，不传递作者或上轮 reviewer 会话作为新的独立判断来源。资料与旧 finding 保持可访问，作者自检不替代独立证据。
2. 核对有效问题是否关闭、目标是否仍一致，以及本轮查证与仍有效旧证据是否覆盖当前完整范围。未经解决的有效问题不因后来乐观结论而消失；没有实质问题且覆盖充分时可零修改结束。
3. 证据或独立审查条件不足先补条件，仍不足时报告缺口；需要新的产品决定时返回原依据、已验证结果、缺口与影响，不自行修改规格或启动设计。预算耗尽也不降低交付标准。

## 结果与恢复

返回实际范围与版本、修改和验证、当前核验依据、未关闭问题及覆盖限制，区分本轮查证和复用证据，不把复用称为两份新全面审查。发生修改时说明累计已用额度及继续或暂停原因，结果由调用者采用。

在对话、已有 Work／tracker 或必要报告中保留原范围、授权、已用额度、结果与停止理由，不强制新建过程文件。Skill 重入、换会话、执行者更换、commit、报告改名或新 Build 目录不重置同一未完授权；事实不明先恢复。后续任务、整体交付及外部动作依各自授权处理。
