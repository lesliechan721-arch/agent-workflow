# Codex Enhance

在 Codex 中组织通用委派、技术第二意见和大范围事实调查。当前任务负责人采用 Skill 方法，执行者直接完成有界任务。

## 安装

```bash
aw install codex-enhance -p codex
```

仅支持 Codex。项目启用复用用户级共享 Skill 配置，不产生独立的项目执行配置。

## 包含的 Skill

| Skill | 什么时候使用 |
| --- | --- |
| `codex-subagent-guide` | 已允许委派，需要选择执行配置、传递上下文、等待或续接 |
| `codex-advisor` | 已安排技术第二意见，或重要判断卡点会影响行动 |
| `codex-explore` | 需要在大范围或陌生资料中查找并核验事实 |

Advisor 和 Explore 通过 Guide 委派。普通有界任务可直接使用 Guide；少量已知文件的定向读取通常直接完成。

## 典型用法

```text
使用 codex-subagent-guide，把这项已授权的实现交给一个执行者。
```

```text
使用 codex-advisor，对当前兼容方案取得 design 第二意见，并核验重要建议。
```

```text
使用 codex-explore，调查这个陌生仓库中的配置读取路径，给出可核验的文件定位。
```

## 配置与执行

四个通用 profile 和三个探索 profile 保持原默认值。所有 profile 定义执行器、模型和推理强度；省略执行器按 `native` 解释。执行器也可使用 `subagentCommands` 中的稳定 key。执行器表默认空，默认配置不会启动外部服务。

`advisorProfile` 是通用咨询配置，默认 `gpt-6-astra` / `high`。design、debug、review 可分别设置 `advisorDesignProfile`、`advisorDebugProfile`、`advisorReviewProfile`。运行 Skill 只展示已经配置的选项；默认只有通用项，不列出未配置字段或回退说明。专属配置整体使用，非法配置或不可用执行器会报告错误。

先进行一次有界咨询。只有新证据或具体追问能推动任务时才追加；当前任务明确的次数和费用预算仍生效。咨询执行者只读，不能批准、修改或再次委派。旧 `advisorPolicy` 不再控制咨询，仍需的禁止或次数限制须由当前任务明确给出。

native 直接使用当前宿主工具和角色。配置或角色更新后，宿主可能需要受支持的刷新或新会话；安装成功不证明当前会话已加载最新版。

外部执行使用前台调用，明确提供执行配置、指令文件和任务文件。可以使用各 Skill 的默认指令，也可提供符合任务授权的自定义指令。指令与任务数据分开传入；外部程序可能访问网络、处理材料并产生模型费用，须使用可信且已获准的服务。

附带的 Codex 外部执行器仅支持只读任务。任务须携带必要项目约束；配置了执行器不代表已获得资料外发或写入许可。实际工具权限和隔离能力以所选服务及当前环境为准。

## 配置生效

保存设置须 apply 后才供新的外部调用使用；未 apply 时继续使用旧生效值。配置或安装失败可能只影响部分产物，按实际诊断通过正常 sync 或 reinstall 恢复。已启动调用继续使用原输入和执行句柄。

## 边界

- 写入取本次授权与真实工具权限的交集。Advisor 和 Explore 始终只读；建议代码和候选 patch 不等于已实施。
- workspace 的后续读取访问真实工作区；bundle 只交付明确选择的当前材料。只读指令不单独证明技术隔离。
- 等待超时继续同一原生 handle 或宿主 session，不增加生成次数。活跃外部调用保留已读取的输入和原进程句柄。
- 前台外部调用不支持脱离宿主运行或跨父会话恢复。服务终态或停止范围无法确认时保留 unknown；退出码 0 或非空文本不能单独证明成功。
