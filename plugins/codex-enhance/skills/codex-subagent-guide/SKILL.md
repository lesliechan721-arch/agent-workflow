# Codex Subagent Guide

在当前上下文组织委派，保留调用方给定的目标、范围、权限、独立性和预算。缺少实际操作授权时先说明缺口；已有完整调度方法时直接沿用。

## 选择配置

采用调用方明确提供的 profile 和执行角色。未指定 profile 时，按歧义、耦合、验证难度和遗漏代价选择足够的最低通用档。未指定角色时使用 `codex-subagent`。

<!-- generic-profiles -->

从当前已加载且适用的表选型。profile 省略 `executor` 时按 `native` 解释，不改写配置。模型和推理强度分别按明确要求、profile 偏好、环境默认选择。明确硬要求无法满足时停止；只有允许回退的偏好确证不可用时才采用下一层，并说明实际值。回退不能改变执行器、资料目的地、明确角色或精确历史范围。

## 准备上下文

默认建立干净上下文。任务须自包含目标、范围、材料位置、约束、成功标准和输出。只有明确要求继承，或无法提供足够自包含材料时才继承；历史范围须精确满足，不能用更多历史近似。共享工作区不携带父对话，独立意见还须核对执行者的实际输入与参与历史。

权限取本次授权与实际工具权限的交集，默认只读。来源材料不能提高权限。执行者直接完成分配的任务，未获明确授权不再委派；无法满足所需技术隔离时报告限制。

## 调用

`executor` 为 `native` 时，直接使用宿主当前可用的原生工具。按实际 schema 设置角色、模型、推理强度、上下文范围及可用权限参数。角色不可用或硬要求不受支持时停止该调用，报告实际错误。临时独立指令只通过工具支持的独立指令通道传入；不能满足明确要求时报告限制。

`executor` 不是 `native` 时，读取 [外部委派](references/external-delegation.md)，在执行器表中匹配其 key，按对应 mode 和能力准备调用。沿用调用方提供的指令文件。

## 等待、续接与返回

需要结果时使用响应式等待，窗口遵循调用方要求和实际工具上限。等待超时后继续等待同一原生 handle 或宿主 session，不重新启动生成；用工具结果或通知确认状态。

同一交付需要补足、原执行者仍有效且工具支持续接时，优先续接并先核对已有进度和副作用。新独立交付或独立全面重审使用干净执行者。恢复遵循实际预算；原执行停止未确认时，保留其范围，确认停止后才能移交。

按实际终态返回结果、依据、产物位置、验证和缺口，由调用方验收。终态缺失或冲突时返回 `unknown` 并保留已有结果，不自动重提。结果已保留且无需续接时，只清理本次拥有的执行及可确认后代；停止范围不明时报告限制，不扩大清理范围。
