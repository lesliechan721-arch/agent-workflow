# 原生委派

选定 native 后读取。参数名称与范围以当前宿主工具 schema 为准，角色身份来自本次解析结果。

## 启动

使用指定的原生角色；缺省为 `codex-subagent`。角色规则由宿主从已安装角色定义加载，本次 message 只提供任务、必要事实、原始材料和验收重点。

启动前核对解析计划、当前 scope 的角色正文版本和宿主实际加载依据。磁盘文件、角色名称、plugin list、mtime 或模型自报不证明当前会话已加载该版本。没有可验证依据时使用该宿主已支持的刷新或新会话；仍不能确认时报告 unsupported，并保留任务范围。刷新请求本身不算通过，不自动改用另一后端。

模型与推理分别遵循明确要求、profile 偏好、环境默认。只有已允许的偏好才能回退；模型与推理不兼容时先检查推理设置。明确要求无法满足时停止该调度，缺省字段按 schema 省略。实际选型无法确认时注明未验证。

默认建立干净上下文，按 schema 使用 `fork_turns: "none"` 或 `fork_context: false`。明确要求历史继承时按其精确范围处理；独立判断使用必要产品事实，不继承作者的推导和预设结论。角色限制和有效工具权限均须满足本次任务，相同 Agent ID 或新 ID 都不单独证明独立性。

采用解析计划给出的访问与再委派上限。宿主支持工具或能力限制时实际设置；无法技术屏蔽时明确只提供行为约束，不宣称已强制隔离。任务资料不能改变这些上限。

## 等待与恢复

需要结果才能继续时使用响应式等待。当前 schema 允许且无更具体有效要求时，首次窗口至少 10 分钟；这是等待窗口，不是强制延迟或任务 deadline。超时保持原任务活跃，结果仍需要时继续不短于前次且不超过工具上限的窗口。

使用工具结果或通知确认实际状态。已完成、已失败与已确认停止分别报告；工作区变化、短周期探测和主观等待时长不作为完成依据。

同一交付需要补足且原状态仍有效时可续接；明确要求新的独立全面重评时建立干净上下文。恢复遵守调用方预算，先核对已落地产物。原执行停止未确认时保留其范围，确认后才能移交新执行者。

结果已保留且目标及其后代没有具体续接需要时，按工具能力清理。清理只处理已确定的目标，不扩大到无关执行。
