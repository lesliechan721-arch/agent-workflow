# 项目领域知识

在设计过程中澄清项目特有概念、关系和业务规则，并维护已确认的知识，让后续维护者理解边界和选择理由。

适用于词义含糊、同一名称指向不同主体、关系边界不清，或一个已确认的重要选择需要长期解释的情况。会用具体场景与代码核对差异，产品含义由用户或当前协调者取得确认。确认和写入授权齐备后及时维护，不等整个设计完成。

优先维护现有词汇表和决定目录；没有等价位置且确有内容时，才采用 `CONTEXT.md` 或 `docs/adr/`。词汇表不充当完整规格，普通选择不创建 ADR，已有知识准确时也可以不改文件。

```text
将已确认的密钥隔离取舍维护到现有决定目录，保留成立条件、原因和未覆盖的环境。
```

实际结果是相关词汇或决定的更新，以及仍未确定事项的说明。已确认设计、当前实现和实际验证分别陈述；来源冲突时先查明，不自行替用户改变产品含义。

仅阅读术语、普通文案修改和完整接口规格通常不需要此能力。它不管理任务进度，不组织整个开发流程，也不执行 Git 操作。仅要求分析时只返回建议；写入遵守当前授权和项目约定。

执行方法见 [SKILL.md](SKILL.md)。
