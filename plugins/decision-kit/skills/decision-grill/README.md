# Decision Grill

通过有依据的问答，把当前计划、方案或重要决定想清楚。独立调用可完成一个访谈；受委派时只负责给定范围的问答与答案确认。

## 适合使用

- 当前有需要用户回答的材料选择，或调用方已将该问答交给本能力；一题与多轮均可。
- 需要比较主要方案、取舍、失败路径和验证方式。
- 希望压力测试一个计划或重要技术方向。

## 工作方式

Skill 会先调查事实，再把推断的共享决策方向（Decision frame）在第一个材料问题之前或同轮展示给你。若多个合理方向会改变推荐，它会先用简短后果对照请你选择方向。

每轮优先处理会影响多个后续分支的上游问题。首屏说明当前决定、现在决定的原因、推荐和主要结果差异。默认使用简短结果对照或具体场景；已有复杂材料难以理解和反馈时，借助 `explain-for-review` 调整呈现，再继续当前问答。解释不替你作决定；具体候选或实验更能校准答案时，返回证据需要，不靠增加问题替代原型。

当相关问题已决定、明确委托、转为需证据或已接受后果地延期时，交付当前结果。需证据的问题仍未决定，访谈结束不表示整个主题已对齐。真实回答已清楚且汇总没有新增含义时可以直接结束；新的综合解释、条件或用户明确要求的最终记录再请求核对。

## 不适合使用

- 只需要一次性解释、比较或评审。
- 必须看到、运行或操作候选方案才能决定。
- 只需要测试、压测或外部证据确认技术事实。

已有保存授权和明确位置时，可以先保存用户明确确认的一批决定，同时保留开放问题并标明整体记录尚待确认。批次保存不扩大确认范围；保存仍需实际确认与授权，后续原型和产品实施由调用者组织。
