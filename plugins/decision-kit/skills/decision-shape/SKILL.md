# Decision Shape

负责当前主题的需求覆盖、方法选择、结果整合与对齐完成判断。问答、原型和知识维护各由对应能力完成；不编写完整实施规格或启动产品实施。

## 先看全貌

读取原始请求及补充、当前资料、项目事实、适用的既有词义与重要决定、接受证据。保留原始要求的可访问位置，整理后的摘要不替代来源。明确本次要达成什么、在哪里结束，以及优先保证什么、可接受什么代价。已有有效方向直接复用；方向不清且会改变选择时，用 `decision-grill` 取得实际回答，不把模型推荐当作共识。

先广后深地检查当前范围，不因最先发现的一个问题而忽略其他要求：

| 检查面 | 找出会改变结果的内容 |
| --- | --- |
| 目标与范围 | 用户要完成的结果、成功判断、明确排除项、各条原始要求 |
| 人与领域 | 使用者、角色与权限、核心概念、关系和必须保持的业务规则 |
| 行为与体验 | 主要使用路径、输入输出、状态变化、界面信息与操作、必要边界和失败恢复 |
| 约束与证据 | 现有合同与数据、兼容或迁移、安全与性能限制、验收、尚未验证的假设 |

检查面是防漏方法，不是逐项问卷。只展开与当前任务有关的部分；可查事实自行调查，已确认内容不重问。单项任务可以只用一两句话说明已定内容和当前缺口。

向用户呈现简短的主题全貌：已确定什么、有哪些明确问题、哪些范围内主题还不能具体化，以及哪些明确在范围外。已有精确问题即使受前置条件阻塞，也保留问题与依赖；尚不能具体化的主题不提前拆成细节。范围内尚未展开不等于已排除。

## 按缺口推进

从前提已明确的问题开始，优先解决影响多个后续选择的上游问题。向被采用能力提供当前主题、共享方向、已有决定、具体问题、必要来源与授权；同一上下文直接复用，不为方法调用创建新会话或交接协议。

| 当前缺口 | 动作与返回结果 |
| --- | --- |
| 事实尚不清楚 | 调查代码、文档或环境，保留实际事实和未验证范围；不让用户凭偏好回答技术事实 |
| 需要用户权衡、确认条件或消除理解差异 | 使用 `decision-grill`，包括只有一题的情况；取得真实答案、委托或明确未决 |
| 布局、信息层级、操作、状态关系或可行性需要具体证据 | 使用 `decision-prototype`，给出问题、观察重点和结束条件；消费实际候选、实验结果及接受范围 |
| 领域词义或关系模糊、与现有知识冲突，或重要取舍需要长期理由 | 使用 `project-context` 澄清模型或维护知识；消费明确含义、待确认问题和实际更新位置 |
| 已有复杂材料的关系、取舍或后果难以理解和反馈 | 使用 `explain-for-review`，提供读者问题、完整来源及当前状态；采用实际呈现与反馈，不把阅读当作确认 |

体验是需求的一部分时，主动检查低成本证据能否显著减少误解或返工。新界面、关键操作或复杂状态的文字描述可能掩盖不同理解，不必等到证明文字无效或用户反复要求后才给候选。采用能区分答案的最低成本证据；已有充分接受证据直接复用，纯文案且含义已清楚时不强制制作原型。解释已有材料交给 Explain，比较尚未决定的行为交给 Prototype。写入、实验和外部动作仍依当前授权；条件不足时保留缺口，不假装已完成。

领域知识贯穿对齐过程。出现新概念、关系或含义冲突时，让 Context 澄清差别；涉及产品选择的部分由 Grill 取得答复，不另起重复访谈。已确认且值得长期保留的知识，由 Context 在写入授权内及时更新现有位置。普通任务要求留在当前记录，已有知识足够时直接复用。

## 整合后再检查广度

每批答案或证据返回后，更新对应主题与依赖，再查看其他未解决主题。Grill 的问题结束、原型被接受或知识文件写好，都不单独代表整体对齐完成。新的证据让模糊主题变得可具体讨论时，纳入下一批问题；推翻已有决定时只重开受影响部分，保持其他确认与授权限制。

整合保留实际确认来源、条件、例外、精确值、约束强度、理由及委托边界。原型保留接受版本、适用页面／状态、须保持的关系、允许变化和可重放入口；知识定义引用其维护位置，不再复制一份长期真值。建议、调查事实和未决内容各保留其性质。

结束前双向核对：每项实质要求都有对应决定、开放问题、明确委托或有依据的范围处理；每项新增硬约束都有用户要求、实际确认、适用项目合同或明确委托支持。核对主要场景、相关失败路径和验收，以及证据接受范围、知识实际更新或待写位置、来源可达性。范围内未展开主题、冲突与可能推翻方向的证据不能静默消失。延期保留用户接受的后果与适用的重新评估条件。缺少依据时交付具体缺口，不宣称完整。

用户对明确问题的答复可以直接确认该问题。汇总仅复述原意时无需再确认；跨主题整合产生新的实质含义时，用 Grill 核对变化。用户要求最终记录确认时遵循该要求。

## 保存与交付

沿用调用方给定位置、已有主题记录或项目约定。长对齐、原型或跨上下文前，在授权范围内保存主题全貌、当前决定、来源与剩余问题；已有草稿能完整承载时更新同一份。独立请求记录且没有现有结构时使用 Shape 模板（`assets/shape-template.md`）。无需恢复时在对话交付，不强制工单、索引或额外文件。

交付当前有效结果、确认与委托范围、开放问题、证据及知识位置，使接手者无需私有历史即可恢复。保存草稿不表示批准，接受设计不新增实施权限；后续规格或执行交回调用者。
