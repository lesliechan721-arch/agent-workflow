# 项目知识布局

维护领域语言或重要决定，且需要选择文档位置或记录形式时读取。

## 复用现有位置

优先用户指定位置，再沿用项目现有glossary、domain文档或决策目录；仅在内容确有价值而无等价位置时使用默认。单领域可采用根 `CONTEXT.md` 与 `docs/adr/`；项目已有多领域边界时在对应边界维护，不自行创建一套领域分区体系。

项目入口如AGENTS或领域索引只保留必要读取指针。其修改仍遵守授权和项目约定，不把全部项目规范复制进入口。

## 内容分别负责

- 词汇解释本领域含义、重要区别和范围；具体协议可指向已有公共合同、类型或行为测试，当前实施步骤留在任务中。
- ADR解释已确定选择、成立条件、必要取舍和后果。相关行为可指向已有合同、代码或测试；必要理由留在记录内，篇幅随实际含义，不为每个小选择建ADR。
- 当前开发目标由规格能力组织，默认保存在本地任务空间。已有API、产品或架构合同确受本次变更影响时，在对应位置维护；只有真实消费者需要时才新增长期设计资料。
- 实际操作说明、命令和测量结论随实现验证更新；已确认目标不自动成为“已支持”的事实。
- 本次未决、临时方案和实施状态由调用者的任务记录保存，不变成永久项目规则。

## 时机与变更

一个术语或重要决定已有实际确认且写入获准时即可更新。无需等待整个开发完成，也不因用户在同一主题回答了一项就推定其他未决事项已确认。

记录只覆盖实际确认范围。本次不实现某能力是任务边界，除非用户明确决定长期限制，不能推广成永久禁令。安全例外同样不得扩大到未授权主体或环境。

已有决定改变时按项目约定修订当前记录及规范；有必要的取舍理由可以保留，时间顺序和聊天往返不作为常驻知识。来源冲突先查明，不单凭最新修改日期作裁决。

## 交付检查

定义与决定有明确位置，材料条件、风险和必要理由完整。长期有价值的信息可以从记录及实际项目资料恢复，不依赖待删除的本地任务目录；不要求把整份任务规格转成长文档。已取消或未实现的目标不陈述为当前产品事实。
