# Decision Shape

面向用户或调用方委托的需求与方案对齐。先看清整体要求和剩余问题，再逐步解决关键选择，避免只深入一个问题而遗漏其他需求。

Shape 组织 `decision-grill` 的问答、`decision-prototype` 的早期候选与实验，以及 `project-context` 的领域建模和知识维护。文字容易掩盖不同体验时，会主动提供适当证据；词义或重要理由明确且获准保存后，及时更新现有知识。已有结果足够时直接复用，不强制每种能力都执行。

已有复杂材料难以理解时，使用 `explain-for-review` 提供保真的阅读与反馈入口；需要选择新的行为或体验时使用原型。呈现、实际答复与接受证据分别保留，不把阅读当作批准。

交付当前决定、成立条件、例外、确认来源、证据和知识位置。范围内尚未展开、需要证据、已延期和范围外的内容保持可辨；一次问答或原型接受不自动代表整体对齐完成。

直接访谈、单一原型或知识维护仍可独立使用对应能力。简单对齐可一轮完成；无需恢复时在对话交付，长任务沿给定位置或现有记录保存，不强制创建工单、Spec 或开发阶段。本技能不启动产品实施，写入及外部动作仍需相应授权。
