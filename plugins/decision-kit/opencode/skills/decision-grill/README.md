# Decision Grill

通过有边界的逐轮访谈把计划或重要产品/体验选择想清：先自行查明仓库事实、对可跑实验的技术分叉先实测再给推荐，只把真正需要人拍板的方向、业务规则与取舍按依赖逐轮抛出。

## 适合使用

- 需求、计划、业务规则或权限/恢复边界尚未想清，希望 Agent 主动发现遗漏分支、隐含假设与后果。
- 需要被有节奏地追问直到关键产品取舍全部落地。

## 示例请求

```text
使用 $decision-grill 围绕租户退出后的数据保留规则逐轮问我，先查明仓库现状与上游决定。
```

## 工作方式与边界

- **工作方式**：先只读自查已有代码与决定；可靠最小实验定案的问题先实测再推荐；前提矛盾或得不偿失时直说反对并给替代；每轮只问 1–3 个独立前沿问题并附推荐依据与代价，复杂已有材料妨碍理解时先调用 `explain-clearly`。
- **不适合使用**：明确限定的简单单项选择可直接对话回答；纯内部工程选型由工程设计处理；需要动手体验页面或交互候选改用 `decision-prototype`。
- **权限与副作用**：共识形成前不启动产品实施；仅在授权范围内保存决策记录，不修改生产源码。
