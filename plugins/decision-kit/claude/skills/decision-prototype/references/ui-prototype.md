# 界面原型

当空间组织、信息层级、操作入口或交互感受会改变决定时使用。

## 让候选代表不同答案

先说清本次比较的维度。通常两三个候选已经足够，差异应体现在结构、信息顺序、主操作或流程，而不是只更换颜色和阴影。已有方向只需局部修正时，不必重做一组候选。

尽可能呈现真实使用上下文：应用外壳、代表性数据量、关键状态和需要支持的屏幕尺寸。用户允许时可借用现有页面环境；否则在原型目录复现足以影响判断的部分，不复制整个产品。

先选方向，再提高保真度。只有动画、滚动、响应式或实际操作感受影响决定时，才为它们投入实现成本。

## 让反馈容易表达

- 方向选择用候选比较和简短后果说明，允许都不接受或提出组合意向。
- 用户需要指出位置时再启用标注，不提前要求所有候选都具备编辑器能力。
- 静态 HTML 可给关键区域添加稳定的 `data-prototype-id`，用于现有 Shell 的 DOM 标注。脚本型 HTML 使用隔离模式，不承诺同样的标注能力。
- 连续调整仅开放当前决定需要的少量受控参数；不要实现任意拖拽网页编辑器。

原型应可通过图片、单文件或项目已有命令方便重放。选择已明确时，停止继续润色并保存答案及必要限定。
