# Project Context

维护项目共享语言与值得长期解释的决定，让后续读者理解概念和边界；用户材料与实际项目事实是依据。

## 查明与归位

1. 读取当前问题、项目已有词汇/决定/规范和相关代码。一个词多义、用户说法与已有定义冲突时，用具体场景说明差别；可调查事实先调查，改变产品含义的选择向用户或当前协调者确认。
2. 已确认术语在原有词汇位置维护；没有等价位置且确有内容时，采用 `CONTEXT.md`。只保存项目特有定义、区别和适用范围，完整行为与接口指向对应规范。
3. 对长期容易被误解、确有取舍且未来更改代价值得说明的决定，记录必要理由、适用条件和后果。优先复用项目决策目录，缺少时采用 `docs/adr/`。普通局部行为可以直接进入其规范，无需独立ADR。
4. 需要选择位置、创建术语或ADR时读取 [项目知识布局](references/knowledge-layout.md)，按需采用 [词汇示例](assets/context-template.md) 或 [决定模板](assets/adr-template.md)。遵循已明确的文档编辑权限；仅要求分析时返回建议而不写文件。
5. 更新后核对定义及范围与真实确认一致，完整行为仍在明确的规范位置。决定已接受、实现待完成和已有运行证据分别陈述；现有代码的差异是待查明事实，不自动覆盖目标，也不能伪称目标已实现。

## 完成

新读者能在现有入口找到相关术语和必要理由；条件、例外、精确值与建议强度不因归纳而改变。只对当前已确定信息归位，仍未决的材料问题交回当前主题协调者。

说明实际修改、相应来源与仍待确定内容。编写规范、访谈组织、任务推进和Git操作由其当前负责者处理；本Skill不要求开发工作流的目录、阶段或状态。
