# Project Context

维护项目共享词义和值得长期解释的决定，以实际确认和项目事实为依据。

## 核对与维护

1. 读取当前问题、已有词汇/决定、相关合同和代码。可查事实先调查；一词多义或与原定义冲突时用具体场景说明差别，改变产品含义的选择由用户或当前协调者确认。
2. 词汇保留本领域的定义、区别与适用范围。重要决定只记录那些缺少理由会被误解、确有取舍且后续更改代价值得说明的选择；保留其条件、例外、必要理由与后果。
3. 需要确定位置或记录形式时读取 [项目知识布局](references/knowledge-layout.md)，按需采用 [词汇示例](assets/context-template.md) 或 [决定模板](assets/adr-template.md)。优先复用现有资料，仅在编辑获准后写入；只请求分析时交付建议。
4. 核对记录与实际确认一致，精确值与建议强度不因归纳改变。已接受目标、待实现内容和已验证事实分别表达；代码差异需查明，不能自动覆盖决定或证明目标已经实现。

## 交付

相关词义和必要理由在明确位置可找到，记录自身保留完整边界与适用来源。说明实际修改及仍需决定的问题，结束本次知识维护。
