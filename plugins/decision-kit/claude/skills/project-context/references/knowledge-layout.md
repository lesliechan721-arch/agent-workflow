# 项目知识布局

选择领域词汇或重要决定的位置、形式时读取。

## 位置与入口

优先用户指定位置，其次项目已有 glossary、domain 文档或决策目录。确有内容且无等价位置时，单领域可采用根 `CONTEXT.md` 与 `docs/adr/`；已有多领域边界则维护对应位置，不为本次记录新建领域分区体系。

项目入口或领域索引只添加必要读取指针，其修改仍需适用授权。已有定义的细节使用相关合同、代码、类型或测试的精确引用，必要含义和理由留在记录内。

## 记录范围

词汇按 词汇示例（`assets/context-template.md`） 表达项目特有含义；重要选择按 决定模板（`assets/adr-template.md`） 说明范围、理由与后果。普通选择没有长期解释需要时，不创建 ADR。

记录的适用性以实际确认决定：本次不实现某能力不自动成为永久禁令，一个环境的安全例外也不扩展到其他主体或环境。已有一项答复不代表其他事项同时确认。

## 变化与查证

已确认且写入获准的词义或决定可以及时更新。原定义或决定发生变化时，按项目约定处理当前记录及其直接引用，保留理解它所需的理由；冲突先核对确认与适用范围，不能仅按修改日期决胜。

后续读者应能从记录与可访问依据恢复必要含义。仅有目标决定或取消的方案，不能写成已支持或已验证的产品事实。
