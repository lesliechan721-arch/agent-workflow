# Decision Prototype

围绕一个明确的产品、布局、信息层级或状态交互取舍，制作最低成本的可丢弃原型，收集用户真实反馈并记录绑定版本的精确接受范围。

## 适合使用

- 界面排布、交互操作流、状态转换或权限行为仅靠文字难以拍板，想直接体验候选。
- 需要把 2–3 种实质不同的方案放进同一个切换器并排比较，或通过本机网页 Review 留下结构化标注反馈。

## 示例请求

```text
使用 $decision-prototype 做一个可操作的状态模型，让我确认撤销行为并记录接受范围。
```

## 工作方式与边界

- **工作方式**：先一句话定清要决定的问题与观察目标，按不确定性选逻辑演示、界面原型或隔离技术实验；需要结构化反馈时启动仅绑定本机的 Review 服务（默认 30 分钟有效），局部修订递增 revision，最后交付精确接受边界（适用页面/状态、必须保持的关系与允许变化细节）。
- **不适合使用**：仅为了理解已有复杂文档、规格或系统机制（不探索未定候选）改用 `explain-clearly`；纯内部工程实现选型由工程设计处理。
- **权限与副作用**：仅写入原型目录（默认 `.dev-workflows/<decision-id>/prototypes/`），明确标注为一次性临时产物，不覆盖生产源码；提交反馈或构建子代理完成均不自动等于接受或实施授权。

详细执行说明见 [SKILL.md](SKILL.md)。
