# 逻辑原型

当用户必须操作状态、权限或数据变化，才能判断模型是否符合预期时使用。

## 做成可理解的演示

- 把正在验证的问题放在可见位置。使用业务语言标注状态和操作，不让用户阅读内部对象或源码才能理解。
- 展示与决定相关的当前状态，以及最近动作改变了什么；原始 JSON 可以作为辅助，不作为唯一界面。
- 提供自由操作和少量引导场景。场景从已知初始状态开始，可以重置；自由操作和场景使用同一套逻辑。
- 覆盖一条常见路径，以及真正能改变决定的一种边界或非法操作。不穷举生产系统的全部错误。

只构造回答问题所需的模型。单文件 HTML 常常足够；现有应用中已有合适环境时也可复用，但修改生产路径需要授权。

## 在网页反馈中呈现

一个可操作模型通常使用 `selectionMode: none`。重点是让用户走场景、观察结果并评论，不强制创建多个界面候选。

需要 JavaScript 的 HTML 在当前 Review Shell 中使用 `htmlExecution: sandboxed`。这一隔离模式不提供静态 DOM 标注或 CSS 变量控制；使用总体评论、引导问题或另行生成的截图收集定位反馈。不要同时开启脚本与同源权限来恢复标注。

配置合法值以根 Skill 指向的 schema 为准。若演示运行正确但用户仍无法回答问题，先改变状态展示或缩小问题，而不是继续添加底层功能。
