# Codex Explore

这个工作流只负责把容易污染主会话上下文的只读证据探索交给子代理。加载后先做 Gate 判断；不满足条件时交回主代理，按普通任务处理。

## Gate

只有同时满足以下条件，才继续委派子代理：
- 用户明确要求使用 `codex-explore` 做只读探索，或问题必须先做只读证据探索才能可靠推进。
- 取证范围边界不明确，或位于陌生、外部、本轮尚未建立上下文的代码库、文档集、网页、日志或用户材料中，需要先搜索、筛选、排除和核验证据；典型信号是跨 6 个以上文件、3 个以上模块、多来源资料、长日志、需要跨多个官方文档或网页检索，或大段用户材料。它们只是辅助信号，不能单独决定是否委派。
- 如果由主代理独自完成，为了找出可靠答案预计会打开或阅读大量候选文件、搜索结果、日志、网页或用户材料，其中相当一部分可能与最终答案无关，会明显占用或污染当前会话上下文。
- 探索工作能和主代理当前必须亲自处理的工作清楚分离。
- 如果只是交叉验证或独立核对假设，必须同时满足上面的取证范围和上下文污染条件；交叉验证不能单独作为启动子代理的理由。

以下情况立即停止使用本工作流，不要启动子代理：
- 来源和候选材料已知，预计只需读取 2 到 3 个文件或少量明确片段即可完成。最终答案只有一个事实并不是停止理由；如果仍须在陌生或外部的大量材料中搜索、筛选和核验证据，仍应使用本工作流。
- 主代理直接用 `rg` 加少量文件阅读更高效，且不会为了找答案读取大量无关内容。
- 用户只是顺带提到 `codex-explore` 或 `plugins/codex-explore`，但没有要求用它做只读探索，且问题本身不需要隔离探索上下文。
- 任务目标本身是实现、修改、格式化、提交或其它写操作，并且无法清楚分离出只读证据探索；或者要委派的子任务需要提权、登录、购买、发布、发送消息或调用有副作用的接口。

触发例：
- 探索 `/path/to/external-project` 这类陌生或外部源码，确认某个 API、工具名、配置项或行为约定。
- 在大型日志、多个官方文档或网页资料、用户提供的大段材料中筛选证据，最终只汇总关键结论。
- 核对一个平台事实，虽然最终答案很短，但必须先全局检索并排除多个候选解释。

停止例：
- 打开已知文件 `src/tools/foo.ts` 查看一个常量名。
- 在当前仓库 2 到 3 个已知文件里查一个字段。
- 已经知道证据文件，只需要读取几行做确认。

如果正反例与其它阈值发生冲突，优先判断是否需要隔离大量可能无关的探索上下文。

Gate 通过后，主代理不要重复探索同一个问题；进入委派流程。

## 委派前判断

只把具体、边界清楚、可以独立产出结论的只读探索交给子代理。

如果任务涉及网络、文档或时间敏感事实，必须遵守当前会话的工具、联网、官方文档优先和上层安全策略。子代理继承当前会话可用的工具和权限；不能访问来源时要说明限制，不能凭记忆补事实。

## 委派规则

优先使用 Codex Explore 自带的探索子代理。role 已配置默认模型 `{{explorerModel}}` 和推理强度 `{{modelReasoningEffort}}`，但只有当前 `spawn_agent` 工具公开 `agent_type` 时才能选择该 role。调用前以当前工具实际公开的参数为准，不要按 Codex 版本号或配置文件猜测，也不得传入 schema 未公开的字段。

如果 `spawn_agent` 同时公开 `task_name` 和 `agent_type`，按 Codex v2 可选 role 方式调用。`task_name` 使用 `codex_explore_1`、`codex_explore_2` 这类当前父任务下唯一的名称；必须传 `fork_turns: "none"`，否则全历史 fork 会拒绝 role 覆盖：

```ts
spawn_agent({
  task_name: "codex_explore_1",
  agent_type: "{{explorerRoleKey}}",
  fork_turns: "none",
  message: "..."
})
```

如果 `spawn_agent` 公开 `agent_type` 但不公开 `task_name`，按 Codex v1 方式调用。不要设置全历史 `fork_context`：

```ts
spawn_agent({
  agent_type: "{{explorerRoleKey}}",
  message: "..."
})
```

如果 `spawn_agent` 公开 `task_name` 但不公开 `agent_type`，说明当前 Codex v2 运行时隐藏了自定义 role 选择。不要传入隐藏的 `agent_type`、`model` 或 `reasoning_effort`，也不要改用 Codex 内置 `explorer`；改用继承父代理模型和推理强度的默认子代理，并把完整的叶子代理、只读边界和输出合同写入 `message`：

```ts
spawn_agent({
  task_name: "codex_explore_1",
  fork_turns: "none",
  message: "..."
})
```

走隐藏 metadata 的兼容路径前，向用户简短说明本次探索子代理将继承父代理的模型和推理强度，配置的 `{{explorerModel}}` / `{{modelReasoningEffort}}` 不会应用；不得声称专用 role 已生效。如果用户明确要求本次必须使用指定模型或推理强度，立即停止使用本工作流，说明当前运行时无法满足，并询问用户是否接受由主代理继续处理；得到同意前不要继续。

如果工具既不公开 `task_name` 也不公开 `agent_type`，或在 `agent_type` 可用时 Codex 运行时报告 `{{explorerRoleKey}}` 不可用，立即停止使用本工作流，向用户说明当前 Codex Explore 子代理不可用，并由主代理按普通任务继续处理。不要静默换到内置 `explorer` 或其它 role。

除非用户另有要求，默认启动 1 个子代理。只有多个探索问题互不重叠、彼此能独立完成且确实值得拆分时，才启动 2 到 3 个；极少数复杂场景最多 4 个。

每个子代理的 prompt 至少写清：
- 范围：目录、文件、模块、网页、文档集、日志片段、数据范围或行为边界。
- 资料来源：代码库、用户内容、官方文档、公开网页、命令输出，或这些来源的组合。
- 具体问题：明确要回答什么，不要只写“看看这个模块”或“查一下资料”。
- 探索深度：只能使用 `quick`、`medium`、`very thorough`。
- 委派边界：明确子代理是叶子探索代理，不得调用任何子代理调度或管理工具（包括 `spawn_agent`、`send_input`、`send_message`、`followup_task`、`wait_agent`、`resume_agent`、`close_agent`、`interrupt_agent`、`list_agents`），也不得再拆子任务；如果范围过大，只说明需要主代理缩小问题。
- 只读边界：明确不得创建、编辑、移动、删除、格式化或回退文件，不得安装依赖，不得请求提权，不得登录账号、购买、发布、发送消息，或调用任何有副作用的外部接口。
- 期望输出：要求返回关键结论、证据路径或链接、必要行号、来源时间、不确定点，以及建议主代理下一步查看的内容。

## 等待与整合

### 运行边界

子代理启动后，主代理的职责从“亲自探索”切换为“调度、等待、整合和少量核验”。不要再用 `rg`、文件阅读、网页搜索或其它工具同步调查同一个范围、同一个问题或同一批候选材料；这会和子代理重复消耗上下文，并削弱委派的意义。

子代理运行时，主代理只能处理与该探索结论无依赖、且不会覆盖同一探索范围的工作；如果下一步依赖子代理结果，就等待。不要因为想“先看一眼”而并行重查同一问题。

### 等待策略

启动后必须等子代理进入最终状态并读取结果，不要因为短暂无返回就关闭后重做。

调用 `wait_agent` 时按当前工具实际公开的 schema 传参，不要混用 v1 和 v2 的调用形状。设置 `wait_agent.timeout_ms` 前，先按任务规模、资料量、探索深度和子代理数量估算合理等待时间。默认一次给足预期完成时间，不要用过短 timeout 反复空转轮询；`quick` 可以短等，`medium` 和 `very thorough` 通常更适合按分钟级等待。v2 的 `wait_agent` 可能只返回 mailbox 更新摘要；继续等待并读取主会话收到的最终状态通知，不要把摘要当成子代理结果。

### 整合边界

整合结果时，只保留关键结论、证据路径或链接、必要行号、来源时间和不确定点。不要把子代理的完整回复直接转给用户。

只有在子代理结论存在明显矛盾、缺少关键证据、或最终答案需要精确引用时，主代理才补读少量材料核验；补读范围应限于子代理指出的具体文件、行号、链接或最小必要上下文。不要把“核验”扩展成重新探索。

### 完成与清理

读取并整合结果后，只有当前工具列表提供 `close_agent` 时，才用它关闭本工作流启动的子代理。没有 `close_agent` 时无需执行清理；`interrupt_agent` 只用于取消仍在运行的任务，不能代替 `close_agent` 清理已完成的子代理。`wait_agent` 只负责等待，不等于关闭 agent。
