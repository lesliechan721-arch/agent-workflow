# Codex Explore

目标是把会明显占用或污染主会话上下文的只读证据探索交给专用子代理。加载后先做委派价值 Gate；不满足价值条件时交回主代理，按普通任务处理。

完成标准：每个委派问题得到符合证据合同的结果或明确的缺失说明；最终结论只使用通过校验的结果；所有已启动子任务均已终态、已确认停止，或已标记为未解决且没有并行接管。

## Gate

Gate 只判断拟委派的子任务，而不判断顶层任务类型。即使顶层任务是 review、缺陷分析、质量判断、修改或实现，也只有拟委派的子任务同时满足以下条件，才继续委派子代理：
- 用户明确要求使用 `codex-explore` 做只读探索，或问题必须先做只读证据探索才能可靠推进。
- 候选材料范围较大、边界未知，或位于陌生、外部、本轮尚未建立上下文的代码库、文档、网页、日志或用户材料中，需要搜索、筛选和核验证据；主代理直接处理会阅读大量可能无关的候选内容，明显占用或污染当前会话上下文。典型信号是跨 6 个以上文件、3 个以上模块、多来源资料、长日志、需要跨多个官方文档或网页检索，或大段用户材料；数量只作辅助判断。
- 能把探索工作写成具体的事实检索问题，划定资料来源和预期证据输出，并与主代理必须完成的缺陷判定、质量评价、严重性分级、修改建议或通过结论清楚分离。

上下文隔离本身构成委派价值。Gate 成立时，即使探索位于关键路径且没有其它可并行工作，也可委派并等待；主代理不得重复调查同一范围。

交叉验证或独立核对假设不能单独触发本工作流；最终答案只有一个事实并不是停止理由。任务特征与数量阈值冲突时，优先判断是否需要隔离大量可能无关的探索上下文。

以下情况立即停止使用本工作流，不要启动子代理：
- 来源和候选材料已知，预计只需用 `rg` 加定向读取 2 到 3 个文件或少量明确片段即可完成，且不会读取大量无关内容。
- 用户只是顺带提到 `codex-explore` 或 `plugins/codex-explore`，但没有要求用它做只读探索，且问题本身不需要隔离探索上下文。
- 拟委派的子任务本身要求缺陷判定、质量评价、严重性分级、修改建议、实现或其它写操作，无法清楚分离成只读事实探索；或者需要提权、登录、购买、发布、发送消息或调用有副作用的接口。
- 用户要求权限级只读，但当前 turn 未明确具备且可由子代理继承该边界。

价值 Gate 通过后先按下节选定 role，再读取当前 `spawn_agent` schema 检查运行能力。仅当工具公开 `agent_type`，且未限制或明确允许选定 role 时才启动子代理。否则不启动替代 role；把该范围视为委派失败，按后文的失败回退规则处理。

## 委派规则

只使用 Codex Explore 自带的以下 role；叶子代理约束和 developer instructions 由 role 提供。不得启动默认子代理或改用内置 `explorer`、其它 role。

### Role 选择

选择优先级固定为：
1. 用户在当前请求中显式指定 `model` 或 `reasoning_effort` 时，选择 `{{customRoleKey}}`。只传用户实际指定且当前 schema 公开的字段；未指定字段交给 Codex 原生默认。即使用户同时指定探索深度，也仍用 custom role，深度只写入 prompt。
2. 用户只显式指定 `quick`、`standard` 或 `deep` 探索深度时，选择对应预设 role。
3. 否则根据任务判断；无法明确分档时选择 standard。

预设 role：
- `quick` → `{{quickRoleKey}}`：问题明确、歧义低，主要是在大量候选中定位、提取或核对窄范围事实。
- `standard` → `{{standardRoleKey}}`：常规跨文件、跨模块或多来源追踪核对，包含适度归纳或来源冲突。
- `deep` → `{{deepRoleKey}}`：高歧义、强冲突、复杂因果、范围特别大，或要求高完整性和深入核验。

调用预设 role 时不得传 `model` 或 `reasoning_effort`。`{{customRoleKey}}` 不锁定这两个字段且永不自动选择；只有用户在当前请求中显式指定至少一个字段时才能使用。用户显式字段未由 schema 公开时不启动子代理，说明当前调度能力无法满足该指定。已传入的模型不可用、推理强度不受支持或其它非临时参数错误按启动失败处理；不得删除字段、切换预设或静默重试。

任务涉及网络、文档或时间敏感事实时，遵守当前会话的工具、联网、官方文档优先和上层安全策略。子代理继承当前会话可用的工具和权限；不能访问来源时说明限制，不能凭记忆补事实。

按当前 `spawn_agent` schema 调用：始终传选定的 `agent_type` 和完整的 `message`；custom role 只透传用户显式指定且 schema 公开的模型字段；有 `task_name` 时使用语义化且唯一的名称；有 `fork_turns` 时传 `"none"`，有 `fork_context` 时传 `false`。上述方式不继承父会话历史，`message` 必须自包含所需的来源定位和最小上下文；只存在于父会话中的材料按当前 schema 传入最小必要内容或可访问定位，无法安全传递时不委派并报告限制。不要传 schema 未公开的字段；role 不可用时按委派失败处理。

除非用户另有要求，默认启动 1 个子代理。只有多个探索问题互不重叠、彼此能独立完成且确实值得拆分时，才启动 2 到 3 个；不得超过当前可用并发槽位，任何情况下最多 4 个。

每个子代理的 prompt 只写本次任务需要的内容：
- 范围：目录、文件、模块、网页、文档集、日志片段、数据范围或行为边界。
- 资料来源：代码库、用户内容、官方文档、公开网页、命令输出，或这些来源的组合。
- 具体问题：明确要回答什么，不要只写“看看这个模块”或“查一下资料”。
- 探索深度：只写 `quick`、`standard` 或 `deep`；预设 role 与其档位一致，custom role 按用户要求或任务复杂度选择。
- 必要上下文：路径、URL、记录 ID，以及子代理无法从可访问来源自行获得的最小背景。
- 期望输出：本任务必须回答的字段、格式和覆盖范围。

不要在 prompt 中重复专用 role 已提供的叶子代理、只读和通用证据规则。

## 隐私 Gotcha

向公开网页或外部搜索发送查询前，最小化并脱敏查询；不得包含密钥、个人数据、私有代码或用户材料原文。无法安全脱敏时，只使用本地或用户已提供的来源并报告限制。

## 只读边界

本工作流及其委派范围保持只读：叶子代理始终不得写；主代理在探索期间不得在该范围写。工作流完成或停止后，主代理可继续顶层任务已授权的修改；写操作、实现和修改决策不得委派给 Codex Explore 叶子代理。

子代理继承父 turn 的有效 permission profile、approval policy 和 sandbox。父 turn 可写时只能提供行为只读，`spawn_agent` 不能把单个子代理独立降权。用户要求权限级保证但继承边界不明确时停止，不得把指令约束描述为权限隔离。

## 等待与整合

子代理未终态且未确认停止期间，主代理不再同步调查同一个问题或同一批候选材料；可以处理不依赖其结论的其它工作。

`wait_agent.timeout_ms` 是单次最长响应式等待窗口，不要求实际等待满该时长，也不是轮询周期。首次存活探测前给子任务至少 `{{minimumInitialWaitMinutes}}` 分钟的累计等待预算；当前 schema 允许时优先使用 `timeout_ms={{minimumInitialWaitTimeoutMs}}`。用户指定单次等待时优先遵守，并始终服从 schema 上下限。

等待因非超时事件提前返回且目标仍未终态时，先处理该事件，再继续等待剩余预算；不得因此提前发起存活探测。

仅当累计等待预算已满足、`wait_agent` 明确报告超时，且当前环境支持不会中断原调查的状态探测和回复时，才向每个未完成代理探测一次，要求只回复 `status=progress` 或 `status=blocked` 及必要原因；超时本身不代表失败，同一子任务最多有一个未决探测。能力不可用时跳过协议，按工具结果、运行时通知和任务必要性继续等待或标记未解决；不得用会中断、重定向或替换原调查的操作模拟探测。

- 回复正常推进时，继续等待；后续使用相同或更长的窗口并受当前 schema 最大值限制，具体长度按回复中的进度和任务需要判断。
- 回复阻塞或需要输入时，主代理处理可解决的阻塞；需要新授权、用户选择或范围变更时向用户说明。
- 返回最终结果时，按下文证据合同校验。
- 暂未回复不能单独证明代理已经挂死；按当前工具说明判断探测是否仍待交付，再结合任务必要性、已有运行证据和用户要求决定继续等待、停止当前 turn 或标记未解决。

是否请求部分结果或提前收敛由主代理根据状态回复、任务覆盖要求和用户目标判断，不设固定收敛阶段。不得使用短 wait 循环、周期性状态查询或重复进度询问来监控子代理。

每个子任务最多恢复一次，等待和存活探测不占恢复额度：仅明确的临时启动或运行故障可以使用原 prompt、role 和参数重试；空输出或可补充的缺失项可以向原代理追问。其它情况或恢复后仍不合格时，判定失败或无效。

多个子代理分别判断；失败不影响其它有效结果，也不能被其它结果掩盖。失败或无效内容不得整合，也不在同一轮重新委派同一范围。只有已确认没有代理仍在处理该范围时，才适用以下回退：
- 用户明确要求使用 `codex-explore` 或隔离探索上下文时，报告失败类型和缺失，不由主代理接管该范围。
- 本工作流自动触发时，主代理可对失败范围做一次最小、只读且任务相关的回退。回退后仍缺少必要证据就缩小结论并报告缺失。

使用子代理结果前，主代理检查：
- 是否回答了指定范围内的具体问题。
- 每个影响最终答案的关键结论是否绑定实际读取且可核验的来源定位。定位可以是文件路径与必要行号、URL、用户材料的段落或行号、命令或工具名称及可识别的输出片段或记录 ID；时间敏感来源还需提供来源时间。
- 直接证据、推断、来源冲突和证据缺失是否明确区分。
- 不确定点是否会改变最终结论或需要用户补充信息。

缺少可补充字段时使用剩余恢复额度；否则将结果判定为无效。只有最终答案依赖关键争议、缺少关键证据或需要精确引用时，才补读子代理指出的最小必要上下文；不要扩展成重新探索。

整合结果时，只保留通过校验的关键结论、对应证据、必要行号、来源时间、冲突和不确定点。不要把子代理的完整回复直接转给用户。

完成前，有 `close_agent` 时关闭本工作流启动、已终态或明确放弃且不再需要的代理，包括失败、无效、阻塞和恢复后仍不合格的代理；不要关闭仍在运行且结果或后代仍有必要的目标。未提供时无需额外清理。
