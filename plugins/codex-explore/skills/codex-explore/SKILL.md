# Codex Explore

这个 workflow 只处理“大范围只读探索”。加载后先只做 Gate 判断，不要一边读取本 skill 一边读取目标代码、文档、网页、日志或用户材料；Gate 不通过就停止使用，由主 agent 按普通任务处理。

## Gate

只有同时满足以下条件，才继续委派子代理：
- 任务必须先做只读探查才能得出结论，并预计跨 4 个以上文件、多模块、多来源材料、长日志、网页/官方文档，或大段用户材料。
- 需要整理长上下文、搜索证据、比较既有实现或外部资料、独立核对假设，或探索工作能和主 agent 当前必须亲自处理的工作清楚分离。

以下情况立即停止使用本 workflow，不要启动子代理：
- 单个事实查询、已知文件内的小搜索，或 2 到 3 个文件内能快速完成的定位。
- 主 agent 直接读取少量材料更高效。
- 用户只是提到 `codex-explore`、`$codex-explore`、`plugins/codex-explore` 或在维护本插件，但问题本身不需要大范围探索。
- 实现、修改、格式化、提交、需要授权的动作，或主 agent 下一步必须立即依赖的阻塞决策。

Gate 通过后，主 agent 不要再自行探索同一个问题；进入委派流程。

## 委派前判断

先快速拆分任务，区分主 agent 现在必须亲自处理的工作，以及可以独立交给子代理的探索工作。只把具体、边界清楚、可以独立产出结论的只读探索交给子代理。

如果任务涉及网络、文档或时间敏感事实，必须遵守当前会话工具可用性、联网要求、官方文档优先和上层安全策略。子代理继承当前会话可用的工具和权限；不能访问来源时要在结果里说明限制，不能凭记忆补事实。

## 委派规则

默认使用 Codex Explore 受管子代理，role 已配置默认模型 `{{explorerModel}}` 和推理强度 `{{modelReasoningEffort}}`。除非用户在当前请求里明确指定其它模型或推理强度，`spawn_agent` 只传 `agent_type` 和 `message`。

```ts
spawn_agent({
  agent_type: "{{explorerRoleKey}}",
  message: "..."
})
```

用户在当前请求里明确指定其它模型或推理强度时，改用 Codex 内置 `explorer`；指定的字段显式传入，未指定的字段继续使用插件配置默认值。

```ts
spawn_agent({
  agent_type: "explorer",
  model: "<用户指定模型或 {{explorerModel}}>",
  reasoning_effort: "<用户指定推理强度或 {{modelReasoningEffort}}>",
  message: "..."
})
```

如果 Codex runtime 报告 `{{explorerRoleKey}}`、`{{explorerModel}}` 或指定推理强度不可用，先向用户说明当前 workflow 默认配置不可用或已被用户指令覆盖，再按用户最新指示处理。不要静默换模型或 role。

除非用户另有要求，默认启动 1 个子代理。只有多个探索问题互不重叠、彼此能独立完成且确实值得拆分时，才启动 2 到 3 个；极少数复杂场景最多 4 个。

每个子代理的 prompt 必须包含：
- 范围：目录、文件、模块、网页、文档集、日志片段、数据范围或行为边界。
- 资料来源：代码库、用户内容、官方文档、公开网页、命令输出，或这些来源的组合。
- 具体问题：明确要回答什么，不要只写“看看这个模块”或“查一下资料”。
- 探索深度：只能使用 `quick`、`medium`、`very thorough`。
- 只读边界：明确不得创建、编辑、移动、删除、格式化或回退文件，不得安装依赖，不得请求提权，不得登录账号、购买、发布、发送消息，或调用任何有副作用的外部接口。
- 期望输出：要求返回关键结论、证据路径或链接、必要行号、来源时间、不确定点，以及建议主 agent 下一步查看的内容。

## 等待与整合

子代理运行时，主 agent 不要重复调查同一个问题；能处理无依赖工作就先处理，否则等待。启动后必须等它进入最终状态并读取结果，不要因短暂无返回就关闭后重做。

`wait_agent` 的 `timeout_ms` 要先按任务规模、资料量、探索深度和子代理数量评估，并显式设置一个合理等待窗口。默认一次给足预期完成时间，不要依赖过短 timeout 反复空转轮询；`quick` 可以短等，`medium` 和 `very thorough` 应给更长等待窗口，通常按分钟级等待更合适。

整合结果时，只保留关键结论、证据路径或链接、必要行号、来源时间和不确定点。必要时补读少量材料验证，不要把完整回复倾倒给用户。

读取并整合结果后，立即用 `close_agent` 关闭本 workflow 启动的子代理。`wait_agent` 不等于关闭 agent；它只负责等待结果。
