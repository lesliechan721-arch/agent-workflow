# 设计 Skill Eval

创建或修改用例、fixture 与判定规则时使用。

## 先确定要证明什么

从真实用户任务选择少量有区分度的场景族。分别考虑触发、正确使用、实际产物和成本；只测“不能多做”不能证明会完成任务。旧版回归、常见任务和机制探针分开解释，不用同义请求数量代表覆盖。

用真实或足够具体的输入定义预期结果与允许差异。Oracle 是判定通过或失败的依据，应来自需求和领域规则，不来自当前 Skill 恰好做了什么。相近边界用最小条件变化体现，正确对照应允许等价方法。

触发测试关注是否加载时，不额外假定它必须是首次入口；合理辅助使用可以成立。首次路由或上下文隔离需要实际观测支持，不能只靠 prompt 中的角色声明。

## 构造可达的输入

采用实际运行器的格式和示例。没有格式依据时交付人读案例，不发明通用 Eval JSON。文件、工具、权限或已有产物决定结果时，fixture 必须真实提供这些条件。

正常包满足进入目标步骤的基本前提；有意非法包用于测试拒绝，不同时假装在测后续方法。模拟工具说明覆盖范围并拒绝未知操作，不能充当真实产品成功证据。

写任务明确允许修改的文件和可核对产物。只读规则需要在具备相应能力时观察主动不写，而不只是环境禁止。交接测试使用本次上游实际生成物；人工准备的两端样本只能分别测局部能力。

## 写有区分力的断言

数量、文件变化、格式和准确字段交给机械检查；内容质量采用可解释的语义判断。断言覆盖用户在意的结果，而不是固定措辞、内部步骤、标题或无用途输出协议。

检出用例不提示具体缺陷；已知问题修复可以提供明确位置，但结论仅对应修复能力。保留等价正确例，避免模型为符合 Oracle 而过度修正。

评价自主设计时，给原始资料、真实目标和必要环境，不在请求中安排要删除的例子、应内联的段落或预定结构。把这些提示保留在明确纠正用例中，分别解释能力。执行上下文不带作者修订历史、评分答案或候选优劣标签；被测能力的完整目标正文若已作为方法依赖读入，重建结果只证明复用，不能作为独立综合证据。

写清为什么该条件决定结果，以及什么最小改变会翻转预期。没有依据的精确数量或代理数不应成为硬断言。范围、前提和依据较多时写在伴随说明，不向严格格式塞新字段。

## 比较与迭代

需要判断收益时保留相同资料、权限、工具环境、用例与评价规则，比较基线和候选的实际产物、轨迹、试错与人工介入。无 Skill 基线移除对已删除能力的悬空调用，但保留原始领域知识。

用未参与调整的请求检查泛化。总是通过的断言可能没有区分力，总是失败的断言也可能是坏前提或错误 Oracle；结合真实产物判断。界面观感或整体风格难拆成二值时保留人读比较，不用形式字段取代质量。

失败先检查 fixture、Oracle、评价器和运行环境，再定位 Skill。修改 Oracle 后，重新审核受影响比较；不要用新标签证明旧候选无回归。追加运行遵守已有预算。

交付完整用例、输入、允许差异与判定依据，说明结构检查、独立审核和模型运行的实际状态。作者自检不能签独立准入，运行器合同与执行由相应能力负责。
