# Skill 组合与输出边界

职责拆分、能力组合、执行角色或固定输出发生变化时使用。

## 连贯职责与两种成本

以用户结果、权限、证据生命周期、目标环境、上下文隔离价值和实际复用判断边界。对象差异常可由 reference 分支处理；独立裁决或可复用能力可以保持公开。能为每个分支起名字，不足以要求新增 Skill。

同时比较实际读入的 description/正文/参考资料与调用链，以及用户需要记住的入口和内部对象。独立性收益不足以抵消导航和维护时合并；只减少入口数也不能证明一个大 facade 合理。用户启动专项评审时，整个插件组合和公开能力面使用 Reviewer 的工作流或公开能力范围。

## Caller 与 leaf

共享参考不一定需要新增 Skill。只有资料本身需要被独立发现或作为可复用能力采用时，纯参考 Skill 才有入口价值；几个已知任务只是读取同一组规则时，可共同指向有稳定位置的普通文件。两个用户专用入口不能靠互相调用取得共享规则，应让所需资料在各自路径中直接可达。

选择共享方式时核对实际交付：消费者能否取得文件，读取条件是否清楚，权威正文是否只有一处。构建时分发副本与新增公开入口是不同决定；不能为了减少源码副本而增加没有独立用途的调用层。

当前上下文中可确认同版本、同适用条件的规则直接复用；内容不可用或适用条件改变时只补读必要资料。不因文件同名就假定内容等价，也不经 Author 工作流取得共享规范。

独立可用是能从当前请求与必要公开资料完成有意义的工作；允许公开工具和能力依赖。

每个 Skill 定义自身负责的动作与完成条件。使用其他能力时，说明采用条件、本次范围、必要资料与权限，以及当前调用者如何采用和核对结果；完整下游方法由对应能力维护。同一 Agent 已有上下文直接复用。

当前能力采用任务给定的位置与约束，正文只保留完成自身结果所需的方法。

按实际动作、条件和消费者判断重复。跨角色必要的安全检查与独立核验分别保留；概述其他执行者的方法应服务当前决定、交接或验收，需要完整细节时使用明确指针。

真实交接沿本次产物与可达引用检查：接收者能否取得已确认决定、重要设计、完成依据和执行所需上下文。明确所需片段与位置，并在更新进度时保留任务定义；私有会话记忆和含糊的继承说明须补成可访问依据。

## 执行角色与独立证据

执行角色来自当前分工。已具备条件的执行者完成所分配范围，不重放同职责协调步骤；协调者只补足缺少的能力或隔离。

需要独立判断时核对作者参与、历史来源、已有安排和当前输入。必要的原始资料与旧问题保持可达；采用另一 Skill 或更换角色名称本身不形成独立性。作者自检与独立裁决分别报告。

## 对象视图与编辑位置

区分完整包、生成产物与需要构建的源码。完整包按适用标准检查；只有源码时说明哪些运行资源尚未取得。文件缺失在实际消费对象上判断；相同正文在不同环境中的结果分别核对。

当前执行者取得本次目标及必要来源材料，核验其可见内容。发现位置和可修改位置可以不同；修改权威源码后重新取得受影响的产物。来源不明时说明限制，不把生成副本当权威源。

## 固定输出是否必要

先识别结果用途：用户明确指定的格式、真实业务 parser、外部文件消费、恢复、授权或跨上下文交接可以需要结构；只有自带 validator 不能自证价值。静态搜索没找到用途只表明待核验，不证明不存在。

仅为同一会话继续使用而增加 `nextSkill`、`artifactPath` 或状态协议，且没有其它消费目的时，优先使用语义完成条件；有明确用户格式要求则遵守，不武断删除 JSON。

人读结果按阅读需要组织。真实程序接口由消费者定义最小字段；实际交接保留接收者需要的内容。

## 使用这些标准

创建与评审采用相同的用途判断。同一根因归一个主要问题，不因影响多个维度重复计罚。
