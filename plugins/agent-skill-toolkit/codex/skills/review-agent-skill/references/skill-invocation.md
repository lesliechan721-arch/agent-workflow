# Skill 调用与触发标准

设计或检查 description、默认适用范围和能力调用时使用。具体字段按目标客户端的调用合同核对。

## 选择谁来启动

先判断谁需要发现这项能力，以及谁应决定启动时机，再选择调用属性。

| 需要 | 选择依据 |
| --- | --- |
| 模型应从用户任务中自行识别，或其它 Skill 需要采用它 | 保留模型可达的入口，description 给出决定性的使用条件；独立发现的价值应抵得上入口的常驻成本 |
| 只在用户选定时机启动，不需要模型自主采用 | 使用用户显式入口，把用途说明给人；同时承担用户记住或查找入口的负担 |
| 模型需要背景方法，但用户不需要直接启动 | 在客户端支持时分别控制两个入口，保留模型可达性，不把隐藏用户入口误作关闭模型调用 |

模型入口、用户入口与 description 的实际读入方式分别核对。关闭隐式调用不等于禁用整个 Skill；也不能从某个客户端的手动模式推导所有客户端都没有上下文成本。必需 description 仍按包格式保留。

## 调用可用性

允许模型采用且在当前环境可发现的 Skill，可以由模型选择，也可以在其它 Skill 中通过“使用 `<name>`”明确组合。只支持用户启动的 Skill 视为用户宏，不能作为模型自主调用的必要下游。

检查目标环境实际提供的能力和调用字段。文件存在、已发现、已加载与实际完成分别取证；必要下游须在当前环境可达。

## Description 与读取指针

区分 Skill 能完成的任务、值得模型默认选择的任务，以及由其它能力或普通执行处理的任务。按结果、必要依据、约束和独特方法说明边界；issue、ticket 或“实现”等载体与动作词只是线索。显式选择与有依据的委派仍可使用该能力，不由此推导所有相近请求都应自动加载。

按任务族、目标执行者和环境说明它补足的知识、方法或交接约束。规范、领域事实和观察可支持设计，未验证增益保留为假设；局部有效性结论限于相应场景。普通执行也是可选路径，收窄 leaf 时一并核对 caller 的必要下游要求。

据此决定调用属性和 description。description 说明做什么、何时使用及高价值 near-miss；正文提供条件明确的能力指针。先确认适用性，再评价命中路径的读取量。

正文的“使用另一 Skill”是能力指针：在当前材料足够时直接复用上下文；有必要才说明该次目标、范围和所需结论。不要求创建统一参数、返回值或 handoff 文件。

必要入口只能由用户启动时，说明入口和待完成事项，或采用当前可用的替代路径。

## 触发测试的含义

是否被加载、是否为首个入口、是否作为允许的辅助能力、最终任务是否正确，是不同问题。不能用“不应成为主入口”推出“整个任务都不许加载”；不能把能够加载当成已执行所有步骤。

采用运行器实际支持的记录。分别观察漏触发与误触发，并按错误代价解释。只有字段或 description 对照时，结论限于配置与设计。
