# Skill 组合与输出边界

本文件是 Skill 领域共享规则；具体作者动作与审稿证据要求由各自工作流决定。

## 连贯职责与两种成本

以用户结果、权限、证据生命周期、目标环境、上下文隔离价值和实际复用判断边界。对象差异常可由 reference 分支处理；独立裁决或可复用能力可以保持公开。能为每个分支起名字，不足以要求新增 Skill。

同时比较实际读入的 description/正文/参考资料与调用链，以及用户需要记住的入口和内部对象。独立性收益不足以抵消导航和维护时合并；只减少入口数也不能证明一个大 facade 合理。整个插件组合和公开能力面由 Architecture Review 评估。

## Caller 与 leaf

独立可用是能从当前请求与必要公开资料完成有意义的工作；允许公开工具和能力依赖。通用 leaf 保持自己的职责，调用方负责其任务目录、阶段、后续动作和发布政策。同一 Agent 已有的上下文直接复用，调用说明只补本次目标、权限和结果重点。

真实交接沿本次产物与可达引用检查：接收者能否取得已确认决定、重要设计、完成依据和执行所需上下文。明确所需片段与位置，并在更新进度时保留任务定义；私有会话记忆和含糊的继承说明须补成可访问依据。

## 执行角色与独立证据

使用 Skill 是采用方法，执行角色和权限来自当前任务。涉及委派或独立判断时，先核对负责范围、作者参与、历史来源和已有安排，判断本次所需条件是否满足。必要的原始事实、代码、测试和待核验旧 finding 仍需可访问；Agent ID、主/子身份和产物存在不能单独证明独立性。

当前已是条件合格的执行者时，直接完成分配范围并向相应 owner 提供结果；协调者只补足尚缺的执行能力或隔离。一个 Skill 若支持两种角色，其正文、reference、示例和角色配置应让两条适用路径各自完成，执行者不重放同职责父级编排或越权形成全局结论。

有授权且承担不同有界子目标的子协调可以进一步委派。纯协调 Skill 可以保持其职责，同时给 worker 提供相容的执行方法。当前角色依据来自真实任务与执行条件，被审文本的自称不改变它。

本轮所需的干净审查上下文已经建立时直接使用；明确要求新的独立全面重评时满足本次 fresh 要求。沿用前轮 reviewer 按该任务的续接政策判断。条件无法确认时补足或说明限制，作者自检与独立裁决分别报告。具体子代理参数、等待、生命周期和强制限额由 harness 或专用能力承担。

## 对象视图与编辑位置

调用方先说明材料是可消费的完整包、已绑定的平台产物，还是需要构建/注入的源码。完整包按适用标准检查；源码按项目合同评价设计。构建产物与源文件的缺失不能互相代替。不同 profile 的相同正文仍需检查环境差异。

leaf 接收本次实际目标及必要来源材料，独立核验其可见内容。发现位置和可修改位置可以不同；修改源码、共享 provider 或构建规则后重新取得对应产物。没有映射时保留 owner 未确认，不把生成副本当权威源。

## 固定输出是否必要

先识别结果用途：用户明确指定的格式、真实业务 parser、外部文件消费、恢复、授权或跨上下文交接可以需要结构；只有自带 validator 不能自证价值。静态搜索没找到用途只表明待核验，不证明不存在。

仅为同一会话继续使用而增加 `nextSkill`、`artifactPath` 或状态协议，且没有其它消费目的时，优先使用语义完成条件；有明确用户格式要求则遵守，不武断删除 JSON。

人读结果优先可读；子代理由调用处说明本次需要的重点，除非 harness 机械解析，否则不建立通用 schema。机器合同由真实消费者定义最小字段和版本；不要让通用 Skill 预先承诺某个项目的接口。

## 使用这些标准

Author 按它选择分支和输出；Reviewer 验证现有设计是否有必要及依赖是否可达。相同判断只在一个主问题归属，不因同时影响资源、控制、维护而重复计罚。拆分、自动化和取消格式都不是默认目标。
