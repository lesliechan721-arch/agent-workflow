# Eval 的评价资格

用于深入检查测试前提、观测、对照和结果解释。

## 可达性与观测

先确认被测对象确实满足进入目标步骤的前提。正常完整包的名称与目录应相容；有意非法输入测的是拒绝，不同时声称在测试后续方法。文件、工具或权限决定结果时，检查真实 fixture 和执行设置。

加载记录只能回答是否加载。首次路由需要顺序观测，辅助使用需要允许的组合范围，最终质量需要实际产物。description 重叠不能证明发生共载，expected 输出不能证明运行成功。

独立性需要实际任务来源、作者参与和上下文构造。Agent 名称或一项 fork 参数不足以证明独立；已符合条件的执行者无需为了数量再增加一层。纯源推理可以声明假设，但应与运行证据分开。

只读行为需要在具有相应能力时观察未写入；单靠环境禁写只证明限制生效。模拟工具只证明模拟范围，不能替代真实客户端或服务执行。

## Oracle 与正确对照

按真实用户要求解释正确结果。输出措辞、合法实现方式和无影响的步骤顺序可以不同，除非消费者确实要求精确形式。用户需要可复制 JSON，本身就是输出用途，不必强行增加程序消费者。

为检出问题提供没有泄露答案的有效目标，再给决定性条件相同而结论正确的对照。用最小反例定位边界，不用完全无关的任务当负例。若改变了多个重要条件，不能把结果差异只归给一个规则。

交接测试让下游使用本次上游实际产生的材料，检查信息是否足够、能否到达及结果是否正确。两个独立手工好样本不能证明整条交接路径。

## 断言与证据

格式、文件存在、准确数量、修改范围等机械结果交给 parser、文件比较或调用日志。语义质量写清可观察目标与允许差异；界面和风格等难以拆成二值的质量，保留人读比较及依据。

审视没有区分力的断言：两边总通过可能只测到模型常识；两边总失败可能是坏前提、错误 Oracle 或未覆盖能力。保留真正必要的不变量，但不要把它们都算成 Skill 增量价值。

通过意见应能定位实际产物内容。文件里有“摘要”标题不等于有合格摘要，有测试脚本不等于执行过测试。输入不足先归因到前提，不诱导执行者补造事实。

## 对照公平与归因

固定任务材料、工具、权限、模型、运行布局、评价规则与预算。无 Skill 基线移除要求调用已删除能力的悬空指令，但保留原始领域依据。候选的帮助工具不同可能就是本次干预，应记录差别，不能把额外数据或权限也一起改变。

按任务族、正负类型及基线/候选查看原始结果；解释漏触发和误触发的实际代价。合成机制探针、真实回归和常见任务不应默认为相同发生频率。小样本结果不代表固定成功概率，追加运行仅在已有预算内进行。

查看实际失败轨迹和成本异常，依次排除资料缺失、错误标签、评价器误判、环境问题、陈旧输入与方差。确定 Skill 根因后，建议能覆盖该类任务的最小改变，同时检查相近正确场景；不要为单个不真实挑战扩大普通路径。
