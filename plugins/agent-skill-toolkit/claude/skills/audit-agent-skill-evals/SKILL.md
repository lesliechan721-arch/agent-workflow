# Audit Agent Skill Evals

只读审核 Skill Eval 能否有效评价目标能力，并按真实证据归因运行结果。被测 Skill 与用例保持只读；按请求交付审核意见、结果归因或运行器要求的正式准入产物。

## 1. 审核用例前提与 Oracle

从用户目标和领域规则独立推导正确行为，再核对 Oracle，绝不从现有标签或通过率反推正确答案。

逐例检查 4 个硬问题：
1. **前提是否真实可达**：输入是否给出决定性事实？测文件/脚本/修改范围时，fixture 是否真实落地，而不是只口头声明？
2. **测的到底是什么**：分开核对加载、首次入口、合法辅助、自主检出、已知修复与范围控制。提示了故障位置的修复例不能冒充自主检出；只禁多做不能证明正向完成。
3. **边界与自由度**：是否有最小条件变化的反例？是否允许等价正确做法，防止断言锁死措辞或内部步骤？
4. **错误代价**：漏触发与误触发代价通常不等，高影响边界错误不能被平均通过率掩盖。

细查可达性、观测方式、公平对照或归因时读 Eval 审核标准（`references/eval-audit-standard.md`）。普通源审核可直接完成；只有需要正式机器准入（`preflight`）时才读 正式准入（`references/formal-admission.md`）。

## 2. 解释运行结果（Result Triage）

读取实际产物、调用轨迹与运行环境，按顺序排错：**用例前提 → Oracle → 评价器 → 运行环境 → 模型方差 → Skill 方法**。文件标题、自述或总通过率不能代替真实产物与轨迹。

对比基线与候选时，确认两者共享相同领域资料、工具、权限和评价规则；若无 Skill 基线保留了悬空调用或少了原始资料，差异不能算 Skill 增益。修改过 Oracle 后，受影响的旧对比作废。

## 3. 交付结论

给出哪些预期成立、具体问题（位置、直接证据、最小修正）和剩余未知。严格区分源审核、正式准入和模型实跑三类证据；参与了本次 Oracle 设计的上下文只能做作者自检，不能签发独立通过。
