# 候选接受与停止

## 比较前固定

baseline 与 candidate 的准确版本、保留行为、场景族、允许修改、同一 corpus/grader、模型和工具环境，以及调用/成本预算。FN/FP 非劣容忍度和关键行为由用户或既有 suite policy 给出；缺失时报告并采用可解释的保守比较，不事后调阈值。

Oracle 语义审查可以在输入未改变时引用；**正式 Audit 的 target/provider/workspace/cases 绑定必须按每轮 Spec 重新验证**。失败修 Oracle 后废弃受影响比较，重新建立公平对照。

## 接受

- 包、引用、脚本及保留机器合同有效；硬安全边界未删除。结构改写已对照原文核对主体、条件、权限、顺序/并行、例外、停止边界、约束强度和引用含义。
- 固定代表性/回归集没有不可接受损失；高影响异常查明，不由其余通过抵消。
- 模型方差足以解释的小差异标不确定，必要时在授权内增加 paired runs。
- 至少一项实际复杂度或运行成本下降，其他显著变差项已披露；不能只移动文字后声称更轻。结构候选说明实际减少的查找、关系重建或维护负担；排版紧凑或字符减少不单独证明收益，人审改善与模型成本分别报告。
- 未新增更重的补偿规则；总修改符合用户范围。

接受只表明当前证据支持采纳，不证明全局等价。Challenge 失败按真实性、影响和既有承诺处理，不自动牺牲常见正例追求全通过。

## 拒绝 / 不确定 / 停止

明确回归则拒绝；证据不足则 inconclusive，保留 baseline。达到预算、边际收益小、剩余候选涉及未经授权范围或 Oracle 变化时停止。有限候选不能证明 Pareto 最优，只报告本次已比较版本间的取舍。
