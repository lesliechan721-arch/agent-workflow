# Skill 设计与交付检查

新建、实质重写或改变职责时使用；局部修正只取相关条目。

## 设计依据

在已有上下文中明确实际用户任务、默认失败或缺失知识、成功标准、范围外事项、允许修改的路径。没有执行基线时写为假设，不虚构用户失败记录；新任务也可以基于项目规范和领域材料设计，不能因尚无量化基线而拒绝所有创建。

先选择一个连贯用户结果。创建/修改可以包含局部自检；独立质量裁决和 Oracle 审核是另一种证据职责，不由作者自证。涉及调用或拆分时，按本 Skill 已列出的调用与组合 reference 决定，不将这些领域机制写入通用内容标准。

## 包与资源

`SKILL.md` 的 name 与目录一致，description 描述当前职责和可辨识边界。主文件保留触发后必须知道的规则及资源指针。条件方法放 focused references；重复确定性操作放脚本；模板/数据放 assets。缺省资源不是缺陷。正文和资源的写作使用 `agent-content`。

同一上下文的设计决定无需 SkillDesignBrief JSON。用户明确要求的文档或实际消费者要求的格式按对应约定交付。普通小改不增加 schema、validator、reference 或 Eval。

## 完成

修改范围、硬约束和原有用户工作必须保持。实际检查 frontmatter、目录、引用和改动涉及的结构；脚本检查依赖、`--help`、输入/输出及安全样例。报告已执行命令和结果；未运行的 build、模型 Eval、独立 Review 明确未执行。

重大变更比较原版与新版的触发、权限、资源、公共消费者和相关用例。Eval 设计结果注明未独立审核。交付不以自动运行 Review、Audit、模型 Eval 或发布为完成条件；这些动作须另有任务依据和授权。
