# 重构与消融的对照验收

对已有 Skill 做删减、合并或重构，并需要通过基线对照验证无回归时读取。仅做静态修改而未跑对照时，只报告静态核对范围，不宣称已验证无回归。

## 1. 比较前固定条件

开始对照前写清并冻结：
- baseline 与 candidate 的精确版本（如涉及构建生成物，用相同环境准备两者的最终消费包）；
- 必须保留的核心行为、硬安全边界与机器合同；
- 同一组代表性任务与回归用例、同一模型、同一工具和权限环境，以及明确的运行预算；
- 若有漏触发/误触发容忍度要求，事先写明，不看结果事后调阈值。

修改了 Oracle 后，受影响的旧比较作废，须重新建立公平对照。

## 2. 接受标准

同时满足以下条件才接受候选：
1. **结构与保真完整**：`check-skill.mjs`、脚本接口及保留的机器合同全部通过；主体、条件、单位、权限、顺序和例外未丢失。
2. **无不可接受回归**：固定代表集与回归集不出现高影响失败（高影响异常须查明，不能被其它通过项平均抵消）。
3. **可观察净收益**：至少一项真实指标改善（实际读入上下文、跳转次数、重复试探、错误率、耗时/Token 成本、人工介入或维护位置），且显著退化项已如实披露；只挪动文件位置但每次仍全量加载，或仅源码变短而最终消费包未变，不算运行收益。
4. **未新增补偿负担**：没有为了修补删减后果而引入更重的替代规则，且总修改符合授权范围。

正文更短但迫使执行者猜字段含义、单位或边界，不是有效简化。断言均通过但整体质量难区分时，用**盲评 A/B**（隐藏 baseline 与 candidate 来源交评委或人工比较产物）规避偏好偏差；同用例多轮结果高方差提示指令存在歧义，单用例耗时或 Token 显著离群（如 3 倍）即使通过也应读执行轨迹查死循环或多余步骤。

## 3. 拒绝、不确定与停止

- 观察到明确回归 → 拒绝候选，保留 baseline。
- 差异落在模型正常波动内或样本不足 → 标记 `inconclusive`，保留 baseline，必要时在授权内补做配对运行。
- 达到预算、边际收益微弱、剩余改动超出授权或 Oracle 变动 → 停止比较并交付实际记录（基线、候选假设、证据、决策与停止原因）。
