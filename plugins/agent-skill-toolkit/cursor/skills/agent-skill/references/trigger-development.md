# 触发问题的诊断与修改

排查漏触发、误触发，或调整自动/手动调用策略时读取。调用语义见 `references/skill-invocation.md`，字段见 `references/skill-format.md`。

## 1. 先分层定位根因，再动刀

先拿真实请求、现行 description、metadata、相关 caller 和加载记录，按现象定位最小修改点：

| 可观察现象 | 先核对 | 最小修改位置 |
| --- | --- | --- |
| 未出现在能力清单 | 能力清单、解析结果与启用状态 | 修可用性或安装路径，不要改 description |
| 要求手动，但模型自动启动 | 平台调用字段与 caller 是否强行调用 | 改对应调用开关或 caller |
| 已发现且允许选择，但命中范围偏 | 真实任务、独特价值与 near-miss | 改 description 与适用边界 |
| 已加载但任务做错 | 输入、正文方法、资料或脚本 | 修执行方法，禁止继续堆触发词 |
| leaf 已收窄，caller 仍无条件调用 | 上层条件与用户政策 | 修 caller，保留 leaf 的合理用法 |

没有加载记录时，只给候选归因和静态建议，不宣称误触发已复现。修改落在权威源码。

## 2. 改写 Description 与调用开关

- 写清用户想达成的连贯结果、决定性输入、隐式触发线索与高价值排除边界，不把内部实现步骤塞进 description。例：把“处理所有日志问题”改为“摘要用户已提供的日志，归纳错误与缺失信息；需要登录服务器排查时不使用”。
- 不把全部负例抄进 description，也不因请求含 `issue`/`fix` 就硬拉触发。
- 改调用开关时只改目标字段，保留无关正文与其它平台开关。

## 3. 触发实验与选版（仅在有运行条件与预算时）

用运行器真实加载记录判定触发，不以回复中提到 Skill 名称代替加载。

1. **构造高区分度查询并分层切分**：正例覆盖真实上下文（路径、细节、口语/省略、未直呼领域名的隐式意图、嵌入多步流程的任务），不用模型靠基础工具一步能做完的简单常识题充数；负例选共享关键词或相近概念的 **near-miss**，禁用毫无重叠的送分负例。按正负例比例分层切分训练集（用于改写）与验证集（用于选版），固定模型、工具、权限和正文；只测 description 时不动正文。
2. **重复观测**：预算内重复独立运行，记录计数与比例（如 `2/3`）；启动失败、超时与记录缺失单独报告，不算未触发。需要阈值时实验前定好，不事后反调。
3. **从训练失败提炼泛化边界**：只看训练集失败指导改写（验证集失败不喂入改写过程），按任务族修适用边界，禁止把单个失败查询词塞进 description；连续几轮局部微调无提升时，改换结构性不同的表述框架，并先核查用例标签与可达性，不要机械加长。
4. **用验证集选版**：按既定错误代价选版（末版未必最好），**不要**拿验证集具体失败继续微调后仍宣称它是未见泛化证据。差距在噪声内就保留基线。

交付采用或建议的文字、选择理由、正负计数、未覆盖边界与已用预算；无运行条件时明确标注待实测。
