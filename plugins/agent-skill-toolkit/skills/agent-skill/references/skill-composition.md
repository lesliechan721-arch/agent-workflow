# Skill 组合、多组件架构与重构边界

拆分职责、设计或评审多 Skill 工作流与公开入口，或重构已有 Skill 体系时读取。创建、重构与评审采用同一套边界标准。

## 1. 公开入口与 Skill 边界

从**用户会请求的结果**归组能力（如编写、重构、评审、部署），而不是按目录或内部对象切分。判断一个能力是否值得独立成 Skill，看四件事：**独立用户结果、权限边界、证据生命周期/独立裁决需要、实际复用价值**。能给分支起名字，不构成拆分理由。

重点检查以下组合反模式：
- **薄壳转发宏与投影膨胀**：如果一个 Skill 的正文几乎只是“直达某内部参考 + 复读一遍通用边界/位置/恢复条款”，应先质疑该入口是否带来足够的发现收益，而不是靠构建期复制几十份投影维持表面对称。
- **多分支重复法典**：同一入口下的多条路线/Playbook 共享的权限、预算、停止条件和工作位置，只在入口维护一份权威正文；子分支只写该分支独有的操作步骤与反模式。
- **为复用资料硬建 Skill**：几个已知任务只是读取同一组规则，直接共享稳定位置的普通文件即可；只有资料本身值得独立发现，纯参考 Skill 才有入口价值。

同时比较**机器上下文成本**（常驻 description、单次路径读入与跳数）和**人的选择成本**（需记住的入口与内部概念），保留有价值的人工判断。当**仅用户手动启动的 Skill** 数量超出人类记忆负担且不宜直接合并时，允许设一个同样**仅手动启动的路由 Skill**替人列索引，但它只能提示人类该显式启动哪个目标，绝不能宣称自动调用它们（与应避免的“主动两跳纯索引 Skill”区分）。

## 2. Caller、Leaf 与共享交付

- **各自负责自身结果**：每个 Skill 定义自己的动作与完成条件。调用其他公开能力时，只说明采用条件、本次范围、权限和如何核对结果，完整方法留给对方维护。
- **共享交付核对**：确认最终消费包里文件真实可达、读取条件明确、权威正文只有一处；分清“源码”“构建时复制”与“安装依赖”，不把生成副本当权威源，不靠人工互相调用手动宏取得共享规则。
- **执行角色与独立性**：已具备条件并获派任务的执行者直接完成分配范围，不重放同级协调步骤。需要独立判断时，核对作者是否参与、上下文是否干净隔离、原始依据是否可达；换个 Skill 名称或只加一层包装不产生独立性。

## 3. 多 Skill 工作流与插件边界检查

设计或评审跨组件工作流时，按**实际任务路径**从头走到尾，不只孤立看单个 Skill：
1. **路由与授权**：核对首入口、必经下游与普通直接路径；确认没有把手动宏当成自动下游，也没有让可选高成本步骤变成默认必经阶段。
2. **真实交接**：沿上游实际生成物检查下游所需的目标、决定、约束与验收是否完整可达；摘要不能只剩进度而丢失任务定义。
3. **固定输出必要性**：只有用户明确指定格式、真实程序 parser、外部文件消费、恢复或跨上下文交接才需要结构化输出。仅为同一会话下一步模拟函数返回的 `nextSkill` / `artifactPath` / 状态 JSON 应删除。
4. **失败与恢复**：核对真实失败后已产出什么、哪些工作可安全继续、谁负责重试；对外部或用户可改状态，保留最小可行恢复，不为假想失败堆叠补偿协调层。
5. **插件拆分依据**：独立安装价值、不同受众、运行依赖、权限或发布节奏才支持拆插件；只有源码目录不同或方法共用都不自动决定拆或合。通用内容方法与 Skill 机制层分开维护，避免普通文档被迫加载 Skill 协议。

## 4. Skill 级重构手法

重构已有 Skill 或多 Skill 体系时，先用 `agent-content` 的内容重构手法做内容层重构（锐化去抽象、剪枝去免责、层级重组、规则上提），再按实际问题施加 Skill 层重构：

| 问题信号 | Skill 层重构动作 | 核对要点 |
| --- | --- | --- |
| 薄壳入口、同类动作拆太碎或投影过多 | **合并入口**，将差异下沉为条件参考 | 核对旧调用方迁移、权限与独立裁决边界不被破坏 |
| 主动 Skill 覆盖面过宽或常驻纪律误装成 Skill | **收窄触发面**，或将全局极简纪律移入 Rules/工作流入口 | 核对剩余任务族的触发正反例与显式调用路径 |
| 重复、脆弱的解析/计数/校验靠长 prompt 勉强约束 | **逻辑下沉脚本**（读 `references/script-authoring.md`） | 脚本有 `--help`、明确退出码与错误诊断；正文只留调用与业务解释 |
| 同源规则改写后不确定是否引入隐蔽行为退化 | **建基线对照消融**（读 `references/ablation-acceptance.md`） | 固定基线、任务与权限，比较实际产物与成本，不拿字数下降当收益 |
