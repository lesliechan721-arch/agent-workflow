# 工作流评审

以实际任务路径为单位，核对每个交界处能否把工作推进到结果。

## 路由与职责

从原始请求核对首次入口、必要下游和合理的普通执行路径。某个下游仅允许用户启动时，调用者不能把它当作自动流程的必经能力。description 潜在重叠需结合真实调用记录，不能直接当成已发生竞争。

把每个组件的主要动作与完成条件放到路径上比较。同一执行者复用不同方法可能合理；两个组件重复要求相同调查、相同产物或相同同级协调，才需要查是否冗余。实现者、独立判断者和实际执行者的结论不能相互冒充。

检查当前入口能否完成有意义的任务。通用能力可以接收调用者给定的路径和范围，但不应为一个上层项目硬编码阶段、状态或发布政策。

## 交接与证据

沿上游本次生成物检查下游需要的目标、重要决定、领域资料和验收条件是否完整且可达。摘要不能只保存进度而丢失任务定义；路径存在也不等于接收者已经读取。

真实交接测试让下游消费本次产物。分别测试上游和下游的手工样本可以定位局部问题，不能替代整条路径。需要独立上下文时同时检查输入来源和作者参与，不能以换名字或打开另一个 Skill 证明独立。

机器身份、运行事实及结果状态由真实工具或消费者定义。组件需要记录跨上下文工作时保留必要内容；同一会话内部继续工作不必为了模拟接口增加状态协议。

## 权限、失败与恢复

区分只读、修改、执行和远端动作的实际授权。可选实验或高成本步骤不应因为处在调用链中就变成必经阶段。

沿真实失败路径检查：已完成的结果是什么，后续哪些动作还能继续，谁拥有重试或恢复能力。对用户可修改或外部系统拥有的状态，不能承诺全链路补偿；保留最小可行恢复而不是为每种假设失败增加协调层。

## 依赖与成本

区分构建时复制与运行时读取，核对交付包中的工具和资料是否足够。声称独立运行时使用只有声明环境、交付物和输入的实际证据；环境描述或 manifest 不能代替运行。

比较同一任务的直接路径与组合路径：增加的方法是否减少猜测、试错或人工干预，隔离是否满足真实证据要求，调用与导航是否增加无用负担。必要领域知识和独立判断不能仅因增加字符或步骤被删除。

建议指出真正应修改的组件与影响范围。缺少关键运行前提时报告受限结论，不把尚未证实的全链路推演写成必然失败。
