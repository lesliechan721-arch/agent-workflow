# Eval 设计方法

只在任务要求创建或修改 Eval 资产时读取。普通 Skill 变更不自动引入脚本、固定用例数量或模型运行。

## 先固定测试问题

区分加载、首次入口、允许组合、行为、产物和成本，并说明是在验证现行约定、适用范围还是增量价值。标签来自用户目标、适用要求与实际前提；description 和 Oracle 相容只说明约定一致。普通执行、明确方法选择和辅助使用按各自目的定义预期，未验证收益作为假设。

使用调用方明确提供或目标环境已有的 runner 合同/示例。没有格式依据时先明确目标 runner，或给出人读案例草稿；不能发明“通用 Eval JSON”或让格式猜测进入发布集。runner 的字段名、版本、路径和 CLI 只在其适配资料定义，本文件不指定某个实现。

## Case 与 Oracle

关键案例说明现实场景族、决定性条件、可观察结果及允许差异；边界或回归说明改变哪个最小条件会改变正确结果。不要只写“改变条件即可翻转”。标签依据可来自用户合同、Skill 规则和真实 fixture；已知争议不伪装成确定标签。

合成案例可以覆盖真实任务；挑战或机制探针应标明范围，不冒充常见分布。按场景族而非同义句数量计覆盖。分别说明漏触发与误触发代价，正负数量平衡只是诊断安排。

断言检验业务行为，不强迫复述术语、固定内部分阶段或无用途 JSON。合理的可选辅助能力不应因不是顶层 owner 而被判失败。

## 前提、fixture 与 grader

依赖文件、权限、状态或命令结果的场景，fixture 必须确实提供；准入拒绝与有效输入下的语义失败分开。涉及独立判断或委派时，交代起始角色、作者参与、历史来源、已有执行安排和负责范围；由这些前提及明确要求推导 fresh 与代理数量。

源设计推理可声明场景假设；真实独立性结论需对应的上下文构造、任务分配与执行证据。按需要比较协调者和已受委派执行者，并同时验证结果、权限与所需隔离。工具不可用和工具可用但主动不用分别观察。

检出能力使用未提示具体错误的有效目标及等价正确反例；修复、降级和输出格式只证明各自能力。交接效果让下游消费本次实际生成物，保留原始材料和可达指针；两端的人工样本只作为各自或对照输入。

写操作限制允许变更和实际产物；只读规则不能只靠 sandbox 禁写来证明模型主动遵守。CLI test double 明确模拟范围并拒绝未知操作，不能充当真实产品成功证据。机械结果交给文件/parser/调用日志，语义部分说明 grader 和允许差异。

普通 case 只保留所需字段；规则追踪、代表性和运行资格可写在伴随说明里，不为审计向严格格式塞入新字段。

## 比较与交付

冻结用例、Oracle 和 grader，按任务族、执行者与环境比较 baseline/candidate。评估收益时，普通无 Skill 基线保留相同目标、必要材料、工具和权限；移除强制调用已移除能力的悬空指令，并记录这项控制差异。必要原始依据缺失应归为 baseline/fixture 问题。

分别记录结果质量、偏离、人工介入和成本。Oracle 改变后重新审核；样本比例结合代价、方差和旧版表现解释，不用新标签宣布旧版无回归。

交付分别说明结构检查、独立 Oracle 审核、真实运行的实际状态。发布必需案例由项目政策和可执行前提决定，不能全部设为必需，也不能通过全部关闭验收隐藏缺口。作者自检不签发独立准入，运行另需授权。
