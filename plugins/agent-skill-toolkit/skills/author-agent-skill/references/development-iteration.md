# 完整开发中的验证与修复

用户委托完整开发，或明确要求当前修改后的评审、实验时使用。局部修词和只写用例按其原范围完成。

## 按证据定位下一步

核对当前产物、已完成检查、验收缺口和剩余预算。确定性错误先修对应文件或工具；不要用更多文字补偿脚本实现、分发或输入前提的问题。

需要质量判断时使用 `review-agent-skill`；需要评价用例或异常归因时使用 `audit-agent-skill-evals`。提供当前目标、原始依据、实际结果和可访问材料。独立判断需要未参与本次实质起草的合格上下文；缺少条件时继续完成允许的实现与检查，标明独立审核未执行。

## 实验与修复

只有实验能改变当前判断，且任务允许模型成本与相应副作用时，采用当前运行器。固定比较用例和评价规则，按运行器合同取得与本次输入相符的有效准入；身份和执行凭据由运行器提供。

查看实际失败和成本异常。先排除资料、Oracle、评价器、环境和方差，再修正文或脚本。修复应对应可复用任务族，并检查相近正确场景；不要为一个失败不断堆叠共同规则。

Oracle 变化使受影响对照失效，需重新建立比较。追加实验不超出既有预算。条件齐备的已授权验证继续完成，不将每个正常步骤再次交给用户决定。

## 结束

验收满足，或预算、能力、资料达到边界时，交付完成物、实际结果和未解决问题。过程资料只在恢复或跨上下文使用需要时保存；当前任务的进度不能代替目标与验收依据。
