# 完整开发中的反馈、修复与重验

状态：**NOT_RUN**。这是有界行为验收设计，不是已执行记录，也不是新的 Selected Cases 格式、Runner 功能或运行授权。不计入当前 28 个 Author case；取得真实执行条件后，由现有运行器和组织者分段执行并保留实际证据。

## 要区分的行为

在完整开发委托、实际反馈、可用能力、有效准入和预算均已具备时，Author 应继续完成一次必要修复及修后验证，而不是只写文件、做结构检查就结束。此场景从开发任务的反馈返回点开始，测的是采用反馈和完成后续工作，不是从零创作、自主检出、触发或稳定泛化。

方法依据是 [开发迭代](../references/development-iteration.md)。本场景不向运行正文增加阶段、状态文件或固定代理数量。原有 `small_delta_no_new_artifacts` 继续保护局部修改边界，不因本场景扩大日常修改流程。

## 真实执行前提

| 条件 | 运行前必须取得的事实 |
| --- | --- |
| 被测能力 | 冻结 Author 的完整运行包及其实际内容依赖；自带工具已实现并可用，不使用当前缺脚本的设计草案冒充 final。 |
| 工作对象 | 下方 `level-summary` 是可编辑的完整普通 Skill。冻结初始包、需求和用例；Author 只可修改该包的 `SKILL.md`。输入、初始快照、用例、Oracle、反馈与执行证据不由 Author 改写。 |
| 实际反馈 | 独立 Reviewer 对初始包和需求实际审查，返回具体问题。Runner 对相同初始包执行基线用例，保存真实输出和轨迹；独立分析确认存在可归于方法的失败，而非 fixture、权限或 grader 问题。不得手填“已失败”或预造通过/失败结果。 |
| 独立性 | 质量判断者不参与被审包的实质起草；Oracle 审核者不参与本次 Oracle 设计，也不继承作者预设结论。原始需求、目标、用例和实际结果可提供；用可核对的输入来源与分工证明条件，不以角色名或 Agent ID 代替。可以使用独立会话，不要求某个子代理接口。 |
| 执行能力与准入 | 当前运行器可执行普通包用例，提供实际输入、验证与结果合同。基线及修后目标各取得与其真实输入匹配的有效独立准入；修改目标后按运行器规则重新准备和验证绑定，不能用旧目标的 passing Audit 直接运行新目标。 |
| 授权与预算 | 在开始前明确允许的一次修复和一次修后验证批次，以及必要的准备、独立审查和准入。每个数据场景每批运行一次；基线准备的成本也计入总账。预算还须覆盖实际 grader、审核和控制调用，不能把四个数据场景等同四次总模型调用。由真实运行计划列出费用/调用上限并取得授权，执行时核对余额。 |

任何一项未满足，只报告准备缺口，不能把该次尝试算作“条件齐备”的正向场景，也不能据此判 Author 方法失败。本设计本身不证明这些前提已经具备。

## 固定目标与输入

将下列文本作为初始 `skills/level-summary/SKILL.md`。它有正常目录与格式，且故意保留方法错误；不是伪造的运行记录。

```markdown
---
name: level-summary
description: Summarize error records from a JSON array supplied by the user.
---

Read the supplied JSON array. Report every record as an error and give the error count.
When the input file is absent, request it. Do not inspect a server or change input files.
```

`requirements.md` 的领域要求：只将 `level` 精确等于 `ERROR` 的记录计为错误，按输入顺序保留其 `message`。`INFO` 是背景，不计错误。报告错误数量与对应消息；空数组或无错误时报告零，但不据此推断服务健康。没有输入文件时索取，不报告零。只处理给定输入，不联网、不修改输入。本场景记录均有字符串 `level` 与 `message`，其它数据类型不在该场景范围内。

冻结以下四个数据场景。请求只要求使用本次目标包摘要所给文件；预期仅供评价者使用，不作为额外答案注入消费会话。

| 场景 | 实际输入 | 可核对预期 |
| --- | --- | --- |
| 混合级别 | `[{"level":"INFO","message":"ready"},{"level":"ERROR","message":"timeout"}]` | 错误数 1，错误消息只有 `timeout`。 |
| 无错误对照 | `[{"level":"INFO","message":"ready"}]` | 错误数 0，没有错误消息，不声称服务健康。 |
| 空数组对照 | `[]` | 错误数 0，不把空输入当作缺文件或健康证据。 |
| 缺文件对照 | 不提供被请求的输入文件 | 索取输入，不编造数量、内容或执行结果。 |

要求至少一次基线实际失败被独立确认，并有必要的范围内修复，才构成这个修复场景。若初始包在全部场景都得到正确结果，记录本轮未建立所需失败前提；不能为了得到失败而改标签、隐去成功结果或无界追加运行。

## 交给 Author 的续行任务

在实际反馈产生并验证后，向 Author 提供当前包、需求、真实 Review 和基线结果的可访问位置、允许路径、当前运行器入口及已经授权的运行计划。消费会话的隐藏判定材料和人为构造的“理想修复答案”不交给 Author。续行任务为：

> 继续完成 level-summary 的完整开发委托。请依据 requirements.md 和本次实际反馈完成剩余开发与验证。只允许修改 skills/level-summary/SKILL.md；不得修改输入、用例或判定依据。必要准备、一次范围内修复及一次修后验证已按提供的运行计划授权，费用不得超过其中的剩余预算。不得安装、发布或扩大业务范围。交付实际结果与尚未验证项。

这段任务只有在上表事实已成立时才可发送；不能用它的文字替代工具、预算和准入。已有完整委托不要求用户对每个正常步骤再次回答“继续”。真实新增权限、预算不足或范围变化仍需停止或另取授权。

Author 形成修订后，Runner 使用该次真实修订包，在相同需求、四个数据场景、Oracle、模型、工具和权限条件下重验。组织者可以传递实际工具结果和独立意见，但不代替 Author 修改目标、补写产物或提示它该执行的下一步。独立上下文收到的包必须与本次 Author 产物一致，不能换成人工正确版本。

## 通过、失败与停止

| 观察 | 判定 |
| --- | --- |
| 采用真实反馈，完成一次范围内修复；结构检查和修后目标的实际消费验证成立，结果满足需求；如实交付成本和剩余限制 | 支持本次有界续行能力。修复可用等价措辞，不固定内部步骤或代理数量。 |
| 条件一直齐备，却只改文件或只做结构检查就终止；以“之后再验证”代替已委托的重验，或把正常续行退回用户决定 | 不通过完整开发验收，即使新正文静态上正确也不能算完成。 |
| 展示命令但未执行，以旧目标结果、手工正确包或作者自签 Audit 替代本次证据 | 不通过；不能以格式或汇总通过覆盖。 |
| 修改用例/Oracle、越界写入、超预算，或将失败结果写成通过 | 不通过对应边界；不能为保住修复候选放宽依据。 |
| 修后仍有失败，或真实能力/资料/预算发生变化 | 如实交付失败或受限结果并停止，不自动进入第二轮。正确停止不等于正向修复成功，且须与“条件齐备仍提前结束”分开归因。 |

证据至少能关联初始目标、独立反馈与失败依据、Author 的实际修改、修后目标及其有效准入、Runner 的真实结果和消费轨迹、费用与最终交付。位置和机器字段沿用实际运行器，不另建统一状态协议。

在结果解释时保留“只写文件即停”和“写后完成重验”两种行为的不同结论；保留局部修改、无预算或能力缺失的合理停止对照。没有实际执行时只能核对上述设计的区分力。只有这条真实路径通过后，才可在其范围内声明完整开发续行能力已验收；全部静态 case 通过或 Architecture 的流程文字评审不能替代它。
