# Audit Agent Skill Evals

判断用例能否评价所声称的能力，以及运行结果支持什么结论。被测 Skill 和用例保持只读；按请求交付审核意见、结果解释或正式准入文件。

## 先检查评价依据

从用户目标与领域要求推导预期行为，再核对 Oracle（决定通过或失败的规则）。不要从现有标签或通过率反推正确答案。

逐例核对：输入是否提供决定性事实，任务能否到达所测步骤，断言是否可从实际输出或轨迹判断，合理不同做法能否通过。用于测试文件处理、工具调用或修改范围的前提应有真实 fixture，而不只是一句“环境已经准备好”。

区分正在测什么：加载、首次入口、允许辅助、检出、已知修复、范围控制和任务产物分别需要证据。只限制多做不能证明会做；提示错误位置的修复例不能证明自主检出。检查一个最小条件改变后结果应不同的对照，并提供等价正确例防止过度纠正。

细查 fixture、观测方式、错误代价或比较条件时使用 [Eval 审核标准](references/eval-audit-standard.md)。源审核可直接进行；只有请求正式机器准入时，才使用 [正式准入](references/formal-admission.md)。

## 解释运行结果

读取实际产物、调用轨迹与本次环境。先判断问题来自用例前提、Oracle、评价器、运行环境还是 Skill 方法。声明、汇总和文件标题不能代替它们所声称的执行事实。

比较基线与候选时核对资料、工具、权限、用例和评价规则是否相同。分别看漏触发、误触发与行为错误的代价，检查低样本波动和耗时异常；不只报告总通过率。高影响失败不能被其它成功样本抵消。

修正 Oracle 后，受影响的旧比较不再支持新结论。没有足够运行证据时给出可检验的归因和缺口，不把每个失败都归为生产 Skill 需要新增规则。

## 交付

说明哪些预期成立、哪些用例或结论有问题、最直接证据及最小修正。源审核、独立准入和实际运行分别报告；作者对自己设计的 Oracle 只能自检。追加实验由已有任务授权和预算决定，不在审核中自动运行。
