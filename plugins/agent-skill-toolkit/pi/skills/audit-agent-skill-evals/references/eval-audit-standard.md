# Eval 的评价资格与归因标准

深入审核测试前提、观测方式、对照公平性或运行归因时读取。

## 可达性与观测边界

- **前提匹配场景**：正常完整包应满足基本格式（如 `name` 与目录名一致）；有意非法包测的是拒绝，不同时宣称在测后续方法。
- **观测能证明什么**：加载记录只证明是否加载；首次路由需顺序观测；最终质量需核对实际产物；description 重叠不证明共载。
- **独立性与只读**：新 Agent ID 或一条 fork 参数不足以证明独立——须核对作者是否参与、上下文是否干净隔离。只读规则要在“具备写工具却主动不写”时验证，单靠禁写 sandbox 只证明环境限制生效。模拟工具只覆盖模拟范围。

## Oracle、对照与断言

- **从用户需求定 Oracle**：除非消费者明确要求精确格式（如用户手动复制的 JSON 或 parser 字段），否则允许等价措辞、实现与无关顺序。
- **避免漏测与泄题**：自主检出例不能泄露缺陷位置，并配决定性条件相同但结论正确的反例。交接测试须用上游本次实际产物，不拿两端手工样本拼凑。
- **机械与语义分工**：文件存在、精确字段、修改范围交机械检查；语义质量按可观察目标判断，不以“存在摘要标题”冒充合格摘要。
- **识别无区分力断言与送分负例**：基线与候选全过往往只测到常识；全挂先查坏前提或坏 Oracle；触发负例若与目标技能毫无概念/关键词重叠，只会虚高通过率而测不到精度边界。

## 公平对照与结果归因

- **基线公平**：固定资料、工具、权限、模型与评价规则。无 Skill 基线移除对已删能力的悬空调用，但保留原始领域资料；工具本身若属于本次候选干预，单独注明。
- **拒绝对单一异常过拟合**：区分真实常见任务、回归例与合成 challenge；小样本（如 `1/3`）只报计数与不确定性，不当成稳定概率；不为单个极端合成例给生产 Skill 叠一堆新规则。
- **逐层排因与隐性退化**：看真实失败轨迹，先排资料缺失、错标签、评价器误判、环境故障与方差，确认属 Skill 根因后再建议覆盖该类任务的最小修改，并检查相近正例不退化。同用例多次运行出现高方差往往指向指令歧义；单用例耗时或 Token 明显离群（如 3 倍）即使结果通过也应检查轨迹定位死循环或多余步骤。
