---
name: reconciling-git-merges
description: "当 Git merge 需要协调双方意图时使用：合并发生冲突或正在进行，或 clean merge 会组合相关的行为、契约或依赖。不要用于 fast-forward、already up to date 或修改明显独立的 clean merge。"
---

1. **看清这次合并。** 检查当前状态和相关历史。修改前确认源与目标，不得丢弃、覆盖或混入无关本地工作。仅分析时不得改变 refs、index 或 worktree。若只是 fast-forward 或 already up to date，按普通 Git 流程处理并停止使用本技能。

2. **寻找一手依据。** 针对每个文本或语义冲突，查阅相关提交、测试、代码和关联 PR/issue。Clean merge 只证明文本兼容，不证明组合行为正确。跨文件追踪行为、契约和依赖；同文件修改只是一条线索。

3. **协调双方意图。** 兼容时保留双方意图；不兼容时按明确的合并目标处理并说明取舍。若目标和证据都无法决定优先级，提出待决问题。只做具体交互所需的集成修改，不发明行为。

4. **验证组合结果。** 运行项目要求的检查，以及能覆盖双方交互的针对性测试。修复合并后才出现的问题。

5. **只在用户要求且验证通过后完成。** 仅当无未解决条目且项目要求的检查通过时，才暂存并提交；否则保持未提交并报告阻塞项。合并提交必须包含双方意图协调和组合验证所需的集成修正；不得把未经组合验证的合并结果与后续集成修正拆成多个提交。合并提交属于本技能的完成步骤，不转交其他 Skill。不得纳入无关本地修改，也不得在未被要求时推送。
