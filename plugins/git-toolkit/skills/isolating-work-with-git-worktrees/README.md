# Isolating Work with Git Worktrees

当任务需要独立 checkout 时，安全创建或精确复用 Git worktree，保护当前工作区和未完成修改。

## 适合使用

- 用户明确要求 worktree。
- 需要在不触碰当前任务的情况下处理另一分支。
- 需要同时维护多个 checkout。

## 不适合使用

- 继续当前 checkout 中的同一任务。
- 只读检查或例行 worktree 管理。
- 需要独立 refs 或对象库的完整仓库隔离；此时应使用独立 clone。

## 安全边界

Skill 会在变更前检查路径、分支和现有 worktree，在创建或复用后验证实际结果。它不会仅因工作区存在未提交修改就自动创建新 worktree。

本次为检查、测试、复现等临时任务创建的 worktree，使用结束且无需保留时会自动清理，无需再次确认。已有工作区、用户要求保留或仍供后续工作使用的工作区不会自动清理。运行中的任务、待保留的文件或尚无分支/tag 引用的提交会阻止自动清理。

平台工作区通过平台机制清理，手动 worktree 通过 Git 清理。清理不会强制删除或顺带删除分支；完成后会说明清理结果，受阻时保留现场并报告原因。
