---
name: isolating-work-with-git-worktrees
description: "当任务需要独立 Git 工作目录以保护当前工作区或并行检出另一分支时使用，例如用户明确要求 worktree、需要在不触碰当前未完成工作的情况下处理另一个独立任务，或需要同时处理多个分支。若现有环境已提供所需隔离则复用。不要仅因工作区有未提交修改或任务涉及代码修改而触发；用户要继续当前 checkout 中的同一任务且没有隔离需求时，使用当前工作区。也不要用于不需要独立 checkout 的只读检查、例行 worktree 管理或需要独立 refs/对象库的完整仓库隔离。"
---

1. **选择隔离方式。** 复用已有且满足任务要求的隔离环境；需要创建时优先使用平台原生能力，否则使用 Git worktree。Worktree 共享对象库和多数 refs；需要仓库级隔离时使用独立 clone，或明确提供独立 refs 与对象库的平台环境。

2. **遵守创建边界。** 手动创建时遵循用户或项目路径约定；没有约定时使用仓库根目录下的 `.worktrees/<分支或任务名>/`，不自行换位置。创建前确认 `.worktrees/` 已被忽略；否则停止并取得明确处理方式，此前不创建 worktree 或分支、不换路径、不擅自修改并提交 `.gitignore`。保护原工作区的 HEAD、index 和 tracked/untracked 内容，不强行占用已有 worktree 或已检出分支。若隔离是任务条件，创建失败时不静默退回当前工作区。

3. **在隔离环境中交付。** 任务操作前核对工作区的路径、基点、分支和初始状态；将操作及其产生的修改限制在该工作区，交付时报告路径与分支。

4. **按用途清理。** 本次为检查、测试、复现等临时任务创建的 worktree，使用结束且无需继续保留时自动清理，无需另行确认。用户要求保留、仍供后续工作使用或复用的已有工作区，不自动清理。清理前确认没有运行中的任务、没有待保留的未提交内容或文件，且需保留的提交已有分支或 tag 引用。

平台创建的隔离环境通过平台机制清理；手动 worktree 通过 Git 管理，不直接删除目录、强制清理或顺带删除分支。清理受阻时保留现场并报告原因；交付时说明工作区已清理或仍保留。
