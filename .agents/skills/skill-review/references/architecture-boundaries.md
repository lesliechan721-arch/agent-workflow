# Architecture Boundaries and State-Machine Risk

只在 Skill 涉及异步生命周期、重试、跨 actor 通信、权限或复杂工具编排时读取。

## 默认职责矩阵

| 内容 | 默认 owner |
| --- | --- |
| 使用时机、领域策略、项目约定、稳定默认值、非显然 gotcha | Skill |
| 参数类型、合法值、必填字段、返回结构 | Tool schema |
| 真实状态、事件顺序、超时、取消、并发、幂等、后代关系 | Runtime |
| 确定性解析、生成、转换、一致性和静态校验 | Script |
| 叶子职责、固定配置、最小输出约束 | Role |
| 未证实、低概率、组合爆炸边界 | Eval / issue |

Schema 出现一个字段不等于 Skill 必须为它建立政策；只有字段选择表达稳定产品策略，或真实 trace 证明模型会误用时才写入 Skill。

## 自然语言状态机信号

组合出现时进入架构审查：

- 三个以上命名状态或状态字符串。
- timeout、累计窗口、重试/恢复额度、pending 标记。
- “只允许一次”“同时最多一个”等计数不变量。
- 两个 actor 通过消息协商状态。
- 活动、终态、迟到消息、取消、恢复和关闭顺序分支。
- 多段连续“只有 A 才 B；否则 C；若 D 再 E”。
- 同一流程经过两轮 review 后仍持续追加例外。

风险：

- **low**：少量稳定不变量，例如“只有明确终态才视为完成”。
- **medium**：模型需记住阶段、额度或多个互斥条件。
- **high**：跨 actor 协议、竞态、乱序处理、隐式持久状态或安全关键迁移。

## 处理顺序

1. 重新确认该功能是否属于 Skill 原始目标，是否有 observed/normative 证据。
2. 删除非核心机制或缩减为少量稳定不变量。
3. 使用 runtime/tool 的一等状态、取消、等待和通知能力。
4. 将确定性、静态、可测试部分移入 script。
5. 将尚未证实的边界放进 eval 或产品 issue。
6. 最后才修改自然语言；修改应替换旧分支，而不是追加例外。

把完整状态机移动到 reference 不能解决职责问题。普通脚本也不应通过文件、Git、shell sleep 或轮询模拟 runtime mailbox。

## 跨 role 协议

多个 role 复制同一状态协议时检查：

- 是否存在单一权威来源或生成/验证机制。
- 父子双方是否依赖自然语言字符串和消息顺序维持正确性。
- role 是否承担了本应由父调度器或 runtime 管理的生命周期。

默认让 role 保持叶子职责：完成给定任务，返回结果、证据、验证和阻塞；父调度政策留在父 Skill 或 runtime。

## 架构门禁失败

当核心安全或正确性必须依赖模型可靠维护高风险状态机，且没有一等能力、确定性实现或行为证据时，`architecture-ownership` 应失败。仅影响少见恢复路径且有安全降级时，通常是 P2 或 advisory。
