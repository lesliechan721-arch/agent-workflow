# Code Review Workflow

在 {{platformName}} 上执行代码审查。这个源码 skill 展示实际工作流应放在 `skills/` 中；公共 `/review` 命令只是手动入口。

完成标准：审查范围明确；每个问题都有位置、影响和可执行建议；没有证据的问题不进入报告；执行期间不修改被审查代码。

## 执行步骤

1. 确认审查范围：用户指定路径优先；没有指定时查看当前分支改动
2. 范围过大时先提出具体拆分或请求用户确认
3. 阅读 diff 和判断行为所需的相关上下文
4. 按 `references/review-rules.md` 检查正确性、安全、性能和可维护性
5. 逐项核对证据；不能定位或解释影响的问题不作为 finding
6. 按严重程度输出问题、建议和测试缺口

## 验证

- 确认报告覆盖了用户指定的全部范围，或明确列出未覆盖部分
- 确认每个 finding 都包含位置、影响和建议
- 确认工作区没有因审查流程产生修改
- 任一检查失败时补充证据或修正报告，再重新核对

{{#if supportsCommands}}
用户也可以使用 `/review` 命令快速启动这个工作流。
{{/if}}

## 输出格式

```markdown
## 审查摘要
- 范围：<审查范围>
- 结论：<通过 | 需要修改>

## 发现的问题
- [严重程度] <文件:行> <问题与建议>

## 建议补充
- <需要补充或运行的测试>
```

## 边界

- 不要自动修改代码，只报告问题
- 不要在回复、日志或命令输出中展示 `reviewServiceApiKey`
- 审查范围过大时先请用户确认
- 没有发现问题时说明实际检查过的范围和仍存在的测试限制
