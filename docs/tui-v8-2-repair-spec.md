## 行为与关键场景

### F01：项目声明失败隔离

项目提醒读取结果必须显式区分下列状态，可使用内部 discriminated union 表达：

| 状态 | 含义 | 用户行为 |
| --- | --- | --- |
| `ready` | 声明可读且有效，包括有效空声明 | 按实际声明与当前观测计算待同步目标 |
| `absent` | 已确认声明不存在 | 无声明同步任务；不报告读取失败 |
| `invalid` | JSON、schema 或路径安全校验不通过 | 显示项目问题，提供诊断和修复后重载路径 |
| `unavailable` | 权限、I/O 或项目位置解析失败，不能可靠读取 | 显示无法读取，不推断声明为空 |

`invalid`、`unavailable` 不拒绝整个 `loadStatus`。首页、健康来源、个人插件与安全诊断继续可达；项目同步入口显示“无法读取本项目插件声明”或同等清楚的说明。失败信息必须可在关闭提醒后再次找到，不得只闪现一次。

没有有效声明证据时不生成声明同步计划。依赖该声明的项目写入继续按既有校验阻止；不得用空 roots、旧 roots 或猜测目标授权写入。保持既有 cleanup 等安全恢复合同，不额外扩大阻断范围。

取消仍作为 `AbortError` 向上传播，不投影成项目错误。优先复用 status 已取得的同次读取证据；确需增加读取信息时，在现有读取边界提供，不再添加一次独立存在性探测来猜测 `absent`。当前 `readPluginIntentState` 会把缺失折叠为空状态，实现时需保留两者区别，同时保持已有调用方的严格校验语义。

### F02：复查归属与生命周期

只读复查只观察外部状态，不执行安装或重试。开始时绑定原操作、receipt/intent、会话及当前结果生命周期，不在等待后重新从可变字段推断归属。

- 同一有效结果上的重复复查合并为一个在途请求；可显示正在检查，重复输入不启动额外外部读取。
- 用户实际离开结果页，包括 `h`、`Esc` 或进入其他操作时，该复查失效。尽力取消底层读取；不能取消时丢弃完成或失败响应。
- `H` 重载、会话 retirement/dispose 或信号取消同样使请求失效。即使底层忽略取消，也不得回灌结果、抛出未处理异常、跳页或更新旧记录。
- 仍在原结果生命周期中完成时，更新结果和原操作记录，保留 `operationId`、`operationRecordId`、返回位置及原有执行事实。复查更新最终验证事实，不能凭验证成功推断此前写入或脚本成功。
- 历史中的既有失败证据仍可追踪；当前验证结论必须清楚反映最新有效复查，不把历史失败当作仍未确认的当前结果。沿用现有脱敏和记录容量边界。
- 离开后重新进入同一操作，不重新接纳上一生命周期的响应；原记录保持离开前最后一次有效状态。

同一操作记录更新复用现有 history 能力；不新增后台复查管理器、持久安装台账或跨会话任务。

### F03：本次安装结果的精确归属

完整外部 inventory 是观测输入，本次安装结果是目标投影。先确定当前操作目标，再关联验证证据：

| 操作 | 本次目标边界 |
| --- | --- |
| 首次安装，显式 Agent | 当前 receipt 中实际选定 Skills 与请求 Agents 的组合 |
| 精确重试 | 当前 attempt 的 `attemptedTargets` / `retryPairs`，保持非矩形组合 |
| 自动 Agent | 当前所选 Skills；Agent 仅来自可绑定的实际观测 |

例如，本次只请求 `review → cursor`，清单中的 `unrelated-deploy → cursor` 与 `review → other-agent` 均不属于本次结果。重试仅尝试 `a → x`、`b → y` 时，不显示或重试 `a → y`、`b → x`，也不把前次成功组合计入此次尝试。

每个结果行按 Skill 与 Agent 身份去重，并区分已验证、确认缺失、结果未知。不能只因同名 Skill 在另一个 Agent 上存在，就确认请求组合成功。自动模式没有可靠 Agent 绑定时保留未确认信息，不显示“所有 Agent 成功”。保留现有 unknown 阻止直接重试、missing 经重新准备和确认后精确重试的边界。

同一投影语义用于首次结果、复查和重试的行、计数、摘要与技术结果。技术诊断可保留必要且已脱敏的额外观测，但明确标为外部清单，不计入本次结果。保留范围、插件身份、内容版本等现有归属信息。Skills 成功不改变原生插件状态。

### F04：结果行与分页同源

F03 生成的最终显示行集合是 Portable 分页的唯一数据源。总数、offset、可见范围、隐藏数、翻页动作和键盘边界都从该集合及实际视口预算计算，不使用所选 Skill 数估算组合数。

保持现有问题优先排序。普通与技术模式、60×18 与 80×24、resize 之后所有行均可到达；切换时尽量保留当前行身份，行已消失时定位到有效相邻行。页面至少容纳一条可阅读结果，不能出现仍有隐藏行却无法继续翻页的状态。普通原生、批量和任务结果沿用各自完整显示集合，不因 Portable 修复失去可达性。

### F05：项目提醒的安全退出

项目提醒支持与现有弹窗一致的公共导航：`q`、应用收到的 raw-mode `Ctrl-C` 关闭提醒并进入正常安全退出守卫；`h` 回首页，`H` 安全重载；`Esc` 或既有返回动作只关闭提醒。

默认 Enter 仍为“稍后处理”，不自动同步。actionable 与 blocked 混合、仅 blocked 均遵守相同导航。关闭、取消退出、回首页或重载不破坏进程内提醒去重；不得绕过活动写入和草稿的既有保护。

抽取或复用提醒、风险确认、协议选择、帮助中的公共导航处理，保留每种弹窗自己的确认与返回语义。不要为了统一退出另建全局键盘状态机。输入上下文仍按既有文字输入合同处理字符。

### F06：所有分页阅读页具有基本键路径

对现有分页阅读页做有界清单核对，至少包含插件技术详情、问题技术详情、来源移除引用、来源技术内容及通用结果。每页通过同一轻量分页适配逻辑提供：

- 可见且可聚焦的上一页、下一页动作；方向键与 Enter 能完成翻页。
- `p` / `n` 调用同一动作；PgUp/PgDn 仅作可选增强。
- 完整条目集合和视口预算驱动页边界，帮助及 footer 与真实动作一致。

不得要求功能键或特殊翻页键才能查看组件、技术字段、引用或诊断。文本输入期间 `p` / `n` 仍是文字。适配器复用现有 action 和分页能力，不扩展为新的路由框架。

### F07：Skills 固定操作栏

`portableSkillSelect` 使用现有 `ContentViewport` 与 `PinnedActionBar` 的内容区/操作栏焦点合同。候选与工具不共享一个线性索引。

固定栏包含“继续（N）”及“选择工具”。从第 100 或第 200 个候选一次 Tab 到操作栏，再次 Tab 返回内容区；操作栏内上下、左右均能移动焦点。Enter 打开选择工具，工具提供全选当前结果、只看已选、清空选择及现有依赖入口，不把工具画成复选框。

Space 只切换当前候选，Enter 查看候选摘要；按钮与 `c` 使用同一继续 actionId，空选择时不可继续。依赖带入项与显式选择保持既有区别。筛选或清空使候选减少后，焦点落到有效项或操作栏；切回列表、查看摘要、访问工具和返回原生平台保留尚未提交的选择。继续仅推进流程，不绕过最终 Review 和风险确认。

### F08：普通页面文案与动作身份

来源默认页、本地存储概览和规则页使用面向用户的说明。示例表达包括“当前使用的目录不会删除”“不属于 AW、无法确认安全或仍在使用的内容会保留”“旧版本满足保留期限后才清理”。最终文字必须准确表达实际服务规则，不承诺所有临时内容都能删除。

版本策略表达为“跟随 AW 的稳定版/预览版目录”“固定版本或 Git 引用”等可理解说明；必要概念可作简短解释。`Active`、`foreign`、`AW_HOME 写锁`、`staging`、`replacement`、`delete claim`、`quarantine` 等内部机制说明进入技术详情。精确年龄、节点类型、安全保留原因和锁证据不得因此丢失。

来源更新等菜单标签去除末尾 `…` 或 `...`。范围内动作通过稳定 actionId 绑定按钮、快捷键、启用条件和执行，不通过中文 label 匹配控制行为。文案调整不改变清理候选、版本策略、确认要求或实际服务语义。

## 重要实现决定与边界

| 责任 | 主要现有入口 | 修复约束 |
| --- | --- | --- |
| 项目声明观察 | `controller-runtime.ts` 的 `loadStatus`、`utils/plugin-intent-state.ts` | 类型化读取结果及失败隔离；复用单次证据，保持写入校验 |
| 提醒投影 | `controller.ts` 的 `TuiStatusLoadResult`、`projectCurrentIntentReminder` | 只有有效 roots 参与目标计算；错误不折叠为空 |
| 复查生命周期与记录 | `controller.ts` 的 `recheckPortableResult`、会话导航、`operation-history.ts` | await 前捕获身份，await 后检查有效性，更新同一记录 |
| 验证与 receipt | `portable/skills-cli.ts` 的 `verifySkillTargets`、`portable/commands.ts` | inventory 与 operation targets 分离，初次/复查/精确重试一致 |
| 展示和键盘 | `console-app-v4.tsx` 及已有布局、分页组件 | 显示集合与分页同源，公共动作复用稳定标识 |

以上相对源码路径均位于 `packages/cli/src/`。具体辅助函数命名、文件拆分和最少请求 token 由实施者决定；无需机械叠加 epoch、sequence 和多套取消状态。必须足以区分会话、操作、结果生命周期和同一结果的在途读取。

优先保持公开 receipt/status schema 及现有消费合同。若修复改变公开字段语义，应同步架构说明和相应消费者测试；不得只在 UI 隐藏错误、却继续对外返回混淆归属的本次结果。无需为此次修复引入迁移、持久 ledger、新锁或补偿事务。

继续复用现有 `AW_HOME` 锁、归属检查、依赖计划、确认票据、执行前声明身份校验及恢复入口。不重写业务执行器或目录删除器，不新增页面来规避既有页面的问题。

## 验收与验证

按 [测试指南](testing.md) 的 Test Value Gate，选择最低且足够真实的层级。禁止用源码字符串、静态快照或原型测试替代生产行为验证；同一风险不在多个层级重复堆叠。

| ID | 必需场景 | 核心断言及最低证据 |
| --- | --- | --- |
| F01 | 无效 JSON、无效 schema、权限失败、symlink 拒绝、声明缺失、有效空声明、取消 | runtime 失败注入与隔离文件测试验证状态区别、loadStatus 可完成及取消传播；真实 Ink 验证健康入口和项目问题可达；依赖无效声明的同步不能准备或写入 |
| F02 | 复查等待中 h、Esc、H、新操作、重复复查、dispose；离开再进入；正常完成和读取失败 | deferred Promise 驱动生产 controller/host，验证合并请求、无异常、晚到完成/失败均不回灌、不污染新操作；有效完成更新同一记录且不丢失执行事实 |
| F03 | 无关 Skill、未请求 Agent、同 Skill 多 Agent、部分缺失、未知、自动模式、非矩形 retryPairs | 真实验证 helper/receipt 路径证明目标归属和状态；公开命令 integration 保护结果消费边界；无关观测不进入本次计数和重试 |
| F04 | 60×18 的 1 Skill×3 Agent；技术模式的 1×2；80×24 的 7+ Agent；多 Skill 部分失败、精确重试、resize | 生产投影验证行集合；真实 Ink 逐页收集身份，证明全部结果可达，切换模式和尺寸无越界、无不可达尾项 |
| F05 | actionable+blocked、仅 blocked；q、Ctrl-C、h、H、Esc、默认 Enter、取消退出 | 真实 Ink/host 验证退出守卫、默认稍后、无自动同步、跨重载去重及既有安全保护 |
| F06 | 超一屏组件、问题技术字段、来源引用和其它现有分页阅读页；双尺寸 | 不发送 PgUp/PgDn 或功能键，仅用方向键、Enter、Tab、p/n 读完全部条目；帮助与按钮准确 |
| F07 | 100/200 个 Skills、中间候选、空选择、只看已选、清空、返回平台 | 真实 Ink 验证一次 Tab 到栏、工具可用、内容/操作栏独立焦点、筛选后有效焦点及草稿保留 |
| F08 | 普通来源/存储、失败、损坏、版本冲突、多项目引用；技术详情 | 检查实际渲染的普通文案与菜单，验证动作行为未变；技术页仍能取得必要诊断，不对源码做禁词扫描 |

关联回归还必须保护以下结果，可复用已有有效测试：

1. project/user 配置草稿部分提交：成功层不回滚、不重复提交，只重试失败应用。
2. 来源检查失败且旧启用目录健康：当前可用性不被候选错误覆盖。
3. exact repair、replace、update：各自绑定确认，不将修复自动升级。
4. unknown 阻止未经确认的重装，精确重试不扩大目标，Skills 结果不污染原生安装状态。

已有测试入口包括 `tui-controller-runtime-v5.test.ts`、`tui-controller-v5.test.ts`、`tui-session-host.test.ts`、`tui-operation-history.test.ts`、`tui-portable-skills-v1.test.tsx`、`tui-console-app-v5.test.tsx`、`tui-stage5-v8-2.test.tsx` 及 integration 的 `portable-skill-commands.test.ts`、`tui-catalog-source-v4.test.tsx`。根据实际责任选择增补位置，不要求新建同名专用套件。

实施先运行直接相关定向测试，交付前运行 `pnpm test:unit`、`pnpm test:integration`、`pnpm build` 和 `git diff --check`。若涉及 catalog source state/mutation，按测试指南追加 `pnpm test:smoke:fetch`；单纯文案修改不因此扩大为来源写入验证。
