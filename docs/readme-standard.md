# 插件与 Skill README 规范

本规范面向 `plugins/` 下会进入 production bundle 的 README。README 是插件用户在安装前和安装后都能读取的产品说明，不是 Agent 执行合同、仓库维护手册或评测报告索引。

## 文档职责

| 文件 | 读者 | 职责 |
| --- | --- | --- |
| `.agents-plugin/plugin.json` | CLI 与平台 | 名称、版本、平台、配置和能力等机器元数据 |
| 插件 `README.md` | 插件用户 | 安装决策、能力概览、快速开始、权限和边界 |
| Skill `README.md` | Skill 用户 | 适用场景、调用方式、示例、结果和限制 |
| `SKILL.md` | Agent | 触发条件、执行步骤、Gate、不变量和完成条件 |
| `evals/README.md` | 维护者 | Eval 语料、运行命令和诊断 |
| `reports/**` | 维护者与审核者 | 正式质量证据 |

README 只说明用户可观察的行为。不要复制 `SKILL.md` 的内部算法、完整触发规则或执行步骤。

## 通用规则

- 使用用户语言说明任务，不以仓库文件结构或内部组件开头。
- 同一份 README 必须同时适合 Git 仓库浏览和安装后的 runtime 文件树。
- 相对链接只能指向同一 production bundle 中的文件。仓库专用材料必须使用稳定公开链接，否则不要链接。
- 不写迁移状态、CI、contract test、生成脚本、Eval runner、batch、trace、coverage、源码 commit 或内部报告登记。
- 不以“完整合同见 `SKILL.md`”代替用户说明。可以在高级参考中链接 `SKILL.md`，但 README 本身必须完整回答用户怎样使用。
- 章节按实际能力保留。没有配置、依赖或故障排查内容时，不创建空章节。
- 平台、scope、版本和配置 schema 以 manifest 为真值；调用策略以平台元数据和 `SKILL.md` frontmatter 为真值。README 只做一致的用户语言摘要。
- 名称、命令、Skill 标识和配置键保留原始英文；说明文字使用简体中文。

## 插件 README

插件 README 必须帮助用户回答：为什么安装、会得到什么、怎样开始、会产生什么影响。

必需内容：

1. 标题和一句话价值说明。
2. “什么时候使用”，并说明主要不适用场景。
3. “包含的 Skills”或等价能力表，列出每项能力的用途和调用方式。
4. “快速开始”，包含 `aw install` 命令和至少两个真实用户请求示例。
5. “平台与安装范围”，说明 Codex/Claude Code 与 user/project 支持范围。
6. “权限和边界”，说明写文件、Git、网络、子代理、外部命令等用户可观察影响。

配置、人工依赖、隐私和常见问题只在适用时增加。

```md
# <显示名称>

<一句话说明安装后能获得什么。>

## 什么时候使用

- <用户场景>

不适用于：

- <主要边界>

## 包含的 Skills

| Skill | 用途 | 调用方式 |
| --- | --- | --- |
| `<skill>` | <用户任务> | 自动或 `$<skill>` |

## 快速开始

```bash
aw install <plugin> -p <platform> -s user
```

示例请求：

- “<真实请求一>”
- “<真实请求二>”

## 平台与安装范围

| 平台 | User scope | Project scope |
| --- | --- | --- |
| Codex | 支持 | 支持 |

## 权限和边界

- <用户可观察影响>
- <明确不会执行的操作>
```

## Skill README

Skill README 必须帮助用户回答：什么时候用、怎样调用、会发生什么、会得到什么、有哪些限制。

必需内容：

1. 标题和一句话任务说明。
2. “什么时候使用”，包含主要正向场景和高价值不适用场景。
3. “怎样调用”，明确自动调用、仅显式调用或客户端差异，并给出实际请求示例。
4. “会发生什么”，只说明用户可观察的主要动作和结果。
5. “权限和边界”，说明副作用、确认点和不会执行的操作。

平台或配置限制只在适用时增加。

```md
# <skill-name>

<一句话说明这个 Skill 完成什么任务。>

## 什么时候使用

- <典型场景>

不要用于：

- <相邻但不适用的场景>

## 怎样调用

<说明自动或显式调用策略。>

```text
$<skill-name> <任务说明>
```

示例请求：

- “<真实请求>”

## 会发生什么

1. <用户可观察动作>
2. <确认点或最终结果>

## 权限和边界

- <副作用或只读保证>
- <明确不会执行的操作>
```

## 维护检查

- 新增、删除或重命名 Skill 时同步插件 README。
- 改变平台、scope、调用策略、权限或配置时同步对应 README。
- README 进入 production bundle；已有插件修改 README 时提高插件稳定版本。
- 作者验证继续检查 README 存在且非空。内容质量由本规范和评审负责，不用固定 heading 或 prose 测试代替人工判断。
- 正式报告以 `reports/**/summary.json` 为事实源。`review:publish` 发布报告并封存批次，不修改 README。
