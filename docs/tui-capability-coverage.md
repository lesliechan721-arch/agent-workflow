# CLI 与 TUI 能力覆盖

本表约束普通插件消费流程。TUI 复用 CLI 的规划、配置提交、来源验证和写入服务；页面不循环启动 CLI 子进程，也不承诺跨来源事务或回滚。详细安全边界见[架构说明](architecture.md)。

## 普通插件消费

| 用户任务 | CLI | TUI 入口和恢复路径 |
| --- | --- | --- |
| 添加插件 | `install` | 添加插件 → 插件预览 → 使用位置 → 确认 → 结果；完成后返回插件详情与原列表。 |
| 同步、重新安装、移除和普通清理 | `sync`、`reinstall`、`uninstall`、`cleanup` | 我的插件 → 插件与平台详情 → 确认；来源不可用时保留普通离线清理。 |
| 多插件日常管理 | 多个 selector | 我的插件 → 批量操作；添加插件列表也可多选添加。每批选择一种动作、共同使用位置和平台集合。 |
| 恢复当前项目全部已保存插件 | `sync --all --scope project` | 我的插件 → 同步当前项目全部插件。确认时冻结使用设置中的根插件；不从当前安装清单扩张。 |
| 处理批量部分失败 | 重新选择失败 selector | 结果 → 重试失败项 → 新确认。保留前序已完成或已尝试目标的事实；依赖失败映射回受影响根插件。 |
| 查看与修改设置 | `config`、`config set`、`--preset` | 插件设置 → 设置层 → 分组与字段；支持标量、对象属性和预设。 |
| 删除本层字段与重置整层 | `config unset`、`config reset` | 字段动作 → 恢复继承；设置汇总或不可用设置页 → 整层重置。重置沿用四种实际处置结果。 |
| 保存与应用设置 | `config … --apply` | 保存汇总明确选择只保存或保存并应用；设置已保存而应用失败时进入新的重新应用确认。 |
| 找回来源缺失或下架插件的设置 | qualified plugin 的 `config reset` | 我的插件 → 已保存设置。只读取存储身份和位置；损坏条目不隐藏其他插件，重置不依赖字段定义。 |
| 在设置页修复来源 | `catalog source sync` | 设置暂时不可编辑 → 修复插件来源 → 结果 → 原设置位置；重新读取定义并校验草稿，不自动提交。 |
| 管理来源配置 | `catalog source list/status/add/update/set-primary/remove` | 插件来源 → 详情或完整草稿 → 一次确认；分别选择只保存或保存并启用。移除引用有独立处理计划。 |
| 检查与恢复来源 | `catalog source sync --check`、`sync`、`--replace-damaged` | 来源详情分别提供轻量检查、完整验证、精确修复和替换损坏版本；来源列表可检查全部来源，检查不自动启用更新。 |
| 安装通用 Skills | `skill install` | 插件预览 → 通用 Skills → 选择内容、Agent 和位置 → 确认与结果。 |
| 检查状态与失败原因 | `status`、诊断输出 | 需要处理 → 问题；操作记录 → 完整详情 → 报告预览与保存。历史在本次控制台进程内保留最近 20 条，跨会话重载保留，不持久化。 |
| 调整安装前脚本超时 | `--script-timeout` | 会执行脚本的单插件、批量和配置应用确认页 → 高级选项。编辑后重新生成票据，执行使用确认值。 |
| 有限所有权修复 | `cleanup --force` | 单目标受限清理检查 → 新确认。必须有唯一、精确、非空的专属内容证据；没有批量强制清理或绕过依赖保护入口。 |

## 会话导航

`h` 返回唯一首页并保留当前快照；`H` 在保护草稿和等待执行安全结束后重建会话。它们不安装插件、不清理磁盘，也不自动启用目录更新。执行中的导航待办可以撤销；失败、部分成功和结果未确认时保留结果页。字段输入和搜索优先接收普通字符。

已完成流程的选择、输入、准备、确认和进度页面不保留在可返回历史中。取消编辑和显式重试是不同动作；重试重新读取状态并生成确认。菜单、帮助和快捷键应调用同一个语义动作。

## 明确保留的 CLI 范围

| 范围 | 当前决定与理由 |
| --- | --- |
| JSON、stdin 精确值、debug、日志路径、非交互授权与自动化参数 | 保留 CLI。这些是脚本和机器接口；TUI 提供相同用户任务的交互入口及安全诊断报告，不模拟机器输出模式。 |
| 任意目录的 Skill materialize、validate 和 Eval | 保留 CLI 作者工具，不属于将插件安装到 Agent 的消费流程。 |
| 插件 init、add-skill、validate、test、build、requirements | 正常插件作者工作流，当前没有 TUI 作者工作区。按上下文出现的高级作者入口延期，不把它们称为专业排障。 |
| Catalog Workspace、开发源启停、构建和发布 | 正常目录作者工作流，当前使用 CLI；高级工作区延期。发布、不可变版本与恢复 journal 的既有合同不受本轮影响。 |
| Catalog store 检查与 prune、自描述和底层维护 | 保留 CLI。普通来源恢复和插件清理在 TUI 内可达；存储维护不混入日常安装动作。 |
| 全部个人使用设置的单步 `sync --all --scope user` | 当前没有独立一键入口。TUI 可选择多个插件并使用个人位置同步；项目 clone 恢复的一键流程优先。 |

## 变更检查

新增或改变 CLI 消费能力时，必须更新本表，说明 TUI 入口、失败恢复路径，或有理由的 CLI 范围。新增 TUI 路由必须接入生产路由定义、渲染、实体失效处理和按键合同；不保留开发占位页。

测试通过真实 Controller、运行时和 Ink 入口验证行为，不读取本文件或源码字符串来锁定文案。默认界面与技术详情分别验证；在 80×24 和 60×18 下，确认内容、逐目标结果和诊断末项必须可达。
