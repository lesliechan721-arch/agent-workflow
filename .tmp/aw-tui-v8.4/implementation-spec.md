# AW TUI v8.4 实施规格

状态：修改决策已由用户确认；本文是本次实施的当前规范入口。本文交付不表示代码、终端验证或发布已完成。

确认日期：2026-09-24。设计版本：AW TUI v8.4。

## 1. 交付范围与审阅导航

本次将 TUI 调整为 v8.4 设计中的信息结构和交互形式，并增加一维数组配置能力。用户已确认完整范围、分阶段实施、配置存储统一切换 v5，以及数组资源上限。

优先保证信息清楚、操作一致、完整内容可读、现有安全边界和恢复入口可用。页面收敛不得删除真实的范围、版本、依赖或脚本授权决定。

| 主题 | 当前规范 | 主要结果 |
| --- | --- | --- |
| 阅读、按键与视觉 | 第 2 节 | 保留单焦点；长文本继续左右翻页、`y` 复制；颜色和快捷键有明确层级 |
| 首页与项目 | 第 3 节 | 三个领域入口；完整项目根列表；局部重新检查 |
| 插件筛选 | 第 4 节 | 隐藏无结果候选；按实际 project/user 安装位置筛选 |
| 配置卡片与保存 | 第 5 节 | 值、来源和草稿状态分离；直接编辑；一份保存汇总 |
| 一维数组 | 第 6 节 | 核心、CLI、编辑器和消费者使用同一完整值合同 |
| v5 存储切换 | 第 7 节 | 所有新配置文件统一 v5；不读取或迁移旧 v4 |
| 通用 Skills | 第 8 节 | 正常项两行，短描述优先，重要例外可见 |
| 模板与路由 | 第 9 节 | 六类页面模板和一个通用弹窗组件；保留业务阶段 |
| 分期与验收 | 第 10、11 节 | 明确交付依赖、生产验证和实施自由 |
| 来源与决定 | 第 12、13 节 | 设计入口、源码核验范围、确认依据和旧提案差异 |

### 1.1 相对原设计的明确变更

1. **阅读交互保留现状。** 长文本、诊断、报告、完整值、完整影响等已有阅读页面继续使用 `←/→` 翻页和 `y` 复制全文。统一 Reader 时不得丢失这些操作。具体按键边界见第 2 节。
2. **配置存储统一切换 v5。** 不采用原数组提案中的“兼容读取 v4、首次写数组才升级、无数组文件保持 v4”。也不提供降级导出工具。完整切换和恢复合同见第 7 节。
3. **数组上限成为正式约束。** 原提案中的 128 项和 256 KiB 不再是建议；对象元素继续最多 32 个属性。精确定义见第 6 节。

本轮只生成规格文档。后续实施不包含远端发布、本地真实插件安装或修改用户实际配置；这些动作不因本规格存在而自动获得执行授权。

### 1.2 原型的采用范围

采用 [prototype.html](prototype.html) 和 [index.html](index.html) 中 v8.4 的页面信息层级、卡片关系、状态表达、单焦点、底部动作和响应式关系。场景目录见 [page-catalog.json](page-catalog.json)，共 74 个设计状态。

适用尺寸为 80×24 和 60×18，包含无色参照。字体度量、边框字符和局部留白可以适配真实终端；不得以适配为由隐藏风险、截断唯一完整值入口或改变操作顺序。无需追求浏览器像素与终端像素一致。

原型右侧的场景切换以及“成功／部分失败”按钮是设计工具，不进入产品。原型的数组插件、外部动作、保存结果和项目数据是演示数据；浏览器内存操作不构成真实安装、写入或兼容证据。

## 2. 统一交互、长文本阅读与视觉

### 2.1 单焦点与按键合同

每页只有一个纵向焦点序列。业务动作放在内容下方，与内容属于同一序列；不增加 Tab 操作栏或独立工具栏焦点。首页不添加帮助、退出或返回菜单项。

| 上下文 | 按键与结果 |
| --- | --- |
| 普通列表和菜单 | `↑/↓` 移动，Enter 选择，Esc 按现有返回／取消语义处理 |
| 可搜索列表 | `/` 原位搜索；输入过程中方向键和字母由输入控件处理 |
| 可筛选列表 | `f` 原位轮转有效筛选，规则见第 4 节 |
| 插件来源／配置分组 | 保留现有左右原位切换，不改成进入独立选择页 |
| 多选与下一步 | `m` 多选；`c` 继续；选择本身不授权执行 |
| 配置 | `s` 到保存汇总；它不直接提交配置 |
| 检查与会话 | `r` 只读检查；`h` 返回首页并保留快照；`H` 按现有草稿保护重建会话 |
| 全局帮助与退出 | 保留 `?`、`q`、Ctrl-C 及现有草稿／退出守卫 |
| 长列表 | `a` 定位本页下方动作，再按回原项；短页不额外宣传该键 |
| 文本阅读 | 按第 2.2 节保留翻页和复制；页面菜单仍用上下移动 |

输入、输入法组合、粘贴、弹窗和执行状态必须先处理自己的按键，普通页面快捷键不得透传。弹窗使用自身合同，包括既有风险长文弹窗的分页和复制；不得同时触发底层页面。连按 Enter 不得穿透新弹窗或重复执行。

Enter、Esc、方向键的常规提示集中在页脚。搜索、筛选和主要动作旁使用统一 KeyCap，例如 `[/]`、`[f]`、`[c]`、`[s]`。不增加顶部教学横幅或快捷键菜单。

### 2.2 Reader 必须保留的行为

适用对象是文本阅读视图，包括诊断详情、报告预览、来源／插件技术详情、完整配置值、完整保存差异、操作汇总中的完整影响和结果长详情。列表、输入框和可展开依赖树不因复用模板而变成文本翻页器。

1. `←` 上一页，`→` 下一页；已有 PageUp/PageDown 同义操作保留。分页单位是按当前终端列宽换行后的显示行，不是原始字符串数，也不是横向移动文本。
2. `↑/↓` 保留页面菜单或列表焦点的现有语义。阅读翻页不得切换插件来源、配置分组或另一个目标；这些动作只在各自上下文处理。
3. `y` 复制**当前阅读文档的完整文本**，包括不在当前页的内容；不只复制屏幕可见部分，不包含终端软换行插入的断行。
4. 复制沿用当前安全值／诊断投影和剪贴板实现。不得为复制绕过脱敏，不把私有配置投影混入可导出的诊断。保留复制成功或失败反馈，失败后可重试。
5. 先做安全投影，再按列宽换行，再分页。长路径、中文、超长单行和文档尾部都必须可达，不以永久裁剪代替分页。
6. 终端缩放后重新计算换行和页容量，并保持可用的阅读位置和菜单焦点；不得丢失文档尾部。回到列表时恢复原列表上下文。
7. 页脚明确显示 `←→ 翻页`、`[y] 复制全文` 和返回提示；仅在该阅读视图确实支持分页时显示分页提示。
8. 关系图继续保留左右展开／折叠等已有树操作。进入关系节点的长文本详情后，才应用文本阅读合同。

验收重点是同一长文的首页、末页和完整复制结果一致，复制无软换行和秘密泄漏，按键不会同时触发菜单切换。

### 2.3 视觉角色与终端约束

复用现有调色板，在其上定义语义角色，不逐页硬编码不同颜色。

| 角色 | 表达与用途 |
| --- | --- |
| primaryValue | 明亮正文，必要时粗体；当前值、插件名、待决定版本 |
| label | 正常正文；标题、位置和动作 |
| secondary | 可读的次要文字；简介、来源、检查时间 |
| focus | 强调边框、窄底色和指示符；仅表示当前焦点 |
| change | 蓝色及 `↑/●`；更新、未保存变化 |
| success | 绿色及 `✓`；已经验证的正常或完成 |
| warning | 黄色及 `!`；待同步、检查失败、风险 |
| error | 红色及 `!`；受阻或失败，并提供下一步 |
| unknown | 次要色及 `?`；无法确认 |
| keycap | 高对比的短按键标记，与对应功能相邻 |

颜色只作冗余编码。NO_COLOR 和有限色终端仍须通过符号、文本、粗体、反色或 ASCII 边框辨认状态。焦点不通过调暗所有非焦点值表达；用户应能同时比较多个配置值。不依赖鼠标悬停、动画或闪烁。

在 80×24、60×18、中文长名和缩放状态下验证真实终端布局。小于现有最低尺寸时保留空间不足提示及恢复状态，不以挤掉风险或操作入口解决。

## 3. 首页与完整项目工作区

### 3.1 首页只显示领域入口及其状态

首页只保留“插件”“项目插件”“插件来源”三个入口。状态直接放在对应卡片中；删除卡片外的重复总计、说明和“没有待办”等无效句子。

| 入口 | 状态与计数 |
| --- | --- |
| 插件 | 按 canonical pluginId 去重；更新、需处理等事实分别显示，多平台不重复计数 |
| 项目插件 | 按根插件去重；受阻、待同步、未确认分别表达 |
| 插件来源 | 按 sourceId 计数；更新与检查失败等事实可以同时存在 |

不能用单一 update-first 分支掩盖失败或风险。同一根因可在不同领域标记影响，但不得把三卡数字相加当作全局问题数。

正常状态使用“全部就绪”或“当前可用”；读取中显示“检查中”；未知不得显示健康。没有项目声明显示“未配置项目插件”。没有项目根时入口仍存在，显示“当前不是项目”，进入后只读解释，不提供同步按钮。

原 `issueList/issueDetail` 和安全诊断能力保留，通过对应领域及现有诊断入口访问。首页不另增重复的全局问题卡。

### 3.2 ProjectInventory 数据范围

项目页使用完整只读投影，不能只从 `projectIntentReminder` 的 actionable、blocked、unconfirmed 提醒集合生成。数据来自当前项目声明、实际安装和已有来源／版本证据，不建立新持久安装台账。

- 默认“项目声明”显示全部声明根，包括已就绪项。
- “额外安装”只显示当前项目实际安装、但未包含在共享声明中的根。
- 展示被本项目使用的合法 user 共用目标；不把全局库所有 user 安装纳入本项目。
- 依赖按根关系归组，默认不重复生成根卡。
- 声明引用的插件在 Catalog 中消失，或来源失效时，保留该声明对象及问题。不能因解析失败让问题从列表消失。
- 通用 Skills 由外部工具安装，不自动加入 AW 项目同步；显示其记录归属。
- 不扫描全磁盘、历史项目或增加全局项目注册表。

每卡代表一个根插件，合并多个平台。显示名称、两行以内的工具／位置状态，以及需要时的一步动作或短原因。正常项不重复长说明；共用个人安装明确显示“共用”，不能为了满足项目展示而重复安装。明细显示期望版本、实际版本或未知状态，以及来源。

### 3.3 项目导航、检查与同步

标题只显示一次项目名。搜索和必要的筛选原位进行。首次按“受阻 → 待同步 → 未确认 → 就绪”排序；异步更新不得夺走当前焦点。

`↑/↓` 按根插件移动并自然滚动，不再将每个安装目标作为一张左右翻页的项目列表页。长细节进入 Reader，仍遵守第 2.2 节。Enter 进入统一 `pluginDetail`，origin 只影响返回位置，不生成第二套插件详情。

底部提供“同步待就绪插件（N）”和“重新检查项目”：

- N 对应已确认可执行集合；受阻与未知目标不得混入执行集合。
- 同步按 project 声明和 exact target 规划，依赖去重，不清空个人默认设置，不重复安装合法共用目标。
- 来源、版本、脚本及真实影响需要确认时，进入现有准备与 Review 合同。启动提醒、勾选和继续均不授权写入。
- 重新检查为局部只读 refetch，保留查询、焦点和有效筛选；不调用 `H` 全会话重载，不运行脚本、激活或清理。
- 结果按根再按位置展开；受阻项明确未处理，部分失败不隐藏已完成事实。
- 启动提醒可选择稍后，首页状态继续可见；`H` 不重复同一提醒签名，编辑中不抢焦点。

验收必须同时包含健康声明、异常声明、个人共用、额外安装和不可解析来源，证明列表完整且同步集合精确。

## 4. 插件列表与动态筛选

保留一个筛选轴。候选名称为：全部、已安装、未安装、可更新、需处理、当前项目、所有项目；不增加第二组范围快捷键或工具栏。

| 筛选 | 精确定义 |
| --- | --- |
| 当前项目 | 存在确定的 project 范围安装目标 |
| 所有项目 | 存在确定的 user 范围安装目标，表示个人层安装位置 |

这两个选项不表示“当前能够使用的全部内容”或“全部来源”，也不扫描所有项目。一个插件可以同时匹配两者，但每个筛选内部按 pluginId 去重。仅有声明、尚未同步的目标不算已安装；其问题在项目页和需处理筛选中可见。未知状态不能当成未安装或零项。

计数和显示规则：

1. 从同一 `source + query + snapshot` 计算各候选数量，计算时忽略当前已选筛选。
2. 显示“全部”和数量大于零的候选，`f` 只轮转这些候选。
3. 当前已选筛选因搜索或异步更新变为零时，保留该标签及“本条件无匹配”的状态。用户可用 `f` 或 `/` 修改条件；不得自动切到全部或扩大范围。
4. 用户离开该零项筛选后，它从候选中消失。
5. 查询、计数、渲染和按键处理使用同一集合投影；迟到结果不能覆盖较新的查询结果。允许合并快速输入更新，不改变上述语义。
6. 批量选择集合独立于查询和筛选。隐藏的已选项继续计数，新数据到来不自动勾选新对象。

验收包含 selected-zero、同插件两种安装位置、未知状态、来源切换及隐藏已选项，不能只验证筛选标签是否存在。

## 5. 配置卡片、编辑与保存

### 5.1 ConfigTile 的显示合同

标题嵌入边框，实际值是主内容，来源使用独立小标签，待保存和无效状态另行表达。不能把“值／来源／待保存”重新拼成同权重的一段文字。

- 默认值和已保存值均使用可读正文。焦点由边框和底色表达，不能与成功或错误共用含义。
- 待保存值标明目标，例如“● 待保存到个人”。实际生效值和候选草稿有明确区别。
- 项目值覆盖个人草稿时，主值保留当前有效值，并提示“个人修改不会影响本项目”。
- 无效值显示“需修正”，先执行安全和合法性投影，不能用 summary 把错误美化成正常值。
- 字段用途只在焦点处显示一次。长说明可通过已有完整阅读入口查看，不为每个字段增加 About 页面。
- 卡内值最多两行；可以在两行内完整显示时不截断。超长值提供可达的完整值入口或编辑器，不把被裁掉的 JSON 称为完整值。
- 60×18 下字段卡目标为可见 2–3 张；保存动作仍在同一序列，`s` 可直接到汇总。
- 来源 metadata 不因 UI 简化而改变含义。可以调整作者短说明，但不得由文案推断新的保存权限。

继续使用已有安全对象摘要和 Definition v3 的 join summary。本次真实 Codex Enhance 的七个 profile 仍仅支持 user scope，其默认值保持：

| 字段 | 默认值 |
| --- | --- |
| quickProfile | gpt-6-luna / medium |
| standardProfile | gpt-6-luna / high |
| deepProfile | gpt-6-luna / xhigh |
| simpleTaskProfile | gpt-6-luna / max |
| generalTaskProfile | gpt-6-sol / medium |
| complexTaskProfile | gpt-6-sol / xhigh |
| advancedTaskProfile | gpt-6-astra / medium |

数组场景使用独立演示／测试插件，不为了展示数组修改这些 profile 或授予 project 写权限。

### 5.2 编辑和保存路径

左右原位切换分组。Enter 对普通可修改字段直接进入编辑器：标量进入值编辑器，对象进入属性表单，数组进入集合编辑器。普通值不多经过 `configFieldAction`；遗留只可删除的受限值仍保留安全动作。unset/reset 是明确的低频动作。

确认完整值后选择合法保存目标，回总览形成待保存草稿，再由 `s` 到一份操作汇总。仅一个合法目标时显示该事实并跳过空选择。编辑和选择目标都不写盘。

敏感值继续只允许个人层的既有顶层字符串能力。本次不扩展敏感对象、数组或秘密子项。范围限制必须由核心 writer 执行，不能只靠 TUI 隐藏选项。

保存汇总按 scope 归组，直接显示字段及差异。简要差异和完整差异是同一份操作文档的展示方式，不再形成“汇总 → 完整变化 → 再次重复 Review”的必经链。阅读完整差异不增加一次写授权，也不能跳过真正的 Review。

沿用现有多组提交和应用合同：单配置文件原子提交；多个 scope 不组成跨层事务；保存与 apply 分开报告。已提交组不恢复为旧草稿、不重放；失败组保留处理入口。未知应用范围不能显示为没有目标。显式重试重新准备和确认。

验收覆盖有效值、无效值、个人草稿被项目覆盖、合法目标唯一、敏感字段、部分保存成功及 apply 失败。

## 6. 一维数组完整合同

### 6.1 支持的结构与语法

在既有 Config Definition v3 中增加顶层 `type: "array"` 和一个固定 `items` schema。根 Plugin Manifest 与 Config Definition 的 schemaVersion 仍为 3；存储文件版本另见第 7 节。

允许 `string[]`、`number[]`、`boolean[]`、fixed-object[] 和 KV-object[]。对象元素的属性只能是标量；固定属性可分别具有自己的标量类型，但整列始终使用同一 items schema。

不支持数组套数组、对象内数组、嵌套对象、tuple、anyOf、null 或混合标量元素。不能因为 TypeScript value union 较宽就放过核心同质校验。

`items` 可使用现有本地 `$ref`。展开引用后重新检查所在上下文，禁止通过引用绕过嵌套、敏感或资源限制。保留现有循环检测、引用预算和 schema 展开合同，不运行第三方代码来解释定义。

`items` 自身不允许 `default`、`required`、`sensitive`；对象元素的固定属性仍可声明 `required`，其它属性约束沿用现有浅层对象合同。数组字段自身及全部子项均不得声明敏感值。

示例结构：

```json
{
  "schemaVersion": 3,
  "fields": {
    "reviewLabels": {
      "type": "array",
      "items": { "type": "string", "validation": { "minLength": 1 } },
      "default": ["security", "tests"],
      "validation": { "minItems": 0, "maxItems": 8, "uniqueItems": true }
    }
  }
}
```

[完整数组示例](examples/array-config.proposal.json) 用于理解五种元素类型和 itemSummary。其“proposal”文件名保留来源性质，实施时必须通过生产 Core 验证，不能把参考模型的通过当作生产支持。

### 6.2 数量、字节、相等性与诊断

| 项目 | 规范 |
| --- | --- |
| minItems/maxItems | 可选非负整数；声明 max 时不得超过 128，未声明时有效 max 为 128；min 不得超过有效 max |
| 字段字节上限 | 每个数组完整值的 JSON UTF-8 编码最多 256 KiB，即 262144 字节；按核心规范化后的紧凑值编码计算，不包含外层 envelope 和格式化空白 |
| 对象元素 | 最多 32 个属性；继续遵守既有键、字符串、RE2、format、choices 和 required 约束 |
| uniqueItems | 可选 boolean，默认 false；true 时按规范化完整值判断重复并报错，不静默删除重复项 |
| 相等性 | 对象 key 顺序不影响相等；数组元素顺序影响相等；重复项默认保留 |
| 数字 | 必须有限；数字文本先拒绝空白再解析，不把空白当 0，不隐式将字符串强制转换成数字或布尔 |
| 输入对象 | 只接受安全 JSON record；沿用危险 key、prototype pollution 和非数据对象检查，属性查询使用 own-property 语义 |

这些约束同时应用于 schema/default/preset 校验和所有实际写入入口。不能只禁用 TUI 添加按钮，却允许 CLI 或导入写入超限值。字节上限只增加到数组值，不借本次变更重新收紧无关标量和对象合同。

数组诊断必须能定位字段、0-based 元素索引及其属性。保留旧 `path.field/property` 的已有含义，数组路径增加 `path.segments: (string | number)[]` 表达完整路径，例如 `["modelPipeline", 2, "model"]`；不把索引编码进 fieldKey。界面转换为“第 3 项／模型”。删除或移动后按新列表重算错误路径，不能沿用旧索引。

### 6.3 值、默认值、预设与覆盖

- `[]` 是显式空数组，可覆盖非空默认；字段未设置、unset 和 `[]` 不等价。
- `required: true` 只要求字段存在合法值；需要非空时使用 minItems。
- default 和数组级 choices/presets 都是完整合法数组，不给元素注入默认值，不自动补齐 minItems。
- 数组级 `allowCustom=false` 时只能选择既定整列预设，不提供自定义增删改排。
- item 级 choices 只约束元素值。对象元素预设作用整个对象，不能通过子属性编辑绕过整对象校验。
- user/project 层按整个顶层字段覆盖；不 concat、不按索引补丁拼接、不按业务 ID 合并，也没有跨层元素继承。
- 将元素移回原顺序，且完整值与原值深等序相等时，不保留虚假的 dirty。

### 6.4 数组预览和摘要

标量数组使用实际值 chip；对象数组显示前两项实际摘要及剩余数量／总数。空数组显示“空列表”。不能只显示“自定义 N 项”而隐藏全部值信息。

对象数组通过新增 `presentation.fieldViews.<field>.itemSummary` 引用既有 join summary，并对每个对象元素独立应用。未定义时使用现有安全对象预览。既有 `summary` 仍只作用 fixed object，不改变 join 语法或引入数组索引、任意路径表达式。编译器验证 summary 的目标类型和属性路径。

预览不完整时必须有可达的完整集合／完整值入口。错误值先显示错误状态，不能用摘要掩盖错误。完整文本阅读继续遵守第 2.2 节。

### 6.5 集合编辑器与草稿生命周期

编辑器持有字段级 working value 和仅会话有效的 rowId，列表显示序号及实际摘要。rowId 只用于稳定焦点，不进入存储、Review 目标、导出、权限依据或永久字段路径。

| 动作 | 行为 |
| --- | --- |
| Enter 编辑元素 | 标量复用值编辑器；对象复用属性表单 |
| 添加 | 使用同一元素编辑器；新增元素合法确认后才加入 working value |
| 列表操作 | 用同一个弹窗执行上移、下移、删除，显示当前项和位置；不增加快捷模式 |
| 取消当前元素 | 丢弃该元素的本次未确认编辑，保留其它元素及外层 working value |
| 取消整个列表 | 保留进入前的总览草稿，不把未确认 working value 写回 |
| 删除至不足 minItems | 可暂存于 working value，显示原因；“使用此列表”不能通过 |
| 使用此列表 | 校验完整数组，通过后只选择一次合法 scope，再回总览形成草稿 |

增删改排本身不写磁盘。草稿 owner 必须区分顶层字段、数组、rowId 和对象属性，避免 Esc 丢失其它项。未完成的新元素不能作为无效半成品进入顶层草稿。

编辑期间沿用字段、层、来源和 schema 的现有证据检查。外部值或 schema 变化时停止旧提交，重新检查完整顶层值和授权；不自动重放旧 index patch，不为本功能增加持久编辑日志或锁层级。

### 6.6 数组差异、CLI 与消费者

Review 需要表达新增、删除、移动和修改及代表值，不能仅报增删数量而遗漏顺序变化。无业务 ID 的重复元素不能被任意匹配成修改。实施者可选稳定等值匹配加 LCS，或在无法可靠匹配时显示清楚的前后完整列表；不得伪造无法证明的变更分类。rowId 不参与持久差异身份。

CLI 继续以整个字段 set/unset 表达数组。通过现有完整 JSON、stdin 等已存在的安全输入机制提交；不把 shell 裸逗号字符串解释为数组，也不新增逐 index 命令。`false`、`0`、`""` 在各自同质数组内保留类型和含义。

支持必须贯通 Core types、normalizer、作者 JSON Schema、生成类型、capability derive、Catalog 快照及读取端、配置读写、运行时 config helper、redaction、稳定序列化、schema evidence、保存批次、Review、dry-run、结果和报告。只扩展 React 或 TypeScript union 不构成交付。

新增数组 capability 必须在正式 registry 注册；具体 ID 由实施者遵守现有命名规则确定。源定义、能力派生、运行时支持集合和消费者检查一致，不能将包内 proposal 名称冒充已登记能力。缺少能力的消费者应在执行前拒绝，不污染 Active。

## 7. 配置存储统一切换 v5

### 7.1 切换策略与影响

这是用户选择的 beta 硬切换。数组核心阶段交付后，新 AW 只接受 v5 插件配置 envelope；所有新写入均为 v5，包括只有标量、对象或空 values 的文件。

不做 v4 兼容读取、自动迁移、按文件懒升级、自动降级或降级导出工具。删除数组值也不会改变 v5 格式。

| 文件状态 | 新 AW 行为 |
| --- | --- |
| 文件不存在 | 沿用缺失配置及默认值合同；后续写入使用 v5 |
| 合法 v5 | 核验路径、source/plugin identity、scope binding 和值后读取 |
| v4 或其它不支持版本 | 报告稳定的 `schemaVersionUnsupported`，保留原始文件；不把值当缺失配置静默套用默认值继续受影响写操作 |
| 损坏 JSON／非法结构／身份不匹配 | 沿用对应诊断与安全恢复边界，不自动重置 |

旧文件不因打开 TUI、status、检查、普通保存或应用而被自动删除或覆盖。用户需要通过已有、与 schema 无关的显式 reset 流程确认移除目标旧配置，再重新配置；该流程保留范围、身份、路径及原有安全确认边界。无法证明安全时保留文件并给出可执行的修复路径。

这意味着升级后旧 v4 文件中的个人选择和项目设置不会被新版使用，需要重新输入。共享项目配置使用 v5 后，旧 AW 将拒绝该文件；不承诺已发布旧程序的提示文案能被本次更新改变。回退程序版本不会自动转换数据。

### 7.2 文件结构与版本边界

v5 延续 v4 的命名空间、文件路径和 binding 字段，只改变接受的存储版本和 values 的受限值集合：

```ts
// 存储结构说明；正式类型及结构验证由生产 Core/CLI 定义。
interface PluginConfigEnvelopeV5 {
  schemaVersion: 5;
  sourceId: string;
  pluginName: string;
  binding:
    | { kind: 'source'; sourceIdentity: string }
    | { kind: 'catalog'; logicalIdentity: string };
  values: Record<string, PluginConfigValue>; // 增加第 6 节的一维数组
}
```

user 继续绑定 source identity，project 继续绑定 Catalog logical identity。字段和目录安全检查不降低。写入继续使用现有单一 `AW_HOME` mutation lock 和单文件原子提交，不新增迁移状态机、ledger 或补偿事务。

“v5”只针对插件配置存储 envelope。本次不据此将 Manifest、Definition、Catalog snapshot、Intent、Status、Receipt 或其它公开输出统一改为 5。数组导致公开值集合／诊断扩展时，应同步对应 schema 和消费者文档；独立 envelope 的版本规则仍按其现有合同处理。

### 7.3 消费者与交付门禁

数组 Core、配置存储读写、CLI 和所需消费者一起就绪后，才接入数组 TUI 编辑器。先交付支持新能力的 AW，再让实际发布插件依赖数组 capability；本规格不执行发布。

共享 project store 的版本或能力不兼容必须在受影响平台写入前发现。一个来源或目标失败，继续按现有独立失败合同处理，不建立跨来源强一致或全局回滚。

旧 v4 的拒绝、原始字节保留、显式 reset 后 v5 重建、无数组 v5、数组 v5、身份错误及原子写入都必须通过真实读写路径验证。原提案“无数组仍写 v4”的测试期望必须替换，不能同时保留两种政策。

## 8. 通用 Skills 紧凑选择

正常项固定两行：第一行名称和勾选符，第二行短描述。候选模型贯通已验证的 frontmatter `metadata.short-description`，优先于长 description。

缺少短描述时，从已有可信 description 提取一句有界摘要，内部保留 fallback 来源；不联网生成，不将长 description 完整换行后称为短描述。显示宽度受终端约束，正常项不能因文本较长无限增高。

删除默认列表中的“插件名·当前插件”、direct/transitive provider 行、每行重复范围和 dynamic 标签。依赖提供者及动态生成详情进入 Review／关系视图。同名不同提供者必须保留必要来源消歧，不能为压缩隐藏身份冲突。

不可选、范围受限、需要重新确认等重要例外追加一行短原因，并提供焦点说明。全页范围差异总述只显示一次，最终范围 Review 展开实际影响。

Enter 和 Space 都切换勾选，不进入单 Skill 详情。初始选择继续使用当前 Controller 草稿；不把原型零选择状态当作改为默认零预选的要求。`c` 继续，选择工具放在底部。保持当前准备反馈及 scope 选择后重新物化、校验候选的安全合同。

验收覆盖有／无短描述、中文长文、ANSI 清理、同名来源、范围差异、不可选项和初始草稿选择。

## 9. 六类模板、操作文档与历史路由

| 模板 | 责任 |
| --- | --- |
| HomeNav | 三个领域卡和对应状态 |
| Collection | 插件、项目、来源、Skills、数组项等集合；共享选择、查询、焦点和底部菜单能力，按上下文启用 |
| Detail | 插件、来源、关系节点摘要及一级动作 |
| Editor | schema 驱动的值、对象和数组编辑；统一草稿、校验、取消和 scope |
| Operation | 准备／Review、执行、结果；保留精确目标、授权证据和部分事实 |
| Reader | 安全文本、完整值、诊断、报告和关系阅读；文本按第 2.2 节操作，交互树保留自身操作 |

Dialog 是一个通用瞬时组件，用于选项、危险确认和选择工具，不是第七类业务页面。复用模板不要求所有列表支持所有快捷键，也不把表单交给普通列表按键处理。

目标是共用表现和交互合同，**不是只留下六个路由**。能力、权限、准备和执行继续由原 Controller/service 负责；不另写执行器。

以 [route-mapping.json](route-mapping.json) 中 55 条映射作为迁移核对清单。Alias 是路由适配角色，不是业务模板；其中 `runtimeRemovalVerified: false` 不表示路由已经删除。关键要求如下：

| 现有页面／路由 | 调整要求 |
| --- | --- |
| pluginPreview / pluginDetail | 归一对象详情；旧入口可通过 alias 跳转 |
| projectStatus | 使用完整项目投影和 Collection，不能只显示提醒 |
| configFields / configObjectPropertyEditor / array editor | 使用统一配置卡片、Editor 和明确子草稿 owner |
| configFieldAction | 普通可修改值直接编辑；只可删除的受限状态保留动作 |
| configSave / sourceSave / review / changes | 同一操作文档；完整内容是 Reader 展示，不重复授权 |
| pluginContent | 集合和阅读变体，不维持每项独立分页标准 |
| portableDependencies / pluginDependencies | 共享关系呈现；保留证据类型、方向、本次上下文和权限差异 |
| sourceTechnical / pluginTechnical / operationDiagnostic / report | 共用 Reader；保留安全数据分类及复制边界 |
| platform / More | 仅保留平台专属或低频维护；普通卸载／恢复主路径不被迫中转 |

迁移必须保留 flow origin、return target、草稿、焦点、查询、筛选、滚动位置和实体失效处理，不能只删 route enum。依赖节点返回恢复对应根和方向的展开状态。已完成流程的选择、准备、确认、进度页不留在可返回历史；失败、部分成功和未知结果保持可读，重试总是新的准备和确认。

## 11. 验收与验证计划

### 11.1 高价值验收矩阵

测试遵循仓库 [测试指南](../../docs/testing.md) 的 Test Value Gate。每个风险由最低且足够真实的层负责；跨层测试只增加新的边界证据。不测试文档句子、私有函数布局或模板名称数量。

| 风险 | 必须观察到的结果 | 最低合适证据 |
| --- | --- | --- |
| 首页误报健康或重复统计 | 未知、受阻、更新独立；无卡外重复统计；多平台根去重 | 投影 unit + 真实 TUI 入口的展示／导航 |
| 项目健康项或共用项丢失 | 全部声明、额外安装和合法共用可见；不重复安装 | Controller/runtime；同步准备的真实目标集合 |
| 检查导致重载或写入 | 项目检查保留焦点／查询且只读 | runtime 行为和副作用断言 |
| 筛选悄悄扩大范围 | selected-zero 保留；未知不归未安装；隐藏已选不丢失 | 同一真实列表交互 |
| 配置主值、scope 或保存事实错误 | 生效值与草稿分离；唯一目标跳过空选择；已提交组不重放 | 安全值投影及真实 configSaveBatch |
| 非法数组绕过核心 | 五种合法元素类型通过；嵌套、混合、非法 ref、item default/sensitive、非有限数和超限被拒绝 | Core validator，边界值和结构化错误 |
| 空值及相等性失真 | 未设置、unset、[] 区分；对象 key 重排相等；数组换序不同；unique 默认保留重复 | Core unit |
| 草稿／索引错误 | 元素取消不丢外层；整列取消不污染总览；移动后诊断正确；rowId 不入持久产物 | 真实 Controller/Ink 编辑及保存结果 |
| 范围合并错误 | project/user 按整个数组覆盖，无 concat 或 index patch | 配置解析和真实 CLI 输入／输出 |
| 旧数据被隐式迁移或删除 | v4 稳定拒绝且原始字节不变；显式 reset 后重建 v5；无数组也写 v5 | 隔离文件系统和 CLI integration |
| 不兼容后部分平台已写入 | store/capability 检查先于受影响写入，Active 不被不支持候选污染 | 消费及写入边界 integration |
| Skills 高度或风险丢失 | 正常两行、异常原因可见、来源消歧保留、初始草稿不变 | 候选解析与真实选择交互 |
| 长文或复制丢失 | 末页可达；左右翻页不改菜单上下文；复制完整安全文档且无软换行 | Reader/Ink 按键及剪贴板边界 |
| 模板迁移破坏返回或授权 | origin、草稿、焦点恢复；完成 Esc 不回旧流程；连按不重复执行 | Controller/router 及真实 TUI 流程 |
| 布局和输入只在浏览器成立 | 两种尺寸、无色／16 色、中文长名、缩放、IME 和粘贴可用 | 真实终端／PTY 与必要的人工体验记录 |

128/129 项、262144 字节及超出边界、32/33 个对象属性应覆盖相应核心边界；不为每一层复制相同限额测试。公开能力和结构兼容需包含真实 package/bundle/Catalog 产物层证据，不能只依赖源类型检查。

重复对象的差异表达必须覆盖排序及无法可靠归类的前后列表场景；原型中的假成功／部分失败按钮不提供保存测试证据。

### 11.2 验证入口与限制

实施时先运行直接相关的定向测试，再按变更域完成 `pnpm test:unit`、`pnpm test:integration` 和 `pnpm build`。项目没有单独的 typecheck 命令，构建包含类型检查。

定向测试通过仓库 `scripts/test/run-vitest.mjs` wrapper，使用实际文件所属的 Vitest project；不直接调用 Vitest 或向全量 package test 脚本追加文件名。公开 schema／作者合同变化还需按测试指南补充相应产物和作者入口验证。更新 TUI 消费能力时同步 [能力覆盖表](../../docs/tui-capability-coverage.md)，公开 config/schema 变化同步架构及消费者文档。

普通测试使用 synthetic catalog、隔离 homes 和 fake native runner，不触碰真实用户配置。真实终端验证与真实外部平台安装证据分开记录；mock 不能声称证明外部平台行为。本任务无需运行模型 Eval。

本次文档交付仅核对来源、规则覆盖、局部链接、示例结构和空白错误；未运行生产单测、构建、PTY、浏览器操作、真实安装或发布。现有 `validation/` 结果属于原型／参考模型，不是本次生产验证结果。
